# 新增 DP 说明 —— DP166 ~ DP169

---

## 0. 一页速览

| DP | 名称 | 类型/读写 | 一句话 | APP 要做什么 |
|---|---|---|---|---|
| **166** | led_switch | bool rw | **双色 LED 灯效总开关**（**默认 false = 关**）| 与 DP117（屏）分开做两个开关 |
| **167** | power_off | bool rw | 关机 / 唤醒（**不重启**，WiFi 仍在线）| 关机命令后**不要等设备下线**才更新 UI |
| **168** | ota_result | enum ro | OTA 结果 | 升级页要能收 `2/3` 收尾，不要一直停在"升级中" |
| **169** | file_download | raw wr | **通用文件分片下载** | 分片下发 + 按 DP160 回执判结果（码表见 §5.4）|

**三件最容易踩的事**：
1. **DP166（LED）与 DP117（屏）是两个独立开关** —— 不要共用一个；
2. **DP169 的 SD 写满/写保护现在回码 `2`（文件错误）**，不再是 `1`（网络错误）；
3. **DP167 关机后设备仍在云上**，能立刻回显状态，也能立刻回 DP160 回执。

---

## 1. 通用约定（读这 4 个 DP 前需要知道的 4 点）

| 约定 | 说明 |
|---|---|
| 枚举类 DP 传**数字下标** | 平台显示字符串由云端映射，设备只认 0/1/2… |
| `scale=1` 的数值要 **÷10** | 平台标记了 scale 的 DP，收到的值是实际值 ×10（`600` = 60.0）|
| **raw 单帧 ≤ 255 字节** | 超过必须分片（**DP169** 的数据段 ≤252B/帧）|
| 三种上报机制 | ① 对象型全量上报（**166/167/168**）② raw 主动上报（历史类 DP）③ 被动回执走 **DP160**（**169**）|

> **判断设备是否支持这 6 个 DP**：读 **DP148 `firmware_version`**；或看全量上报里有没有
> **166 / 167 / 168**。**169 是 raw 型、不在全量上报里** —— 只能实际下发一次看有没有 DP160 回执。

---

## 2. DP166 —— 双色 LED 灯效总开关（bool，`rw`）

| 项 | 内容 |
|---|---|
| 取值 | `true` = 允许灯效；`false` = **灯全灭** |
| **默认值（2026-09-28 变更）** | **`false`（关）** —— 进 UI 后 LED 默认不亮；要灯效由 APP 下发 `true` 打开（并持久化）|
| 语义 | **总门**：`off` 时**无视一切灯效槽位**，直接全灭（告警灯/配网灯/呼吸灯一起灭）|
| 落地 | 设备侧 `app_light_ctrl_set_enable()`；同时落 KV，**重启保持** |
| 与 DP117 的分家 | **117 = 屏幕背光**（关了屏幕全黑）；**166 = 双色 LED**。两者是**两个独立开关**，APP 不要共用一个 |
| 恢复出厂 | 会被**复位为默认（亮）** |

## 3. DP167 —— 关机 / 唤醒（bool，`rw`）

| 项 | 内容 |
|---|---|
| `true` | 进入关机（软关机：屏幕灭 + 采集/历史/上报挂起 + 外设断电）|
| `false` | 唤醒，恢复到关机前界面 |
| **不重启** | 这是"软关机"，不是断电重启；RAM 保留 |
| **WiFi / MQTT 保持在线** | ⇒ 关机后设备**仍在云上**，状态可即时上报 |
| 确认页 | 远程关机**不弹本机确认页**（用户定稿）|

### 3.1 两条上报要分清

| 通道 | 内容 | 含义 |
|---|---|---|
| **DP160** | `power_off:trigger:ok` | **"命令已收到并开始执行"** —— 因为关机要停采集/停上报，状态跃变不一定及时，先给 APP 一个确定的受理回执 |
| **DP167** | `true` / `false` | **真实关机态**（全量上报时也**实时派生**，不读缓存）|

⇒ **APP 应该以 DP167 的回显为准**，DP160 只用来确认"命令收到了"。

### 3.2 关机期间
除 DP167 外，其它 DP **不再处理**（按键也被拦）。想恢复：发 DP167=`false`。

## 4. DP168 —— OTA 结果（enum，`ro`）

| 值 | 含义 | 什么时候发 |
|---|---|---|
| 0 | idle | 无升级 |
| 1 | downloading | **OTA 开始**（收到升级通知时）|
| 2 | **success** | **重启后、连云时**比对"目标版本 == 当前版本"成功 → 发 2 |
| 3 | failed | 升级失败；或重启后比对发现版本**没变** → 发 3 |

### 4.1 APP 必须注意
* **升级成功的确认只能等设备重启并连云之后** —— 中间那段"设备重启中"APP 不要判失败。
* 设备同时会走**涂鸦云标准 OTA 通道**上报升级结果（`tuya_svc_upgrade_result_report`），
  ⇒ APP 的"固件升级"页应能正常收尾，**不会一直停在"升级中"**。
* 失败后设备会**恢复资源再重启**，重启回来会补发 `3`。

## 5. DP169 —— 通用文件分片下载（raw，`wr`）

### 5.1 分片帧（raw，单帧 ≤255B）

```
ver(1B, =0x01) + seq(1B, 从 0 起) + total(1B, 总片数 ≤8) + 数据(≤252B)
```

* 同一 `seq` 重复到达 → **覆盖**（幂等）；`total` 变化 → 视为新任务、清空重来
* **30 秒收不齐** → 回执码 `3`（分片超时）
* 分片是**连发**的，一帧**没有**"分片进度回执"，只有最终一条结果

### 5.2 拼装后的 payload

```
task_id(1B) + path_len(1B) + path(≤128B) + url_len(2B 大端) + url(≤1800B)
           + expect_size(4B 大端) + expect_crc(4B 大端)
```

* `path` 相对 `/sdcard/`，如 `repo/assets/a.jpg`
* `expect_size` / `expect_crc` 传 **0 = 本次不校验**（校验项可选，但建议都传）
* `url` 是 HTTP(S) 直链，**长度 >1800 会被显式拒绝**（不会静默截断）

### 5.3 设备侧四重校验（缺一不可）

| 校验 | 规则 |
|---|---|
| 目录白名单 | 必须以 `dl_img/`、`repo/`、`user/` 开头（**不含 `config/`**）|
| 后缀白名单 | `.jpg .jpeg .mjpeg .png .ttf .json .bin` |
| 字符级 | 拒路径穿越等非法字符 |
| 大小上限 | 单文件 **≤ 4MB** |
| （下载后）| 实际大小 == `expect_size`（非 0 时）+ CRC32/IEEE == `expect_crc`（非 0 时）|

落盘方式：先写 `<目标>.tmp` → 校验通过后**原子改名**为正式文件（**不会留半截文件**）。

### 5.4 结果码表（走 DP160，见 §5.5）

| 码 | 含义 | APP 文案建议 |
|---|---|---|
| 0 | ok | 成功 |
| 1 | 网络错误 | 检查网络 |
| 2 | **文件写入错误** | 检查 SD 卡（可能写满/写保护/未插卡）|
| 3 | 分片收齐超时（30s）| 重发 |
| 4 | 被取消（含"上一任务未退干净、本次未执行"）| 稍后重试 |
| 5 | 路径被拒（目录白名单/格式非法）| 路径或目录不合法 |
| 6 | 扩展名被拒 | 文件类型不支持 |
| 7 | 超过 4MB | 文件过大 |
| 8 | ⚠️ **保留码，本固件不产生** | —（写满表现为 2）|
| 9 | 实际大小 ≠ 期望大小 | 传输不完整，重发 |
| 10 | CRC32 不匹配 | 文件损坏，重发 |

### 5.5 结果怎么回来（**走 DP160，不新增 DP**）

```
DP160: "filedl:<path>#<码>:ok|fail"
例:    filedl:repo/assets/a.jpg#0:ok
```
* 对象字段 = `<路径>#<结果码>`；`ok/fail` 只是"码是否为 0"的冗余表达
* **回执在上传完全部并下载完成后才发**（不是收到分片就发）
* 回执字段上限 128B ⇒ 路径请勿过长（设备侧按 112B 设计）

**APP 侧典型时序**：
```
APP: 分片 0..N(DP169)  →  等  →  收 DP160 filedl:xxx#0:ok  →  完成
                                 收 DP160 filedl:xxx#2:fail → 按码提示
```

## 6. SD 卡现状与限制（⚠️ 目前先这样，后续再评估怎么改）

> 本节是**现状说明**，不是最终设计。**先按此对接**；改进方向见 §7.4，但时间与方案未定。

### 6.1 目录职责

| 目录 | 用途 | DP169 可否写 |
|---|---|---|
| `/sdcard/dl_img/` | 相册照片 | ✅ |
| `/sdcard/repo/` | 素材（表情/动效/字库/图标）| ✅ |
| `/sdcard/user/` | 用户自定义文件 | ✅ |
| `/sdcard/config/` | 设备配置（json 等）| ❌ **不开放** |
| `/sdcard/hist/` | 历史数据 | ❌ |
| `/sdcard/data/` | 运行数据 | ❌ |

### 6.2 DP169 落盘硬约束

```
目录根  : dl_img/  repo/  user/
后缀    : .jpg .jpeg .mjpeg .png .ttf .json .bin
单文件  : ≤ 4 MB
路径    : ≤ 128 字节
URL     : ≤ 1800 字节（超出显式拒绝，不静默截断）
协议    : HTTP(S)，只认 200/206，最多跟 3 跳 302
落盘    : 先 .tmp，成功后原子改名
分片    : 单帧数据 ≤252B，总片数 ≤8（即整包 ≤2016B），30s 收齐
```

## 1. 重新配网：请使用 DP150

**问题**：APP 的「重新配网」没有使用 DP150。

**正确做法**

| 项 | 内容 |
|---|---|
| DP | **150 `re_pairing`**（bool，只写 `wr`）|
| 下发 | `DP150 = true` |
| 设备行为 | 清配网信息 → 重启 → 进入配网模式；**本地数据全部保留**（设置 / 历史 / 校准 / 照片）|
| 回显 | 下发后设备回显该 DP（echo 确认）|
| 失败回执 | 被拒时收到 DP160 `re_pairing:trigger:fail`；**成功没有 ok 回执**（设备直接重启离线）|
| APP 处理 | 二次确认 → 下发 → 提示"设备将重启并进入配网" → 等待设备重新上线 |

**勿与 DP141（恢复出厂）混用**：

| 对比项 | DP150 重新配网 | DP141 恢复出厂 |
|---|---|---|
| 本地数据 | ✅ 保留 | ❌ 全部清除（含历史 / 校准 / 照片）|
| 配对关系 | 重新配网（可换账号） | 需 APP 再调 SDK `resetFactory` 解绑 |
| 教程流程 | 不进入 | 进入首次开机教程 |
| 成功回执 | 无（设备重启）| 无（设备重启）|
| 失败回执 | `re_pairing:trigger:fail` | `factory_reset:trigger:fail` |

> DP150 是只写（`wr`）DP：APP 不能主动读它的"当前值"，只能靠回显 / 回执判断。

## 3. 新增：删除所有照片 DP156

| 项 | 内容 |
|---|---|
| DP | **156 `del_all_photos`**（bool，只写 `wr`）|
| 下发 | `DP156 = true` = 清空设备相册（`/sdcard/dl_img/` 全部照片）|
| 命令性质 | **一次性命令**（非开关）：值保持 true 重发 = 幂等，不会出错 |
| 连带效果 | ① 置顶壁纸被清除；② 若设备正在看图，自动退出看图；③ APP 相册列表应同步清空 |
| **完成回执** | ⚠️ **没有主动回执**（设备不发 `del_all:...:ok` 推送）|

**确认方式（DP160 主动查询）**

```
APP 下发 DP160 = "del_all:"        ← 操作:对象（对象为空）
设备应答  DP160 = "del_all::ok"    ← 相册目录已空（注意是两个冒号）
```

建议：下发后延时 3~5 秒查询一次；未确认可再查一次（删除是异步执行的）。

> 单张删除请用 **DP155**（raw，载荷 = 文件名 ASCII）；确认用 DP160 查询 `del:<name>`（`ok` = 该文件仍存在，即未删掉）。

## 4. 【重点】日历史「对不上」—— 请按新帧格式重新解析

### 4.1 问题根因

APP 目前按**旧格式**解析：**日 = 单帧 96 点 / 周 = 7 点 / 月 = 31 点**（9 月 3 日联调说明、固件 1.0.2 时代的口径）。
现固件已改造：**日 = 每指标 7 帧、各自带日期头；周 = 最多 28 点；月 = 最多 180 点、分 1~2 段**。
按旧格式解析会把 7 帧中的**最老一帧（6 天前）**当成"今天"⇒ 日期与数据整体错位。

### 4.2 新帧格式

**日历史（131 / 134 / 137 / 164 / 165）—— 每天 1 帧，共 7 帧**

```
过去 6 天：帧 = [年偏移][月][日] + 96 × 点        （定长；年偏移 = 年份 − 2000）
今天：    帧 = [年偏移][月][日] + N × 点          （变长；N = 当前时刻槽 + 1）
槽 k ⇔ 该帧日期的 00:00 + k × 15min（k = 0..95）
len = 3 + N × 点宽   →   APP 用 len 反推 N
```

**周历史（132 / 135 / 138）—— 单帧**

```
帧 = [年偏移][月][日][N] + N × 点     （N ≤ 28；N = 已聚合天数）
点序：最老 → 最新；最后一个点 = 最近一次聚合日（通常为昨天）
N = 0（从未聚合）：整个帧不发
```

**月历史（133 / 136 / 139）—— 分段帧（1~2 段）**

```
帧 = [年偏移][月][日][段号][总段数] + M × 点   （每段 ≤ 90 点；段 0 = 最老）
总点数 ≤ 180（半年逐日均值）；总段数 = ceil(总点数 / 90) ⇒ 可能是 1 段
```

### 4.3 换算与槽位

| 指标 | DP（日 / 周 / 月） | 点宽 | 换算 |
|---|---|---|---|
| 水位 | 131 / 132 / 133 | 1B | **×2 = mL**（设备存 mL÷2）|
| 土壤湿度 | 134 / 135 / 136 | 1B | 直接为 % |
| 光照 | 137 / 138 / 139 | 2B 大端 | lux |
| 空气温度 | 164（**仅日**） | 2B **有符号**大端 | ÷10 = °C（支持负温）|
| 空气湿度 | 165（**仅日**） | 2B 大端 | ÷10 = %（0x0258 = 600 → 60.0%）|

### 4.4 上报时机

| 时机 | 内容 |
|---|---|
| 每 15 分钟采样后（栅格 :00 / :15 / :30 / :45） | 每指标 1 帧"今天"（共 5 帧；N 随时间增长）|
| 连云 / 全量状态上报（含 APP 主动请求） | 日 5×7 = 35 + 周 3 + 月 6 = **44 帧（上限）** |
| 每天 0 点 | 全量状态上报（跨零点后 APP 立即拿到新一天基准）|
| 设备启动并恢复 SD 历史后 | 补发一次全量历史 |

> 💡 **44 是上限不是定数**：月只有 1 段时实际 41 帧；周 / 月无数据时不发 ⇒ 首连可能只有 35 帧。

### 4.5 必读坑位

1. **点数以帧头为准**，不要写死 96 / 28 / 180。
2. **补 0 连贯**：没采到的槽 / 天以 0 补齐（曲线不断档）⇒ **0 可能是"未采集"而非真实 0**，建议灰显 / 断线处理。
3. **周 / 月点数 ≠ 天数**：N 是"已聚合天数"，设备断电会缺天；**右端对齐**（最后一点 = 最近聚合日，通常为昨天，不是今天），横轴只标相对刻度，**不要标具体日期**。
4. **今天帧随时间变长**：同一天多次收到时**整块替换**。
5. **日块日期由"今天"回推**：设备长期断电后，块日期与块内数据可能不严格对应——按帧头日期归档即可，**不要自行修正**。
6. **未对时帧**：帧头回退为 `2026-01-01`（年偏移 26 / 月 1 / 日 1）**且**今天帧 `N = 1` ⇒ 视为无效，**丢弃**。
7. **月总段数可能是 1**：不要等第 2 段；收到 `段号 == 总段数 − 1` 即认为接收完成（或超时兜底）。
8. **帧长自检**：日 ≤ 99B / 195B、周 ≤ 32B / 60B、月 ≤ 95B / 185B（1B / 2B 点宽）；与帧头矛盾 → 丢弃该帧。
9. **今天帧的两个正常现象**：23:45~23:59 期间 N 恒为 96（不再增长）；跨 0 点后 N 回到 1（新一天开始，不是丢数据）。

## 5. 水位校准流程改版（6 步）

> 固件自 1.0.16 起为**新编号语义**，APP 必须同步改版（按 0/1/2/3 旧编号下发会整体错位）。

### 5.1 步骤与回执

| DP140 | 语义 | 设备屏显示（发送后） | 回执对象 | 用户随后动作 |
|---|---|---|---|---|
| **0** | 开始会话（进校准页 + 提示倒空，**不采样**） | "请先将水箱倒空" | **`begin`** | 倒空水箱 |
| **1** | 采样空杯 | "空杯已记录，请加入 20 mL" | `step1` | 加入 20 mL |
| **2** | 采样 20 mL 点 | "20 mL 已记录，请再加 20 mL" | `step2` | 再加 20 mL |
| **3** | 采样 40 mL 点 | "40 mL 已记录，请点击完成保存" | `step3` | 点击完成 |
| **4** | 计算并保存 | 成功 / 失败页（2.5 秒后回主界面） | **`step4`** ← 保存结果，关键判据 | — |
| **5** | 取消（丢弃暂存） | "已取消"（2.5 秒后回主界面） | `step5` | — |

回执格式：DP160 `calib:<对象>:ok/fail`，例如 `calib:begin:ok`、`calib:step4:ok`。
断线重连对齐进度（可选）：DP160 查询 `calib:step1` / `calib:step2` / `calib:step3`。

### 5.2 时序原则（最关键）

**采样发生在报文到达的瞬间**——`0` 不采样，因此"倒空"可以**先看到设备提示再做**：

| 物理动作 | 必须先于 | 说明 |
|---|---|---|
| —（仅进页面） | 发 `DP140 = 0` | 设备立即提示"请先将水箱倒空" |
| 倒空水箱 | 发 `DP140 = 1` | ✅ 看到提示后再做 |
| 加入 20 mL | 发 `DP140 = 2` | 静置 ≥5 秒 |
| 再加 20 mL（累计 40） | 发 `DP140 = 3` | 静置 ≥5 秒 |
| —（保存） | 发 `DP140 = 4` | 点击即触发 |

⚠️ **第 1 页只能出现"倒空"**，不得出现"加入 20 mL"（否则用户提前加水，空杯基准偏移 20 mL，且设备校验查不出来）。

### 5.3 向导页面（5 页）

| 页面 | 文案（点按钮**之前**完成） | 主按钮 | 点击后发送 |
|---|---|---|---|
| 入口 | 点击"开始校准" | 开始校准 | `DP140 = 0` |
| 1/4 | 请将水箱中的水**完全倒空**，静置数秒 | 已倒空，记录空杯 | `DP140 = 1` |
| 2/4 | 请加入 **20 mL** 水，静置 **5 秒以上** | 已加入，记录 | `DP140 = 2` |
| 3/4 | 请再加入 **20 mL**（累计 **40 mL**），静置 5 秒以上 | 已加入，记录 | `DP140 = 3` |
| 4/4 | 点击后设备将计算并保存校准值 | 完成校准 | `DP140 = 4` |

- 采样步之间**间隔 ≥5 秒**（`1→2`、`2→3`）：按钮置灰 + 倒计时。
- 单步限时 **3 分钟**（设备看门狗超时自动取消 → 引导从第 1 页重来）。

### 5.4 退出 / 取消（必需）

- 退出入口**两处**：页头 `←` + 底部「取消校准」按钮，都弹**同一个二次确认**弹窗。
- 确认后发送 `DP140 = 5` → 等 `calib:step5:ok`（5~10 秒超时 ⇒ 提示"未收到设备确认"）。
- **Android 返回键 / 手势必须拦截**（走同一确认流程）。
- 设备校准页无任何实体按钮：不发 `5` 就只能等设备 **3 分钟看门狗**超时。

### 5.5 失败提示

| 失败步 | APP 提示 |
|---|---|
| 0（开始） | 未能开始校准，请确认设备在线后重试 |
| 1 / 2 / 3（采样） | 未检测到加水或操作过快，请确认已加入对应水量并等待 5 秒后重试 |
| 4（保存） | 校准数据异常，请从第 1 步重新开始 |

> 被拒时**重发本步**即可，不必回到第 1 页（设备屏会显示具体拒绝原因）。

## 6. 新增：屏幕亮度调节（DP117 + DP168）

固件已有现成 DP，**无需新增编号**：

| DP | 名称 | 类型 | 语义 |
|---|---|---|---|
| **117** | 自动亮度开关 | bool `rw` | **true = 自动**（按环境光跟随）／**false = 手动**（亮度由 DP168 决定）|
| **168** | 手动亮度 | value `rw` | **0 ~ 100**（0 = 灭屏）；**仅 DP117 = false 时生效**；自动模式下下发只缓存、不立即生效 |

**默认与持久化**

- 出厂默认：**DP117 = false（手动）+ DP168 = 100**（全亮）。
- 两个值都落设备 KV，**重启保持**。
- 下发后设备均回显（echo）；越界值（DP168 超出 0~100）被忽略并回显当前值。

> ⚠️ **平台命名提醒**：平台 DP117 的名称 / 描述目前仍是"**显示屏幕亮度开关** / true（屏幕默认亮）"（旧语义）——建议平台同步改名为"**自动亮度开关**"，否则 APP 文案容易被理解成"屏幕开关"。

## 7. SD 卡内容更新（方案讨论稿）

> **状态**：📝 **讨论稿 —— 待与 APP / 服务器团队确认采用方案**。固件**尚未实施**；确认后更新本节并排期。

### 7.1 问题

设备的表情动画、中文字库、天气素材等都存放在 **SD 卡**上，而**固件 OTA 只升级代码、不含 SD 内容**。由此产生固有矛盾：

> **固件升级后，SD 内容不会跟着更新** ⇒ 新固件需要的新素材 / 新字库在设备上缺失，
> 表现为：表情播不出、中文显示为方块、天气图标缺失。

同时素材本身也会迭代（表情换新版本、字库扩容等）——需要一个**统一的远程更新通道**，而不是每次换卡 / 返厂。

### 7.2 拟推荐方案：设备直连服务器自主同步

**核心思路**：设备按计划直连服务器，上报"我有哪些内容"，服务器返回"缺什么 / 该更新什么"，设备**静默下载**并落到真实位置。

```
      ┌──────────────────── 服务器 ────────────────────┐
      │  POST /Client/Product/getCommonFileList        │
      │  入参: 设备本地已有文件清单（路径 + 大小）      │
      │  出参: 设备缺失 / 需更新的文件（URL + 目标路径）│
      └───────────────────┬────────────────────────────┘
                          │
        触发: 开机 +30s / 每 12h / 手动触发
                          │
                          ▼
      ┌──────────────────── 设备 ──────────────────────┐
      │ ① 扫描白名单目录 → 组清单                       │
      │ ② POST 上报                                     │
      │ ③ 逐个下载（串行、限速、退避）                  │
      │    落盘: <目标>.tmp → 校验 → rename（原子）      │
      │ ④ 记录变更 → 「静默生效」                        │
      └────────────────────────────────────────────────┘
```

**方案要点**

| 项 | 设计 |
|---|---|
| 触发时机 | 开机 30s 后首次（等网络就绪）；之后每 **12 小时**一次；支持手动触发 |
| 更新范围 | 表情 / UI / 天气素材 / 状态页动画 / 教程素材 / **中文字库** / 植物映射（见 §7.3） |
| 判重 | 路径 + 大小（可选 md5）——**只下缺失 / 变更的**，不重复下载 |
| 生效方式 | **素材：下载完即生效**（下次播放用新文件）；**字库 / 映射：下次开机生效**（运行中已加载进内存） |
| 用户感知 | **全程静默** —— 不弹窗、不重启、不打断 |
| 可靠性 | `.tmp → 校验 → rename` **原子替换**：断网 / 掉电 / 空间不足都不损坏已有文件，下轮自动重试 |
| 安全 | 落盘路径**白名单 + 越界校验**（禁 `..`、禁绝对路径） |
| APP 参与 | **无** —— 设备直连，APP 不在链路上 |

**建议的接口形态（待服务器确认）**

```
请求  POST https://api.yikaltd.com/Client/Product/getCommonFileList
{
  "fileList":   [ {"path": "repo/assets/achoo.mjpeg", "size": 167030}, … ]
}

响应
{
  "retCode": 200,
  "retData": [
    { "filePath": "https://ossim.yikaltd.com/prodFile/v2/achoo.mjpeg",  ← 下载地址
      "target":   "repo/assets/achoo.mjpeg",                            ← 落盘路径（必需）
      "size":     167030, "md5": "a1b2c3…" }                            ← 校验（可选）
  ]
}
```

> **判重方式**：服务器**逐文件比对**设备上报的清单（路径 + 大小）——每次同步都能发现缺失 / 变更的内容（含用户误删、卡局部损坏等设备侧异常）。

### 7.3 内容范围（设备侧白名单）

| 内容 | 路径 | 用途 |
|---|---|---|
| 表情动画 | `repo/assets/*.mjpeg`（84 个） | 表情播放 |
| UI 素材 | `repo/assets/ui/`（cross、loading） | 失败提示 / 下载加载动画 |
| 天气素材 | `repo/assets/weather/`（4 套 × 14） | 首页动效 / 天气页 / 预报图标 |
| 状态页动画 / 教程 | `repo/Test_animation/`（22 个） | 状态页动画、教程素材 |
| **中文字库** | `repo/theme/font/zh/NotoSansSC-*.ttf` | 中文显示（运行时加载） |
| 植物映射 | `plant_map.json` | 植物识别 |

> 合计约 **167 个文件 / 31 MB**。相册与纪念日图片属用户数据，**不在同步范围**。

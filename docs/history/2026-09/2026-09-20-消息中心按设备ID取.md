# 消息中心改成按设备 ID 取（`getMessageListByMsgSrcId`），并把消息字段解包核实

- 环境：SSH 开发机（无 Flutter / Dart / Kotlin 工具链）
- 分支与起点：`main` @ `a9e937b`
- 影响范围：`MainActivity.deviceMessages`（安卓桥接）、`TuyaRepository.deviceMessages`、
  `FlowerpotState.loadDeviceMessages`、割草机-消息通知页的调试板、`MockTuyaRepository`、
  `docs/TUYA_CAPABILITY_AUDIT.md`

## 起因

产品问「是否支持涂鸦返回的日志类型区别」，并指出上一版调试板打出来的内容**明显不对**；
随后给了两条关键口径：

1. **一定要用 `getMessageListByMsgSrcId` 查**——标准的 `getMessageList` 是**聚合**结果，
   按它分页拿不到某台设备的全量消息；
2. **iOS 不是同名方法**，那边是 `fetchEncryptMessageDetailListWithListRequestModel`。

后台那条测试推送：等级「轻微」、推送编号 `GYjoVtpHsqHjpZbc`、名称与内容都是 `text2`、
设备 ID `6c2649322ed1365a00cadl`（设备 ID 不写进代码，调试板里可改）。

## 解包核实（不靠文档，也不靠猜）

`com.thingclips.smart:thingsmart:7.5.1` 父 POM → 模块 `thingsmart-personal-api` →
`classes.jar` → `tools/aar_class_dump.py`：

- `ThingHomeSdk.getMessageInstance()` 存在，返回 `com.thingclips.smart.sdk.api.IThingMessage`；
- `getMessageListByMsgSrcId` 有**四个重载**：
  `(int, int, MessageType, String, cb)` / `+boolean encryptImage` / `+boolean splitImageKey` /
  以及类型收成 `int` 的那版；
- `MessageType` 只有 `MSG_REPORT` / `MSG_FAMILY` / `MSG_NOTIFY` 三个常量（带 `getValue()`）；
- 回调回来的是 `MessageListBean`（`getDatas()` + `getTotalCount()`）；
- `MessageBean` **确实有类型字段**：`int msgType`（四个常量，含 `MSG_TYPE_PRD_WARN`）+
  `msgTypeContent`，另有 `msgCode`、`alarmType`、`extendParams` / `extendJson`、`msgSrcId`、
  `actionURL`、`dateTime` / `time`、附件三件套。
- 顺带确认：**Home SDK 里没有「设备日志」接口**。`IThingDevice` 上没有 log / alarm 方法；
  模块 `thingsmart-log` 是 SDK 自己的埋点上报（`ThingLogSdk` / `CfgBigData`），与设备事件无关。
  也就是说设备侧事件只有两个来源：消息中心 + MQTT 实时推送。

完整签名表写进了 `docs/TUYA_CAPABILITY_AUDIT.md` 新增的第五节。

## 改动

1. **安卓桥接 `deviceMessages`**：
   - 入参加 `deviceId`（= `msgSrcId`，**必填**）、`msgType`（默认 `MSG_REPORT`）、`offset`；
   - 反射**按名字**取 `MessageType` 常量（不写死枚举整数值），拿不到就把类上实际有哪些常量报回去；
   - 按解包出的四个重载**从参数少的往多的试**；命中后诊断里记下**实际选中的签名**
     （方法名 + 参数类型）、`msgType` / `msgSrcId` / 分页；
   - 结果多回 `totalCount`（`MessageListBean.getTotalCount()`）、`msgType`、`msgSrcId`；
   - **不再退回聚合的 `getMessageList`**：没给设备 ID 直接如实返回「要设备 ID」，
     找不到按设备取的重载就把方法清单交回去，人工看。
2. **Dart 侧**：`deviceMessages({required deviceId, msgType, offset, limit})` 一路传下去；
   iOS 的 `MissingPluginException` 分支现在会把**要调的 iOS 方法名**一并带回页面。
3. **调试板**：多了「设备 ID（msgSrcId）」输入框（默认填已绑定的第一台设备）和
   消息类型三选一；结果摘要多打 `msgSrcId` / `msgType` / `totalCount`。

## 同日追加：类型取告警那一档，拉不到时要能自证

产品反馈「**MessageType 要设置为告警**；我看日志好像是没有返回；安卓这边应该是能把**全部告警类消息**
读出来，就是看结果里有没有返回消息等级」。

### 把枚举值读出来了（不是猜）

从 `MessageType` 的 `<clinit>` 字节码里读常量值、从 `MessageBean` 的 ConstantValue 读静态常量：

| 常量 | 值 | 对应 |
| --- | --- | --- |
| `MessageType.MSG_REPORT` | 1 | **告警**（设备消息推送落这一档） |
| `MessageType.MSG_FAMILY` | 2 | 家庭 |
| `MessageType.MSG_NOTIFY` | 3 | 通知 |
| `MessageBean.MSG_TYPE_SYSTEM` | 0 | 系统 |
| `MessageBean.MSG_TYPE_NEW_DEVICE` | 1 | 新设备 |
| `MessageBean.MSG_TYPE_NEW_FRIEND` | 2 | 新朋友 |
| `MessageBean.MSG_TYPE_PRD_WARN` | **4** | 产品预警（告警类） |

所以「告警」= `MSG_REPORT`，桥接的默认值本来就是它；单条消息自己的 `msgType` 则应当是 `4`。

### 为了「没有返回」这件事能自证，加了三样东西

1. **`msgType: "ALL"`**：三档（告警 / 家庭 / 通知）**依次各取一次**，结果里 `perType`
   写明每一档返回几条（某一档失败记 `-1`，原因进诊断）。一次点击就能看出是「告警档空」
   还是「哪一档都空」。
2. **空结果时自动加探两个无参只读接口**：`getMessageMaxTime()`（消息中心最新一条的时间）与
   `requestMessageNew()`（有没有新消息），结果写进诊断 —— 用来区分「这台设备没有消息」与
   「整个消息中心就是空的」（账号 / 家庭对不上、推送没真的发出去都属于后者）。
3. **诊断里记下实际命中的重载**与每一档的 `MessageType(value=…)`，以及 `msgSrcId` / `offset` / `limit`，
   这样截图就能看出这一次到底按什么条件查的。

调试板对应多了「三档都试」这颗 chip，摘要与复制出来的文本都带上 `perType` / `totalCount`。
**任何情况下仍不会退回聚合的 `getMessageList`。**

### 仍然未验证

## 再追加：真机第一次跑的结果，以及为此加的三条诊断

产品用设备 `6c707c4ee7b5e5bea5m7hm` 跑了一次，日志给回来三段：实例方法清单、
`MSG_REPORT(value=1) → getMessageListByMsgSrcId(int, int, MessageType, String, cb)`、
以及 `getMessageMaxTime() → 1789916821` + `requestMessageNew() → MessageHasNew@1e8c1f6`。

### 从这份日志能确定什么

1. **调用链是对的**：实例方法清单与解包的签名逐条对得上（同时能看到混淆孪生
   `bdpdqbp(int, int, int, String, IThingDataCallback)`，反射用的是公开名，不受影响），
   命中的是 5 参那个重载，条件是 `msgSrcId=6c707c…m7hm offset=0 limit=50`。
2. **这次是真的返回 0 条**——那两个只读探针只在 `items` 为空时才跑，日志里有它们，就说明列表是空的。
   （顺带确认：`getDatas()` 返回 null 的情况会被当成一条 bean 打出来，不会走到探针，所以这里是真空。）
3. **账号的消息中心不空**：`getMessageMaxTime() → 1789916821`，**单位是秒**，
   即 2026-09-20 15:07:01 UTC，就是当天。
4. `requestMessageNew()` 回的 `MessageHasNew` 解包后只有三个 boolean：**`alarm` / `family` /
   `notification`** —— 三档就是告警 / 家庭 / 通知，`MSG_REPORT` 对应 `alarm` 这一档。
   第一次跑时这行打的是 `toString()`（`@1e8c1f6`），看不出内容。

### 所以剩两种可能，下一次跑要能分清

- ① 那条消息不在**告警**档；
- ② 它的 `msgSrcId` **不是这台设备**的 devId。
  ⚠️ 值得先核一下：后台监控列表给的设备 ID 是 `6c2649322ed1365a00cadl`，
  这次查的是 `6c707c4ee7b5e5bea5m7hm`，**不是同一台**。

### 为此加的三条

1. **每档返回条数写进诊断**（`MSG_REPORT ← 0 条（totalCount=0）`）——之前只有"调用了什么"，
   单看日志看不出结果；
2. **探针结果按 bean 展开**（`describeValue`）：`requestMessageNew() → alarm=…, family=…, notification=…`，
   直接看出哪一档有新消息；
3. **空结果时追加一步「按类型取一页」**：`getMessageListByMsgType(0, 20, 类型)`，把每条的
   `msgSrcId` / `msgType` / `msgTypeContent` / `msgCode` / `alarmType` / `dateTime` / `msgContent`（截断）
   打出来，用来回答「消息中心里到底有没有这条、它挂在哪个设备/哪一档」。
   ⚠️ 这一步**只是诊断**：不进 `items`、只取一页、只在空结果时跑；取数照旧只用
   `getMessageListByMsgSrcId`，**也照旧不碰聚合的 `getMessageList`**。

验证同前：无工具链，未跑 analyze / test / 编译；四个 Dart 静态自检（328 文件全绿）+
`kt_dangling_refs`（`MainActivity.kt` 绿）+ 括号配平。

### 默认设备 ID 改成联调那台

产品：「那你把默认值设置为这个 ID 不就行了」。调试板的默认值从「已绑定设备里的第一台」改成
常量 `_MessageDebugPanelState._defaultDeviceId = '6c2649322ed1365a00cadl'`
（后台监控列表里那条 `text2` 推送挂的就是它）：

- 只是**调试板的默认填充值**，不参与任何业务逻辑；输入框照旧可以改；
- **把这个常量置空**就回到原来的行为（取已绑定设备里的第一台）；
- 同时在输入框下面列出**当前账号已绑定的设备 ID**——查不到消息时，先看这台设备到底在不在这个账号里。

# 2026-09-11（晚）「零系统框」终审：那版"没弹框"的从未配成，面板路线可行但不走

## 产品的问题

> 早期版本出现过一次……手动点击连接设备，然后整个配网流程没有系统弹框……早期的一个版本
> 实现过，你检查下，现有技术是否可以整个配网流程不弹系统框。
>
> （补充）那版只是 WIFI 名称显示不对，应该是「将设备改为自动连接」那个需求上下的几个版本。

## 一、把两天 40 个配网提交全部翻了一遍

| 时段 | 提交 | 连热点机制 | 系统框 | 配成过？ |
| --- | --- | --- | --- | --- |
| 09-10 下午 | `2ff0dd9` `e2a479e`（搜到就自动连） | `WifiNetworkSpecifier` | **弹** | 能 |
| **09-10 晚 20:45–22:05** | `223bdae` `b3d0d09` `da5a054` `3ea5ea5` `39d29d6` `78afe2a` | **交给涂鸦新流程 `queryDeviceConfigState`**；`da5a054` 起兜底 `openWifiPanel` | **不弹** | **从未** —— 全是 `207220` |
| 09-10 深夜起 | `a07820c` 之后 | 回到 `WifiNetworkSpecifier`，收在「连接」按钮 | 弹一次 | 能 |
| 09-11 凌晨 | 静默连接 / Suggestion 探针 | `WifiManager#connect` / `WifiNetworkSuggestion` | 不弹 | 从未（真机判死） |

产品记忆里那版"手动点连接、全程没框、只是 Wi-Fi 名显示不对"，就是**第二段**：
`78afe2a`「动线改为搜到 → 自动连热点 → 点连接 → 选 Wi-Fi → 输密码」前后。

### 它为什么没框

因为**根本没有东西去连热点**。那几版把连热点整个交给了涂鸦 SDK 的 `queryDeviceConfigState`，
而涂鸦次日书面确认：文档里「SDK 会在指定时间内自动去连接 AP 热点」**说的是设备端**，
手机侧不会连。所以那几版的实际行为是：不弹框 → 手机一直在路由器上 → SDK 空等 45 秒 →
`207220` 配网任务整体超时。**没框和配不成是同一件事的两面。**

### 「Wi-Fi 名显示不对」是什么

`_applyCurrentSsid` 直接读"手机当前连的网络"填进输入框。那几版里手机要么还在路由器上
（名字对但和"已连设备"的页面状态矛盾），要么被上一次尝试留在 `SmartLife-xxxx` 上（把
设备热点名填成了要连的路由器）。后来用 `PairingArguments.routerSsid` 在**连热点之前**把
路由器名抓下来带过去，这个 bug 已经修掉，**现版没有**。

⇒ **那一版不是"差一点就成"的基线，是一版没配成过的。不要再往回找。**

## 二、现有技术能不能全程不弹框——能，但不该走

第三方 App 在 Android 10+ 上让手机连上一个**没有外网的指定热点**，只剩三条：

| 路 | 系统框 | 结论 |
| --- | --- | --- |
| SDK 自己连（新流程 + 新固件） | 无 | 只对**智能生活（预置/白名单）**有效，涂鸦书面确认第三方做不到 |
| `WifiNetworkSpecifier` + `requestNetwork` | **弹一次**授权框 | 现版；App 自己持有连接 |
| **系统 Wi-Fi 面板**（`Settings.Panel.ACTION_INTERNET_CONNECTIVITY`，`da5a054` 的 `openWifiPanel`） | **无**授权框 | 可行——用户在浮起的系统列表里自己点 `SmartLife-xxxx`，再接**标准 AP** `pairViaHotspot` 就能配成。`da5a054` 当时之所以失败，是它后面接的是新流程，不是面板本身的问题。这个组合**从没被完整试过** |

所以"零系统框"技术上**有**：面板路线。但它和"最稳定、最简洁"是反的：

1. **步骤更多**：用户要离开 App 上下文，在列表里找到并点 `SmartLife-xxxx`，等连上，再回来。
   现版是点一下「连接」。
2. **连接归系统持有，不归 App**。Android 10 判定该网络"无互联网"后**可能中途自己把手机切回
   路由器**——表现就是随机的 `207220`。`WifiNetworkSpecifier` 那条是 App 持有请求，系统
   在请求期间**保证**不切走，这正是现版稳定的原因。
3. 面板路线多半还会冒一条「此网络无法访问互联网」的系统通知——系统 UI 并没有真的消失。

## 三、产品拍板（2026-09-11 晚）

**保留一次系统框（`WifiNetworkSpecifier`），不走面板。** 原话选项：「保留一次系统框（推荐）」。

写进 `PRODUCT_RULES` §4.0。今后谁再提"零系统框"，先读本文第一、二节。

## 四、顺手做的三件事

1. **删掉第三步那 1–2 秒随机假延时**（`_cloudStageDelay` + `Future.delayed` + `dart:math`
   import）。SDK 回 `onActiveSuccess` 时设备**已经**注册到云端，那段等待只是让第三步在
   进度卡上"亮一会儿"，纯装的。成功页本身就是"云端完成"的信号。配网整体快 1–2 秒。
2. **核实成功路径会放热点**：原生 `startActivator` 的 `onSuccess` → `stopActivator()` →
   `unbindProcessNetwork()` → `releaseHotspotRequest()`。不会再出现「配网成功但读不到设备」。
3. **搜索页真扫提到 32 秒**（系统允许的上限，见 `febe84a`）。

## 五、为什么产品分不清是哪个版本——版本号两天没动过

`pubspec.yaml` 自 09-09 起没有任何提交，两天 40 多个包全是 `1.0.0+1`；而且**关于页的版本是
硬编码**（`about_page_model.dart: version: '1.0.0'`），不读 APK。所以哪个包都长一样。

- 本次把 `pubspec` 提到 `1.0.0+2`，**此后每出一个测试包 bump 一次 build number**
  （写进 `PRODUCT_RULES` §6）。系统「应用信息」里能看到 versionCode。
- 关于页要显示真实版本得接 `package_info_plus`。本机无工具链、加依赖无法验证，**没有加**，
  列为待办。

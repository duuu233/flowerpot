## 1. 样式：不靠眼睛猜，直接从设计稿取像素

产品反馈「标题输入框的白色和灰色背景样式有问题」「内容输入部分边距不对」。没有设计工具，
就写了段脚本把 `docs/UI/v2/智能花盆ysplanter/编辑纪念日-自定义-文字.png`（1125×2436，@3x）
自己解出来取样和量尺寸——PNG 的 zlib + 五种行过滤器手写解一遍即可，不必装 Pillow。

量出来的（换算成逻辑像素，375 宽）：

| 项 | 设计稿 | 改之前的代码 |
| --- | --- | --- |
| 输入框填充色 | **#F7F7F7** | `AppColors.canvas` #FAFAFA |
| 标题框 / 日期框高度 | **48** | 56 |
| 卡片左右内边距 | **24**（卡片 335 宽、字段 286 宽） | 20 |
| 文字内容框总高 | **109** | 16+104+计数+12 ≈ 150+ |

**填充色就是产品说的那个问题**：`canvas`(#FAFAFA) 是**页面**底色，摆在白卡片
（`surface` #FFFFFF）上只差 2%，框和卡片几乎分不出来。新增 `AppColors.fieldFill`
(#F7F7F7)，注释里写明「别拿 canvas 当它用」以及值的出处。`auth_page` 里原来写死的
`Color(0xFFF7F7F7)` 也换成这个 token（同值，无视觉变化）。

内容框按总高 109 倒推内部：`12(上) + 输入区 67 + 4 + 计数行 16 + 10(下)`，常量都写成
名字带出处，省得下次又按感觉调。

⚠️ 同样「白底上铺 canvas 灰」的还有 `AppDialogTextField`（app_dialog.dart:334）和
`schedule_slot_dialog.dart:265`——本轮**没动**，产品没提到那两处。要一起改说一声。

## 2. DP 154 帧格式核对

对着产品给的规格逐条核了 `tuya_memorial_codec.dart`：

| 规格 | 代码 | 结论 |
| --- | --- | --- |
| `ID(4B 大端) \| 日期(4B 大端) \| type(1B) \| 内容长度(1B) \| 内容(NB)` | `_frame` 正是这个顺序，`_uint32` 是大端 | ✅ |
| ID：APP 分配、设备按 ID upsert | `MemorialEntry.id` 由 App 给，写帧时原样带 | ✅ |
| 日期 `YYYYMMDD` | `dateValue` = `年*10000 + 月*100 + 日` | ✅ |
| `000000` = 停用（保留数据） | `disabledDate = 0` | ✅ |
| `111111` = 删除该 ID | `deletedDate = 111111` | ✅ |
| type 1=文字 / 2=图片 | `MemorialContentType.text(1) / image(2)` | ✅ |
| 停用/删除帧 type 与内容可填 0 | 停用帧 `type: 0, content: []`；删除帧同样 | ✅ |
| 文字最多 **15 个汉字（45 字节）** | 只挡了 15 个**字符** | ❌ **本轮补上** |

补的就是最后一条：新增 `TuyaMemorialCodec.maxTextBytes = 45`，编码时超了直接抛，编辑页
保存前也按字节挡一次并给人话提示。**字数和字节都要挡**——15 个汉字正好 45 字节，但 15 个
emoji 是 60 字节，只数字符会让帧超长、固件那边截断；反过来 15 个 ASCII 才 15 字节，也不该
因为字节没到 45 就放宽到 45 个字符。

### ⚠️ 一个仍未验证的前提

`TuyaMemorialCodec.encodeRaw` 把帧写成**大写十六进制字符串**下发，而上报回来是 base64。
代码注释里写着「这是约定，不是验证过的事实——本项目还没在真机上写过任何 raw DP」。
154（纪念日）、155（删图）、157（置顶）都走这一条。**如果这个约定错了，这三件事都发不出去**，
建议真机上先验一次纪念日保存。

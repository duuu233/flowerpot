## 背景与目标

产品：「看清楚需水状态页面的读取 DP 指令的逻辑，检查下其它功能模块，光照、温度、湿度等是否也有按对应的 DP
读取有关数据」；补充：「首页-绑定设备页面的下面四个子页面，需水状态、光照状态、空气温度、相对湿度，
基本都是一套逻辑，只是 DPID 不一样」。

## 核对结果（按 `09_12` 功能点表逐条对）

基准：需水状态页 = 实时 105/106 + 状态 107（没报按阈值兜底）+ 历史 131–136（`historyFor`）+ 进页面把历史 DP
到货情况打进联调日志。

| 页面 | 实时 / 状态 DP 解析 | 历史 | 联调日志 |
| --- | --- | --- | --- |
| 需水状态 | 105、106、107 ✅ | 131–136 ✅ | 只有历史 DP 体检，且把光照那三条也打出来 |
| 光照状态 | 109、110、108 ✅ | ❌ **读错了**：页面读 `SensorMetric.dli`，仓库把 137–139 挂在 `SensorMetric.light` 下 | ❌ 一条 DP 都没有 |
| 空气温度 | 112（÷10）、113、146 ✅ | 功能点表**没有**温度历史 DP（空态合理） | ❌ 一条 DP 都没有 |
| 相对湿度 | 114（÷10）、115 ✅ | 功能点表**没有**湿度历史 DP（空态合理） | ❌ 一条 DP 都没有 |

实时与状态 DP 的解析（`MethodChannelTuyaRepository._device`：DP 号、枚举值、倍数）四页都对得上功能点表，
问题集中在两处：

1. **光照历史永远是空的。** `DeviceHistory` 的键是 `metric.name.range.name`，`decodeHistory` 把 `illuminance`
   组（137/138/139）经 `_historyMetric` 映射成 `SensorMetric.light`；光照状态页却按 `SensorMetric.dli` 取——
   功能点表里没有 DLI 历史，所以真机上始终「暂无 DLI 历史」，137–139 报上来也画不出来。页面注释
   「DLI is derived from PPFD, which has no history function point」掩盖了这一点。
2. **除需水页外，状态页进页面在联调日志里看不到读了哪些 DP、读到什么值。** 路由观察器对状态页只记
   「进入 ← [光照]」，没有 DP 行。

## 变更内容

- `TuyaRepository.reportedDps(deviceId, identifiers)`：返回设备快照里这几条 DP 的**原始值**（没快照返回 null，
  没报的 DP 对应 null）。Mock 仓库返回 null。
- `FlowerpotState.logStatusDps(deviceId, page, identifiers, {hasHistoryDp})`：记一行
  `读取 ← [空气温度] DP112 air_temperature=246（÷10=24.6），DP113 air_temperature_status=未上报，…`；
  `hasHistoryDp: false` 时再记一行「功能点表里没有这项的历史 DP（只有 131–139），曲线为空态」。
- `logHistoryDiagnostics` 加 `metrics` 过滤：需水页只打 waterLevel / soilMoisture，光照页只打 illuminance；
  不传仍九条全打（报表页）。
- 四个页面 model 上加 `reportedDps` 清单（与 `fromDevice` 实际取的字段对应），四个页面进页面各调一次。
- 光照状态页：历史改读 `SensorMetric.light`（137–139）；图表标题「DLI（每日光量积分）/ mol/m²/天」改为
  「光照强度 / lux」，空态「暂无光照历史」；日视图 96 点按一刻钟换算小时标签（原来按下标当小时）。
- `LightDliBarChart`：纵轴上限原先写死 1.0（给 DLI 的），加 `maxValue` / `decimals` 参数，光照页按数据取
  1/2/5×10ⁿ 的整刻度；超出上限的柱子截在顶部。
- 路由观察器里四个状态页的日志名改成页面标题（需水状态 / 光照状态 / 空气温度 / 相对湿度），和页面自己记的
  DP 行对得上。
- 测试：新增 `test/tuya/status_page_dps_test.dart`（DP 清单对照功能点表；138 的 hex 周包解到 `light` 而 `dli`
  为空；`reportedDps` 原值与 null；日志行格式与倍数换算；光照页历史体检只打 137–139）；
  `light_status_page_test.dart` 断言标题「光照强度」、不再出现 DLI 标题、日志里有「读取 ← [光照状态]」。

## 关键决策

- **光照历史画 lux，不画 DLI。** 137–139 报的是照度（0–9000 lux）；DLI 需要 lux→PPFD 的换算系数（和光源有关），
  拍一个常数属于「写死数据」。设计稿的 DLI 图要等设备新增 DLI 历史 DP 或产品给定换算口径。
- 日志值取**快照原值**而不是页面上显示的值：页面值兜过底（没报时水位 0、状态按阈值推），分不清设备报没报。
- 电池状态页不在这次范围（产品点名的是四个子页），未改。

## 未完成项与风险

- **日期前后翻页不重新取数**：四个页面的 `periodOffset` 只改标题日期，图还是设备最近一次上报的那一包
  （设备只报当前窗口，也没有按日期查询的 DP）。翻到「前一天」看到的仍是今天的数据，这是现状，未改。
- **停留在页面时新到的历史 DP 不会刷新曲线**：历史在进页面 / 切日周月时取一次；实时值与状态会随上报刷新。
- 周视图标签固定「周一…周日」，而周包带的是「起始日」，不一定从周一开始（需水页同样如此）。
- 光照日包 96 根柱子在 375 宽屏上很细，视觉效果未经设计确认。

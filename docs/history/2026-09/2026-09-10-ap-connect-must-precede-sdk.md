# 2026-09-10（晚）实测定论：SDK 不会替我们完成首次连接设备热点

## 实测数据

用最新包（完整官方序列）复测，失败页给出：

```
配网失败，请重试
设备未能成功连接到当前Wi-Fi网络
配网任务整体超时，设备全程没有报过进展：…（207220）
失败 45073ms
```

## 判读

耗时行里**只有「失败」、没有「连设备」**——说明 ① `apQueryDeviceWifi` 自己抛了异常，
它后面那个 `mark('连设备…')` 根本没执行。45073ms ≈ 我们传下去的 `queryTimeout`（45s，
经 `tuya_repository.dart` 转成 45000ms 交给 `ApQueryBuilder.setTimeout`），
也就是 `queryDeviceConfigState` **跑满整个超时窗口**才报 `207220`（配网任务整体超时）。

四条事实合起来：

1. **完整官方序列全部跑到了**：`getDeviceSecurityConfigs` 已预取（`649d22d`）、
   `newOptimizedActivator` + `queryDeviceConfigState` 都在，没有缺步。
2. 返回的是**通用任务超时 `207220`**，不是 `207201`（和设备建立连接通道失败）。
3. **那 45 秒里没有出现任何系统弹框。**
4. 手机全程连在路由器上。

Android 10+ 上，任何应用——**包括涂鸦 SDK，它只是跑在我们进程里的一个库，没有任何额外
特权**——要连上指定 Wi-Fi 热点只有两条路：`WifiNetworkSpecifier`（必弹系统入网授权框）
或用户自己去系统设置连。既然一个框都没弹，**SDK 就没有尝试去连**；它的前提是
「手机已经在设备热点上」。

这与官方 AP 文档自己的开篇一致（原流程与新流程同一页）：

> 将手机连接到配网设备 Wi-Fi 热点后，App 与设备直接通过 Wi-Fi 进行通信配网……
> **但用户需要手动切换手机的 Wi-Fi 设置**

而「在配网过程中，SDK 会在指定时间内自动去连接 AP 热点」那句写在**「恢复配网」**一节里，
讲的是配网中途掉线后 SDK 重连**它已经连过的**那个热点，**不是**替我们完成首次连接。
之前把它读成通用承诺，是误读——`b3d0d09` 那版就是建立在这个误读上的。

## 结论：首次连接热点必须由我们（或用户）完成，没有第三条路

| 方案 | 用户要做什么 | 代价 |
| --- | --- | --- |
| A. App 发起 `WifiNetworkSpecifier` | 在系统授权框上点一次「连接」 | **有弹框**（产品明确不要）。但只 1 次交互，最可靠，每次都成 |
| B. 引导用户在系统 Wi-Fi 里连一次 | 打开 Wi-Fi 面板 → 点设备热点 → 回 App | **没有授权框**，这正是涂鸦文档写的做法。系统会**保存**这个网络，同一台设备之后可能自动重连；换设备（SSID 不同）要再来一次。可用 `Settings.Panel.ACTION_INTERNET_CONNECTIVITY` 以底部弹层形式出现，不必离开 App |
| C. `WifiNetworkSuggestion` | 首次在通知上批准一次，之后静默 | 之后无感，但**连接时机由系统决定、不可控**，可能本身就导致超时 |

⚠️ **没有「零交互」的方案。** 这不是 SDK 选型问题，是 Android 10+ 的平台限制。

## 状态

等产品在 A / B / C 之间决定后再改代码。**不要**在未决定前把
`WifiNetworkSpecifier` 悄悄加回去——产品已明确「不要弹框」。

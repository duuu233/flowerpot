## 1. 防重复点击：把 loading 抽成公共件，按缝隙补齐

原来只有首页那一处有 `_withBlockingProgress`。抽到
`lib/src/shared/widgets/blocking_progress.dart`，改名 `withBlockingProgress(context, action)`。

**为什么光靠 `FlowerpotState.busy` 不够**（这是这次补的主要理由，写进了那个文件的头注释）：

1. `busy` 只在状态层 `_guard` 里翻，**动作开始之前那几十毫秒**按钮还是活的；
2. 有些动作前面夹着系统弹层（选图、确认框），那一段根本不在 `busy` 里；
3. 有些动作是**一串**请求（例如逐张删图），两次请求之间 `busy` 会掉回 false，按钮闪回可点。

补齐的地方：

| 页面 | 动作 | 原来的保护 |
| --- | --- | --- |
| 定制动画 | 上传 / 置顶 / 删除（整串） | 只有 `state.busy` |
| 其他设置 | 温度单位、时间格式等设置项 | 只有 `state.busy` |
| 其他设置 | 重新配网、移除设备、恢复出厂 | **无** |
| 纪念日 | 删除 | **无** |
| 设备信息 | 改名 | **无** |
| 选择植物 | 确认选择 | 只有按钮的 `state.busy`，而详情页是**程序化**调过来的，绕过按钮 |

已经有保护、这次没动的：七个设置页（led / display / hearing / touch / vibration / behavior /
plant_detection）都有 `updating` 标志并把它传给开关卡片显示进度；纪念日编辑页有 `_saving`
并且按钮已经是 `loading: _saving`。

定制动画页除了公共 loading 还加了页面自己的 `_busy`——删除是一串请求，公共 loading 罩住的是
整串，但按钮的禁用态要靠页面自己的标志才不会中途闪回。

## 2. 定制动画：底部栏按「有没有选中图片」换面孔

产品口径：上传按钮改成底部悬浮的长按钮（约 80vw、圆角），选中图片后切换成几个功能按钮，
取消选中再切回来；**最左边那颗要是置顶**（DP 157 `pin_photo`），原来挂的是上传，DPID 不对。

- **没选中**：`FractionallySizedBox(widthFactor: .8)` 包一颗 `FilledButton`（`StadiumBorder`、
  高 50），样式照搬选择植物页底部那一颗。原来是一颗 56 的小圆钮，产品反馈「太小了」。
- **选中了**：一排圆钮 —— **置顶** → 上传 → 删除 → 取消选择。上传两种状态下都在
  （产品补充：「原来的上传你也可以保留」），只是形态不同。
- 置顶按 DP 157 一次只带一个文件名，所以**只在恰好选中一张时可用**，`_pinSelected` 里再兜
  一次，防止状态和界面对不上时误发。
- 四颗圆钮的间距从 `xl`(20) 收到 `lg`(16)：4×56 + 3×16 = 272，375 宽减去页边距还剩 343，排得下。

测试里那条「有图才画删除选中与取消选择」按新行为重写成「底部按钮按有没有选中图片换面孔」：
没选中只有长按钮 → 点一张图出现置顶/上传图标/删除/取消 → 点取消切回长按钮。

## 追加：打包报的那一处编译错误

```
lib/src/features/devices/presentation/device_other_settings_page.dart:122:37: Error:
The argument type 'ActionResult?' can't be assigned to the parameter type 'ActionResult'.
```

`withBlockingProgress` 返回 `T?`（null 表示页面已经不在了，动作压根没发起），
`_updateSetting` 里漏了判空。**八个调用点只有这一个漏**——其余七个都写了
`result == null` 或 `result != null`。补上 `if (!mounted || result == null) return;`。

### 新增 `tools/dart_nullable_await_check.py`

这是本机没有 Dart 工具链之后踩到的**第二类**类型错误了（上一次是 `getJson` 的 `Object?`
被当 Map 索引）。第一类没法机械查，但这一类可以，因为它有很窄的形状：**已知返回可空的
辅助函数**，返回值赋给变量之后第一次被用到时必须是一次判空。

- 名单写死在脚本的 `NULLABLE_HELPERS` 里（目前 `withBlockingProgress` 和定制动画页的
  `_run`），所以不会到处误报；新增同类辅助函数要往名单里加一行，否则这条防线对它无效。
- 判空认这几种形式：`x == null` / `x != null` / `x?.` / `x ?? ` / `x!`。
- 自测方式和另外两个检查器一样：拿改动前的坏文件跑，**报出的行号（122）与编译器完全
  一致**；跑全库 282 个文件零误报。

已写进 `docs/PRODUCT_RULES.md`：改完 Dart 要跑 `dart_string_check` + `dart_dangling_refs`
+ `dart_nullable_await_check` 三个。

## 追加：搜索页设备名闪一下、定制动画选中态去掉上传图标

### 1. 设备名先闪一串标识再变成真名

产品：「搜索出设备，设备名称会闪一下，先显示一串字符感觉像广播ID，然后才显示具体名称。」

根因在 `_FoundDevice.label` 的回落顺序：云端产品名还没查回来时它直接退到
`BleDevice.label`，而**BLE 广播常常既没有名字、mac 也是空的**（真机实测就是
`mac=''` / `uuid='uuid23119e1d4a2b66fc'`），于是 `BleDevice.label` 只能退成
`设备 uuid23119e…` ——一串十六进制先画出来，一两秒后被产品名顶掉，看着就是闪一下。

改成**查的过程中留白**（画「正在识别设备…」），有定论了再画最终名字。

关键是「有定论」要判全，少一种就会留下一个永远转不完的占位：

| 情况 | 判据 | 结果 |
| --- | --- | --- |
| 查过了（含查空、查失败） | `_bleProductInfo` 里有这个 uuid 的键 | 有定论，退回广播名 |
| 正在查 | `_productInfoInFlight` 含它 | 留白 |
| 还没轮到 | 在待查名单里（信号前 20 台且 uuid/pid 齐全） | 留白 |
| **名单外** | 上面都不满足 | **有定论**——它压根不会被查，立刻退回广播名 |

最后一行是这次特意补的：只看 in-flight 的话，信号弱、排在 20 名之外的设备会永远停在
「正在识别设备…」。

### 2. 定制动画选中态不画上传图标

产品二次明确：「选中图片的时候，下面的上传图片小图标就不需要了，只有没选中图片的时候，
展示大的上传按钮就行。」——撤掉上一轮按「原来的上传你也可以保留」加的那颗图标。

选中态现在只有三颗：**置顶**、删除、取消选择。要传新图先点「取消选择」。测试同步改。

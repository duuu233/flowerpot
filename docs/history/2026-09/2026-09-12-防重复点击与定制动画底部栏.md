## 1. 防重复点击：把 loading 抽成公共件，按缝隙补齐

原来只有首页那一处有 `_withBlockingProgress`。抽到
`lib/src/shared/widgets/blocking_progress.dart`，改名 `withBlockingProgress(context, action)`。

**为什么光靠 `FlowerpotState.busy` 不够**（这是这次补的主要理由，写进了那个文件的头注释）：

1. `busy` 只在状态层 `_guard` 里翻，**动作开始之前那几十毫秒**按钮还是活的；
2. 有些动作前面夹着系统弹层（选图、确认框），那一段根本不在 `busy` 里；
3. 有些动作是**一串**请求（例如逐张删图），两次请求之间 `busy` 会掉回 false，按钮闪回可点。

补齐的地方：

| 页面 | 动作 | 原来的保护 |
| --- | --- | --- |
| 定制动画 | 上传 / 置顶 / 删除（整串） | 只有 `state.busy` |
| 其他设置 | 温度单位、时间格式等设置项 | 只有 `state.busy` |
| 其他设置 | 重新配网、移除设备、恢复出厂 | **无** |
| 纪念日 | 删除 | **无** |
| 设备信息 | 改名 | **无** |
| 选择植物 | 确认选择 | 只有按钮的 `state.busy`，而详情页是**程序化**调过来的，绕过按钮 |

已经有保护、这次没动的：七个设置页（led / display / hearing / touch / vibration / behavior /
plant_detection）都有 `updating` 标志并把它传给开关卡片显示进度；纪念日编辑页有 `_saving`
并且按钮已经是 `loading: _saving`。

定制动画页除了公共 loading 还加了页面自己的 `_busy`——删除是一串请求，公共 loading 罩住的是
整串，但按钮的禁用态要靠页面自己的标志才不会中途闪回。

## 2. 定制动画：底部栏按「有没有选中图片」换面孔

产品口径：上传按钮改成底部悬浮的长按钮（约 80vw、圆角），选中图片后切换成几个功能按钮，
取消选中再切回来；**最左边那颗要是置顶**（DP 157 `pin_photo`），原来挂的是上传，DPID 不对。

- **没选中**：`FractionallySizedBox(widthFactor: .8)` 包一颗 `FilledButton`（`StadiumBorder`、
  高 50），样式照搬选择植物页底部那一颗。原来是一颗 56 的小圆钮，产品反馈「太小了」。
- **选中了**：一排圆钮 —— **置顶** → 上传 → 删除 → 取消选择。上传两种状态下都在
  （产品补充：「原来的上传你也可以保留」），只是形态不同。
- 置顶按 DP 157 一次只带一个文件名，所以**只在恰好选中一张时可用**，`_pinSelected` 里再兜
  一次，防止状态和界面对不上时误发。
- 四颗圆钮的间距从 `xl`(20) 收到 `lg`(16)：4×56 + 3×16 = 272，375 宽减去页边距还剩 343，排得下。

测试里那条「有图才画删除选中与取消选择」按新行为重写成「底部按钮按有没有选中图片换面孔」：
没选中只有长按钮 → 点一张图出现置顶/上传图标/删除/取消 → 点取消切回长按钮。

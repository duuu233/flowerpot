## 背景与目标

**大前提（用户原话）**：「目前没有设备支持，只需要点击对应的页面或者对应的操作，
上报下发对应的 DPID，在日志中显示就行。」

所以这一轮做的是：把 09-18 上午做的那套割草机静态页**接到功能点上**——每个动作算出它该发的
DP 号与值，写进联调日志；只读 DP 没有设备会推，由一块模拟上报面板代劳。

## 变更内容

### 1. 新增 DP 层

- `mower_dp.dart`：DP 号常量 + 枚举（DP3 模式 / DP5 状态 / DP117 充电 / DP107 时区 25 值 /
  DP109 语言 18 值）+ DP18 故障位图文案 + **DP101 割草计划 88 字节编解码** +
  **DP103 区域配置 25 字节编码**；
- `mower_device.dart`：这台"设备"的当前 DP 值与**唯一的下发出口** `_deliver`。
  下发＝记日志 + 本地回显；模拟上报的行带「［模拟］」。接真机时只改 `_deliver` 一处。

### 2. 逐条落实产品口径

| 用户口径 | 落点 |
| --- | --- |
| 割草计划不存数据库、显示依赖 DP 解析 | 计划页画的就是 `MowerDevice.schedule`（DP101 解析结果） |
| 停止/继续下发 DP2，true=停止显示、false=继续显示；停止时左三不可点 | `_ActionPanel` + `MowerDevice.commandsEnabled` |
| 自动/定点/回归下发 DP3 | 「自动」= **smart（随机割草）** |
| DP3 = 当前指令则置灰不可重复点 | `MowerDevice.isCurrentMode` |
| 点三颗前判断盖子 DP，异常弹窗且不下发 | `_sendMode` 先看 DP118，弹 `showAppNoticeDialog` 后直接 return |
| 首页黄色提醒依赖 DP18（13 条文案） | `MowerFault.messages`（产品给的原文一字未改）→ `_NoticeBar` |
| DP109 没内容按手机语言给默认值；保存才下发 | `MowerLanguage.forLocale` + 语言页 |
| 启动/停止优先级最高 + 左三不可重复 + **记忆** | 停止再启动按 `lastCommandedMode` 回到上次那颗 |
| 编辑弹窗时长自己算；修边上面加时段总开关（默认开、关了置灰）；判断时段不重复 | 编辑弹窗 |
| 没有 DPID 的功能：进页面/点按钮提示「当前还没有支持的 DPID」 | 设备参数、消息通知、重新配网、设备升级、删除设备 |
| 时区：没开自动设置时用前端本地时区表 | 时间同步页（25 条本地时区，自动设置开着就跟手机走） |

### 3. 帮助中心按产品 ID 分流

后台 `getBasicData.deviceIdList` 里现在**两款产品都有**（花盆 `yciq4kssu1fv8umn`、
割草机 `mz7g3yzaufvoh4ls`）。原来的口径是「取第一个」，再这么取，花盆的常见问题会随后台排序
变成割草机的。改为**先在列表里找本产品**，找不到才退回第一个（仍不写死兜底）；
割草机设置页的「帮助中心」带 `MowerDp.productId` 进去。

### 4. 涂鸦消息调试板（产品当轮追加）

问题：**涂鸦返回的设备消息里到底有没有类型字段**，有的话「消息通知」那三个分类页
（日志/提醒/告警）才做得出来。

- 安卓桥接新增 `deviceMessages`：反射拿消息中心实例（`getMessageInstance` 等逐个探）、
  调列表方法、把每条消息 bean 的**所有无参 getter** 原样 dump 上来；
  **拿不到也不抛错**，把「试过哪些名字、这个类上实际有哪些方法」一并回给 Dart；
- `TuyaRepository.deviceMessages` + `FlowerpotState.loadDeviceMessages`（结果也进联调日志）；
- 消息通知页底部挂调试板：打印每条消息的全部字段，**键名里带 `type` 的标成品牌色**，
  并按 `msgSrcId` 去已绑定设备里找归属、标出是不是目标产品 `ehbx83xdh9jkmxvz`；长按复制。

## 关键决策

1. **下发不经过涂鸦 SDK**。没有割草机设备，`publishDps` 发给一个不存在的 devId 只会报错。
   下发出口集中在 `MowerDevice._deliver`，接真机时改那一行即可，页面一行都不用动。
2. **模拟上报必须标出来**。只读 DP（盖子/故障/电量/充电）由**长按电量环**打开的面板改，
   日志里带「［模拟］」——否则日后有人对着日志判固件行为会判错。
3. **DP3 的枚举序按"枚举值列表 + V2.2 协议"取，不按 xlsx 的说明列**。
   ⚠️ 两份文档在这里对不上：xlsx 说明列写「1 random(弃用) / 2 smart / 3 spot / 4 goto_charge」，
   而同一行的枚举值列表是 `standby, smart, spot, goto_charge, …`（**序号即传输值**，没有 random），
   V2.2 也是 smart=1。说明列是 random 还没删那版留下的。**真机联调第一个验这条**，
   如果设备按说明列解，模式会整体错开一位。
4. **计划的初值取端上默认模板**。没有真机就没有 DP101 上报，真按空起，编辑/重叠/恢复默认
   全验不了。接真机后应改成空、等设备上报填。
5. **雨后延迟的滚轮收到 0-2 小时**：稿子画的是「03 时」，而 DP105 上限是 120 分钟——
   画得出来却发不下去的值不该让用户选。
6. **语言列表按 DP109 的 18 个枚举出，不是稿子上的「简中/English/繁中」**：设备面板没有中文，
   画三个设备不认的选项，用户选了也发不出去。简中/繁中手机落到 English。
7. **iOS 侧没有接 `deviceMessages`**：那边桥接是直接引 SDK 类型写的，本机没有 SDK 包也编译不了，
   猜类名会把 iOS 构建搞挂。Dart 侧捕获 `MissingPluginException` 并如实显示「iOS 待补」。

## 验证结果

⚠️ **本机（SSH 开发机）没有 Flutter 工具链**：未 `pub get`、未 `dart analyze`、未 `flutter test`、
未编译、未真机。实际做到的：

- 仓库自带四个 Dart 静态自检跑 `lib test`（326 个文件）全绿；
- 括号/引号配平脚本对全部新增与改动文件全绿；
- 逐文件核对导入与符号引用（写了个小脚本比对"用到的符号 ↔ 已 import 的文件"）。

新增/改写用例（**都没跑过**）：
- `test/features/mower/mower_dp_codec_test.dart`：DP101 组号映射（周日→组 7）、小端、
  <10 分钟丢弃、关掉的时段不下发、编解码往返、「全部设置」摊成 7 天、重叠判定、
  DP103 百分比 0 删区与距离钳位、DP3/DP107/DP109/DP18 的枚举与文案；
- `test/features/mower/mower_pages_test.dart`：停止态左三点不动、点过的模式置灰、
  停止再启动走记忆、盖子未合弹窗且不下发。

## 未完成项与风险

1. **DP3 枚举序**（见关键决策 3）——真机第一个验。
2. **一条 DP 都没真的发出去过**：整条链路止于日志，`publishDps` 没接。
3. DP111（故障明细 JSON）、DP116（OTA）、DP119（工作时间）没有界面，本轮未接。
4. 消息调试板的安卓实现是**按 7.x 公开命名探的**，本机没有 SDK 包可解包核对；
   真机跑一次就知道对不对（探不到时诊断里会列出该类实际有哪些方法）。
5. iOS 侧消息桥接未做。
6. 「自动设置」这个开关**没有对应 DPID**，是端上的；产品若要设备侧也记住，得加 DP。

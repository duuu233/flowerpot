# 水位校准：step0–step3 改成「卡片出现就下发」，第一步一打开就发 step0

> 文档类型：Historical Change Record
> 日期：2026-09-18
> 环境：SSH
> 分支与起始版本：`main` / `e8b21e4`
> 范围：`lib/src/features/devices/presentation/widgets/water_level_calibration_dialog.dart`、
> `lib/src/tuya/tuya_config.dart`、`lib/src/state.dart`、`test/features/devices/water_level_calibration_dialog_test.dart`
> 依据：产品 2026-09-18 口径「0–3 下发、取消下发 5、4 不管；**第一步就要下发 0**」

## 改了什么

**下发时机从「用户确认完这一步」挪到「这一步的卡片出现」。** 枚举值本身没变，
仍然是 step0 → step1 → step2 → step3、取消 step5、step4 任何路径都不发。

| 时刻 | 改之前 | 改之后 |
|---|---|---|
| 弹窗打开（卡片①倒空水仓） | **什么都不发** | **发 step0** |
| 卡片①点「下一步」 | 发 step0 | 发 step1 |
| 卡片②点「下一步」 | 发 step1 | 发 step2 |
| 卡片③点「下一步」 | 发 step2 | 发 step3 |
| 卡片④「校准完成」点「完成」 | 发 step3 后关闭 | **只关闭，不再下发** |
| 中途「取消」 | 发 step5 | 发 step5（不变） |
| 卡片④点「关闭」 | 发 step5 | **不发**（见下） |

两种口径**发出去的值完全一样**（0、1、2、3），差别只在**谁先谁后**：

- 旧口径是「用户做完了，我报告一声」——设备在用户倒水的**整个过程中都还没进这一阶段**；
- 新口径是「设备先就位，再让用户动手」——卡片上那句话本来就是
  「设备处在 stepN 时用户该做的事」。

所以「第一步就要下发 0」不是补一条，而是把整条链往前挪一格：卡片④出现时 step3 已经发完，
它的「完成」自然就没有东西可发了。

## ⚠️ 顺带改掉的一条：卡片④的「关闭」不再发 step5

旧代码里它发 step5 是**有道理的**——那时 step3 只有点「完成」才发，从「关闭」走等于没走完，
必须用 step5 把设备放出来（注释原话就是这个意思）。

**新口径下这个前提没了**：卡片④能出现就说明 step0–step3 已经发全，这时再补一条 step5
等于让固件把刚校准好的结果作废。所以现在：**半途退出才发 step5，卡片④两个按钮都只关闭。**

这条是口径改动的连带结果，不是用户单独交代的，🔶 **如果产品要的是「只要没点完成就算没完成」，
把 `_handleSecondaryAction` 里那个 `if (!_onSummaryStep)` 去掉即可。**

## 下发失败怎么办

- **开场那次 step0 被拒**：停在卡片①（设备根本没进校准模式，往下走全是白发），
  用 `_stepDelivered` 记住这件事；用户点「下一步」时**先补发 step0，成功了再发 step1**，
  一次点击补齐两条，不让用户点两下。
- **中途某一步被拒**：停在当前卡片，本卡的 step 已经生效、不会重发，再点只补发失败的那一条。
- 失败提示仍由页面那层的 `showDeviceActionResult` 弹，弹窗本身不额外加错误区。

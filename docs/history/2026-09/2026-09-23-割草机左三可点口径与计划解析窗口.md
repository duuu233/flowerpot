## 一、左三按钮

用户：「4，自动\定点\回归 判断 if DP3=当前下发的指令时则不可再次点击改为置灰」「if DP3 并不等于当前按钮状态 这几个按钮应该要正常可以点击啊」。

原来 `MowerDevice.commandsEnabled => switchGo`：DP2=false 时三颗全灰。设备待机时 DP2 也是 false，结果刚开机连「自动」都点不了，
而协议 §9.2 待机启动正是发 DP3=smart。改为 `status != MowerStatus.paused`：只有按过「停止」、设备报 DP5=paused 时三颗不可点；
其余时候只看 DP3 == 这颗（置灰）。用例拆成「待机能点自动」「暂停不能点、继续且设备回 mowing 后恢复」。

## 二、割草计划解析临时窗口

用户：「割草计划 你把数据解析出来 打印在日志上 我要对比一下 可以在页面下方搞个临时窗口」。

- `MowerScheduleCodec.describe`：逐组逐字段列出 88 字节（与 `decode` 不同，无效时段的起止也列），标形态（全部设置 / 按天 / 清空 / 组 0 与组 1~7 混发）、
  ≤10 分钟与起止不合法（设备会丢弃）。
- `MowerDevice.scheduleRaw / scheduleRawSource / scheduleRawAt`：记最近一次原始字节（设备上报或本机下发），同时逐行打进联调日志。
- 计划页底部深色临时窗口：来源 + 时间、hex、base64、解析行，「复制」按钮。**联调完删**。
- 用例：协议 §5.1 两个示例各一条。

## 1. 「设备关机了 App 还显示在线」——不是本轮改出来的，是一直缺主动刷新

先查了怀疑对象。本轮（`8256827` / `7ddcc2f`）对这条链路的改动**只有**给 `DeviceUpdate`
加了 `changedDps` 字段，`online` 的解析、`devListenerProxy`、Android 侧一行都没动
（`git diff e49c03b..HEAD -- lib/src/tuya/ android/` 可查）。

真正的链路是这样的：

```
设备掉线 → 涂鸦云按心跳超时判定 → MQTT 推给 SDK → SDK 更新 DeviceBean
        → IDevListener.onStatusChanged → devListenerProxy → {deviceId, online} → Dart
```

心跳这一段是有的，App 也确实挂在上面。问题出在**它会漏，而漏了就没人补**：

1. App 切到后台、或 MQTT 断开重连期间发生的状态变化**不会补发**。SDK 重连后只是把 bean
   更新到最新，不会再回放一次 `onStatusChanged`。
2. 改动之前 App **没有任何主动刷新**——设备清单只有下拉刷新会重拉，没有回前台刷新、
   没有轮询。所以只要漏掉那一次回调，页面就一直停在「在线」。

另外，云端判定本身就有延迟（心跳超时，通常几十秒到几分钟），这段是设备和云侧的事，
App 改不了；能改的是别再漏。

### 做法：心跳推送为主，前台轮询兜底

- **原生加 `deviceOnlineStates`**：按设备 id 读 `getDataInstance().getDeviceBean(id)` 的
  `getIsOnline`，**纯本地缓存，不发网络请求**。bean 是被 SDK 的 MQTT 维护的，所以它准。
- **`FlowerpotState` 前台每 8 秒对一次**（`onlinePollInterval`），和本地不一致就更正，
  并在联调日志框记一条 `心跳 ← <设备名> 变为离线`。
- **`_FlowerpotAppState` 挂 `WidgetsBindingObserver`**：回前台立刻对一次在线状态、再整体
  刷一次设备清单，并启动轮询；进后台停轮询（后台读缓存没意义，还费电）。
- 设备上报的日志行也带上在线标志，便于分辨是「回调来了」还是「轮询兜到的」。

## 3. OTA 两个弹框各归各位

产品口径（2026-09-12）：**「检查更新」要居中；「固件升级中」贴底、宽度铺满、其余区域盖
黑色半透明遮罩，像底部弹层。** 这推翻了 2026-09-11「两个一起贴底、都保持卡片形态」的口径，
两处注释都写明了沿革，免得下次又改回去。

- 「检查更新」(`showFirmwareUpdateDialog`)：去掉 `alignment: bottomCenter` 和自定义
  `insetPadding`，回到 Flutter 默认的居中。
- 「固件升级中」(`showOtaProgressDialog`)：`AlertDialog` → `Dialog`，
  `insetPadding: EdgeInsets.zero` + `alignment: bottomCenter` + `SizedBox(width: double.infinity)`
  做到满宽，只有顶部两角是圆的；`barrierColor` 显式给成黑色 42% 透明，和「检查更新」同浓度。
  底边在系统手势区之上再留 20。
  - **没用 `showModalBottomSheet`**：进度层要跑完才允许关（`PopScope`），bottom sheet 的
    下拉关闭那套还得一个个关掉，用 dialog 更直接。
  - 关闭按钮从 `AlertDialog.actions` 挪进正文列，跑完才出现。

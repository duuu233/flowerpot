## 2. 设备在线门禁（本轮新需求）

产品口径：**设备列表页、设备详情页能点进去的相关页面，以及下发 DP 指令时，都要先判断设备
是否在线；不在线提示「设备已离线」并跳回设备列表页。**

- 判断只有一处：`FlowerpotState.isDeviceOnline(id)`（`deviceById(id)?.online ?? false`）。
- 下发那一路在 `_publishDps` 里拦：设备**认识且确实离线**时记一条 `下发被拦 ✗ 设备已离线`
  并抛 `TuyaException('device_offline', '设备已离线')`。只拦「认识且离线」的——刚配网完还
  没进列表的设备 `deviceById` 查不到，那种情况照常发，否则会把配网收尾的写操作一起拦掉。
- 页面侧统一入口 `lib/src/features/devices/presentation/device_online_guard.dart`：
  - `ensureDeviceOnline(context, deviceId)`：不在线就提示 + 退回列表页，返回 false。
  - `showDeviceActionResult(context, result, announceSuccess:)`：失败提示；`code` 是
    `device_offline` 时再退回列表页。19 处原本手写 `showAppMessage(context, result.message, …)`
    的地方统一换成它，所以**页面漏加门禁时指令也发不出去、提示也不会漏**。
  - 退回列表页用的是 `popUntil((route) => route.isFirst)`：列表页就是 shell 的首页
    （`AppShell` 在有设备时画的就是 `DeviceListPage`），不另外 push 一个 `/devices/list`，
    免得栈里出现两个列表。
- 入口门禁加在：`HomePage._openDevice` / `_openAddPlant`、`DeviceSettingsPage._openMenu`
  （帮助中心除外，它和设备无关）/ `_showMore`、`DeviceListPage._openDevice`（本来就在列表页，
  只提示不跳转，文案从「请打开设备并保持在线」统一成「设备已离线」）。

## 3. 联调日志从「逐页插面板」改成全局浮层

上一轮只有设备详情页底部有日志框，产品要求「交互多、比较复杂的页面也要加」「只要内容多的
就都需要」。逐页往 `children` 里插面板试过一轮：**十个候选页里三个结构对不上**
（`display_settings_page`、`hearing_settings_page`、`touch_settings_page` 找不到列表收尾），
还容易插进嵌套列表里，而且每新增一个页面都要再补一次。

改成 `lib/src/app/interaction_log_overlay.dart`：

- `InteractionLogOverlay` 挂在 `MaterialApp.builder` 上，一处改动覆盖所有页面，不动任何页面
  布局。默认是左下角一颗小药丸（`联调日志 N`），点开才展开面板。未登录时不挂。
- `Stack` 用 `fit: StackFit.expand`——Navigator 是唯一的非定位子件，默认 loose 会让它自己
  取尺寸，整个 App 会塌。
- `HomePage` 里原来内联的那个面板删掉，避免一页两个。
- `InteractionLogPanel` 加了可选 `onClose`：浮层传进去时「收起」关掉整个浮层。

## 4. 进页面就记「读到的 DPID 和值」

产品原话：「例如设置页面，刚进来的时候就要读取功能设置对应的 DPID 是什么、接收到的值是什么」。

- `FlowerpotState.logSettingsSnapshot(deviceId, page, keys)`：一行里摆齐四样——App 设置键 →
  涂鸦标识符 → DP 号 → 页面此刻用的值，例如
  `读取 ← [震动设置] DP122 vibration_switch=true，DP123 touch_vib_switch=true`。
  作息那两项各占一头一尾两条 DP，合并成 `DP126+DP127 nap_start_time/nap_end_time=12:30-13:30`。
- 触发点是 `InteractionLogRouteObserver`（同文件），挂在 `MaterialApp.navigatorObservers`：
  `didPush` / `didPop` 时按路由名查表。**路由表在一处就全了，新增页面只加一行映射**，不用
  每个页面自己调。`didPush` 发生在一帧当中，直接 `notifyListeners` 会撞上
  「build 期间 markNeedsBuild」，所以推到 `addPostFrameCallback` 再记。
- ⚠️ 记的是**页面当前取到的值**：设备还没上报过这条 DP 时它就是 App 的默认值。要区分
  「设备报的」和「App 默认的」，得等固件把全量 DP 报上来。

## 5. 帮助中心：后台富文本按标签渲染

现象：标题正常，正文把 `<p>` 这类标签当文案显示了。后台（flowerpot-web）的常见问题用的是
**wangEditor v5**（`src/components/RichEditor/index.vue`，全站只有 FAQ 这一个页面用富文本），
存进库里的是 HTML 片段，App 这边直接 `Text(item.answer)`。

新增 `lib/src/design_system/widgets/data_display/app_rich_html{,_parser}.dart`：

- **不引第三方 HTML 渲染库**。wangEditor v5 的输出标签集合是固定且很小的一撮，自己解析既能
  跟着设计系统的字体色走，也不用为了一个帮助中心把一串传递依赖装进包里。
- 覆盖：段落与标题、加粗/斜体/下划线/删除线、行内 `style` 的颜色（`#rgb` / `#rrggbb` /
  `#rrggbbaa` / `rgb()` / `rgba()` / 具名色）与字号（px/pt/em/rem/%）、`text-align`、有序和
  无序列表（含嵌套、`start`）、引用、分割线、链接、图片、`<pre><code>`、表格行、HTML 实体。
  认不出的标签当透明容器（丢标签、留内容），**永远不会把尖括号原样显示给用户**。
- 链接只上色不跳转：App 没有引入 url_launcher，不假装能开外链（`onLinkTap` 留了口子）。
- 顺手落实「不要用静态数据兜底」：删掉 `HelpCenterPageModel.figma` 里内置的 6 条问答，
  后台没配或接口不通时页面就是空态（`AppEmptyState`），不再显示几条对不上版本的假问答。

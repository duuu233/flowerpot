# 恢复出厂设置：先下发 DP 141，下发成功才解绑

> 文档类型：Historical Change Record
> 日期：2026-09-21
> 环境：SSH（本机无 Flutter / Dart / Kotlin 工具链）
> 分支与起始版本：main / `4fd75a5`
> 范围：`lib/src/state.dart`、`device_other_settings_page.dart`、`test/`
> 当前权威文档：`docs/PRODUCT_RULES.md` §4.7

## 背景与目标

产品原话：「恢复出厂设置功能需要先下发恢复出厂 dp 再执行解除设备逻辑」。

改之前的实现名义上已经是「先 141、再解绑」，但有两处与这句要求不符：

1. 141 发不出去（设备离线、下发失败）时**静默吞掉、照样解绑**，页面还提示「设备已解绑并清除数据」
   ——设备上的数据其实没清；
2. 恢复出厂、重新配网共用 `removeDevice(resetFactory: true)` 这一条，没法分别处理。

## 与产品确认的两点

- **解绑用哪个 SDK 调用**：涂鸦 `removeDevice`（「解除绑定」，云端数据保留）与 `resetFactory`（「解除绑定并清除
  数据」）都会解绑、让设备回到配网状态，区别只在云端这台设备的数据（消息中心、云端日志、定时 / 场景）清不清；
  两者都不清设备本身的数据（那只能靠 141）。产品定：**用 `resetFactory`**。
- **141 发不出去时**：产品定**停下、不解绑**。「重新配网」保持现状（设备离线正是它的常见场景）。

## 变更内容

1. `FlowerpotState.factoryResetDevice(id)`（新）：`_publishFactoryReset(id, strict: true)` → `_unbindDevice(id, resetFactory: true)`。
2. `_publishFactoryReset` 加 `strict`：strict 时离线原样抛 `device_offline`（页面按统一口径提示「设备已离线」并回
   设备列表），其它下发失败抛原始码 +「恢复出厂指令下发失败，设备未解绑：…」；功能点缺失也抛错。非 strict 行为不变。
3. 解绑本身抽成 `_unbindDevice`（涂鸦解绑 → 删后台记录 → 清本地），`removeDevice` 与 `factoryResetDevice` 共用。
4. 其他设置页：「恢复出厂设置」改调 `factoryResetDevice`，并在弹确认框**之前**先过 `ensureDeviceOnline`
   （离线不让用户确认一件做不成的事；与 09-12「任何下发 DP 的动作都要先判在线」同口径）。
   「重新配网」仍调 `removeDevice(resetFactory: true)`，「移除设备」仍调 `removeDevice(resetFactory: false)`。
5. 文档：`PRODUCT_RULES.md` 新增 §4.7；`TUYA_SDK_SETUP.md`（141/150 那条）、`PRD_IMPLEMENTATION.md`、
   `AI_CONTEXT.md` 同步。
6. 用例：新增 `test/state_factory_reset_test.dart`（5 条：顺序 141 → `resetFactory`；141 下发失败不解绑；离线不发
   不解绑；重新配网离线照样解绑；移除设备不发 141）；`device_other_settings_page_test.dart` 新增 2 条（点按钮确认后
   调用顺序；离线不弹确认框、不下发不解绑），测试仓库加了调用记录与在线开关。

## 关键决策

- 恢复出厂与重新配网分开两个入口，而不是给 `removeDevice` 再加一个布尔参数：两者对「141 发不出去」的处理
  正好相反，分开命名调用方一眼能看出走的是哪套规则。
- **没有在 141 与解绑之间加等待**：下发成功只代表涂鸦接收了指令，设备能否在紧接着的解绑（模组会被重置）之前
  处理完 141 没有证据，也没有设备回执可等（160 `op_result` 没约定恢复出厂的回执）。不凭空加延时，留给真机验。

# 升级进度到 98% 起显示「固件安装中」+ 准备中那套动效

> 文档类型：Historical Change Record
> 日期：2026-09-17
> 环境：SSH 开发机（Project Hub 分发）
> 分支与起始版本：main / e817468
> 范围：`lib/src/tuya/tuya_models.dart`、`lib/src/features/devices/presentation/widgets/ota_progress_dialog.dart`、`test/`、`docs/`
> 当前权威文档：`docs/PRODUCT_RULES.md` §4.2.1、`AI_CONTEXT.md`

## 背景与目标

产品：OTA 升级的进度走到 **98%** 之后，涂鸦要停一大段时间等设备把固件写完、重启，界面停在
「固件升级中 98%」看着像卡死了。要求到 98% 就换成**最开始「固件准备中」那套来回走的动效**、
文案改成「**固件安装中**」；等涂鸦通知完成，仍按原流程走「升级完成」。

09-15 那版已经有「固件安装中 + 不定进度动效」这一档，只是入口条件是**进度到 100% 或涂鸦报码 6**。
所以本轮不是新做一个形态，而是**把这一档的门槛从 100 降到 98**。

## 变更内容

- `OtaProgress` 新增 `static const installingPercent = 98`，`displayStage` 里
  `if (value >= 100)` 改成 `if (value >= installingPercent)`。**只有这一处逻辑改动**：
  - 弹层的动效和「不写数字」本来就是按 `displayStage != upgrading` 走的（`indeterminate`），
    所以 98 一到自动换成与「固件准备中」同一套 `LinearProgressIndicator(value: null)`；
  - 标题与「其他设置」功能行共用的 `otaRunningLabel` 在 installing 档本来就返回「固件安装中」，
    且不带百分比；
  - 成功 / 失败的收尾（升级完成 / 升级失败、满格 / 停在最后百分比、「知道了」）一行没动。
- `ota_progress_dialog.dart` 补了两段注释说明 98 这个口径的由来。
- 测试：
  - `test/state_ota_test.dart` 的档位表改成 97 → 升级中、98 / 99 / 100 → 安装中。
  - `test/features/devices/device_other_settings_page_test.dart` 的升级流程用例中间插一步 98%，
    断言标题是「固件安装中」、百分比那行是空串、进度条 `value == null`（不定进度）。

### 顺手修掉的一处红断言

同一个用例里 09-15 写的 `expect(find.text('固件准备中'), findsOneWidget)` **本轮之前就是红的**：
「固件准备中」这句弹层标题和它后面「其他设置」页那行功能行的 value 是同一个字符串
（两处共用 `otaRunningLabel`，准备中 / 安装中都不带百分比），`find.text` 会数到两个。
改成按 key 取弹层标题 `Text` 再比 `.data`，新加的 98% 那段也照这个写法——
升级中那两条不受影响（功能行是「固件升级中 42%」，和标题「固件升级中」不是同一个字符串）。

## 关键决策

- **只动阈值，不新增状态。** 产品说的「换成最开始那个动效 + 文字叫固件安装中」正好就是已有的
  installing 档，再加一个状态只会让四段变五段、文案表和测试跟着分叉。
- **98 写成常量而不是散在判断里**：`OtaProgress.installingPercent`。产品要调（比如改 95）只改一处，
  测试和文档都指向它。
- **涂鸦码 6（固件已下载到设备）的优先级不变**：设备真报了 6 就直接安装中，与百分比无关。

## 验证

- ✅ 四个 Dart 静态自检脚本全绿（300 个文件）。
- ⚠️ **本机没有 Flutter / Dart 工具链**：未 `flutter pub get`（`pubspec.lock` 仍未更新）、
  未 analyze、未跑 flutter test（含本轮新增的 98% 断言）、未编译、未真机。

## 未完成项与风险

- **真机要看的是 98 那一下的观感**：进度条从 97% 的实心进度切成来回走的动画，是不是像「倒回去了」。
  产品要的就是这个效果，但真机上看一眼更保险。
- 如果某些设备根本不报 98、直接从 9x 跳到成功，这段动效就一闪而过或不出现——属于正常。
- 阈值定在 98 是产品给的经验值，不是从涂鸦文档推出来的；换一批固件后可能要再调。

## 回滚或恢复

把 `OtaProgress.installingPercent` 改回 100 即可完全恢复 09-15 的行为；测试里 97 / 98 / 99 三条
断言跟着改回 99 → 升级中。

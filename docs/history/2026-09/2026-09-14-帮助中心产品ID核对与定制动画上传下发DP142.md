# 帮助中心产品 ID 核对；定制动画上传补下发 DP 142；上传区去掉「或拖拽」

> 文档类型：Historical Change Record
> 日期：2026-09-14
> 环境：SSH（本机无 Flutter / Dart 工具链）
> 分支与起始版本：main / `a30a418`
> 范围：`lib/src/state.dart`、`lib/src/core/backend/`、`lib/src/tuya/tuya_gallery_codec.dart`、定制动画页、`test/`
> 当前权威文档：`docs/PRODUCT_RULES.md` §4.3；`AI_CONTEXT.md`「内容与维护」

## 背景与目标

产品三条：

1. 帮助中心接口要传产品 ID，检查是不是；
2. 定制动画上传图片后有没有下发指令、有没有接 DPID——联调日志里看不到；
3. 上传区「点击或拖拽文件到这里上传」去掉「或拖拽」，手机端没有这个功能。

## 核对结论

### 1. 帮助中心：**已经在传**，只是联调日志里看不到

- 线上 swagger（`https://api.yikaltd.com/v2/api-docs`，2026-09-14 拉取）：
  `GET /Client/Product/getProductFaqList` 的参数只有 `pageIndex / pageSize / keyword /
  startDate / endDate / broadcastId`，`broadcastId` 说明为「平台设备id」；后台产品表
  `ProductAddApiIn.broadcastId` 同为「平台设备id」（管理端界面文案「涂鸦产品ID」）。
  客户端这条**没有**整数 `productId` 参数，产品筛选只能走 `broadcastId`。
- App（`HttpAppBackendRepository.getFaqs`）一直带 `broadcastId`，值来自
  `FlowerpotState.faqBroadcastId`：当前设备 `productId`（Android `DeviceBean.getProductId`，
  即涂鸦平台产品 ID）→ 任一已绑定设备 → `TuyaConfig.productId`（`yciq4kssu1fv8umn`）。
  不是 BLE 广播 ID `ehbx83xdh9jkmxvz`。
- 看不到的原因：`ApiClient` 的请求日志只 `debugPrint`（且仅 debug 构建），不进 App 内的联调日志浮层。
- 线上数据未核：该接口要登录 token（匿名调用回 `406 请重新登录`），本轮没有用任何账号登录，
  **后台里本产品的 FAQ 是否真的配了这个 broadcastId，没有验证**。

### 2. 定制动画上传：**确实没有下发**

`FlowerpotState.addAnimation` 在有后端时只做了 `uploadImage` + 刷新列表，返回「图片已上传」，
没有任何 DP。09-12 的历史记录里写着「定制动画下发（142/143/144）仍未实现，等设备方给协议与
长度上限」；而 `docs/智能花盆test(yciq4kssu1fv8umn)_09_12.xlsx` 已给出：

| DP | 标识符 | 类型 | 格式 |
| --- | --- | --- | --- |
| 142 | `dl_url` 下载图片 | raw，只下发 | `url_len(1B)+url+name_len(1B)+name` |
| 143 | `dl_show` 显示图片 | string，只下发 | 示例 `flower_red` |
| 144 | `dl_cancel` 取消显示 | bool，只下发 | — |

删除（155 `del_photo`）、全删（156）、置顶（157 `pin_photo`）此前已在下发。

## 变更内容

1. 新增 `TuyaGalleryCodec.downloadFrame`：按上表拼 142 帧；URL UTF-8、文件名 ASCII，任一段为空
   或超过 255 字节直接报错，不截断。
2. `AppBackendRepository.uploadImage` 返回图片 URL（swagger `BaseUploadApiOut{name,url}`，
   复用 `_uploadedUrl` 解析）。
3. `addAnimation`：上传 → 刷新列表 → 取 URL（接口没回时退到列表里新增的那张）→ 联调日志记
   `定制动画 DP142 dl_url：name=… url=…` → 经 `_publishRawDp`（十六进制）下发 142。拿不到 URL 时
   记日志并报「图片已上传，但接口没有返回图片地址，未能通知设备下载」。成功提示改为「图片已上传，
   已通知设备下载」。
4. 新增 `BackendImage.fileNameOf(url)`，列表解析（→ 155/157 用的 `name`）与 142 帧里的 name 同一取法。
5. `loadFaqs` 在联调日志记 `帮助中心 ← getProductFaqList broadcastId=…（涂鸦产品ID，取自…），返回 N 条`，
   失败记 ✗ 行。
6. 上传区文案「点击或拖拽文件到这里上传」→「点击文件到这里上传」（按产品原话只删「或拖拽」）。
7. 测试：新增 `test/tuya/tuya_gallery_codec_test.dart`；`state_backend_integration_test` 的图库用例改用
   记录型涂鸦仓库，断言上传后紧跟 `tuya:142=<帧>`、日志有明文行；两个测试后端的 `uploadImage` 同步返回 URL。

## 关键决策

- **上传后不自动发 143 `dl_show`**：产品只问了「上传有没有下发」；143 会改变设备当前显示的内容，
  取值（示例 `flower_red`）是否就是文件名也未确认。143 / 144 暂无入口。
- 142 下发失败（离线等）时图片已经在后端，不回滚上传；提示按 `_guard` 的失败原因给出。

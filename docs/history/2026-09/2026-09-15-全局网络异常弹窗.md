## 背景与目标

产品：全局加一个手机没有网络时的弹窗提示。

- 标题：网络异常
- 内容：当前网络不可用，请检查网络后重试
- 按钮：取消、重试
- 事件：点击重试（重新执行刷新当前页面，重新加载数据）

## 方案取舍

- **怎么知道「没网」**：常见做法是 `connectivity_plus` 常驻监听，但加依赖要改 `pubspec.lock`，本机跑不了 `flutter pub get`，锁文件对不上；走原生桥接（`ConnectivityManager` / `NWPathMonitor`）又是 Kotlin + Swift 两份无法编译的代码。
  改为纯 Dart 的「按需探测」：`NetworkStatus.probe` 解析一次 APP 后端域名（3 秒超时），解析不了就是没网。飞行模式、Wi-Fi / 蜂窝都关、连着没有外网的 Wi-Fi 都会失败。
  这不是涂鸦 SDK 提供的能力（手机网络状态），不涉及「能用 SDK 就用 SDK」那条。
- **什么时候探测**：闪屏结束（冷启动）、回前台 2 秒后（让刚在系统设置里打开的 Wi-Fi 先连上）、以及任何一次请求因网络失败之后——`ApiClient` 在重试用尽、抛 `NETWORK_UNREACHABLE` / `NETWORK_TIMEOUT` 前上报；涂鸦的失败码分不出是不是网络问题，`FlowerpotState._run` 收到 `TuyaException` 一律上报，由探测来判断（设备离线这类失败查出来网是通的，什么都不发生）。
  代价：用户停在一个不发请求的页面上关掉网络，要等下一次请求 / 回前台才弹。用户真正受影响的时刻正是「要拉数据却拉不到」。
- **「重试」刷新哪一页**：页面没有统一的「刷新」入口，各自在 `initState` / `didChangeDependencies` 里拉数据。新增 mixin `NetworkRetryAware`，页面实现 `reloadForNetworkRetry()`；根 Navigator 上挂 `NetworkRouteTracker` 记路由栈，重试时只调**最上面那一页**登记的方法。没登记的页面（各状态页、设置子页等，数据都在设备快照里）重读一次设备列表。
  没有用「重建当前页」这种一刀切的办法：会丢掉页面里正在输入的内容，还会触发 `dispose` 的副作用（例如校准页关闭时发 `step5`）。

## 变更内容

- `core/network/network_status.dart`：`NetworkStatus.probe`（可替换）、`failures` 流、`reportFailure()`。
- `ApiClient`：三处网络失败与上传的两处网络失败在抛出前 `reportFailure()`。
- `FlowerpotState._run`：`TuyaException` 分支 `reportFailure()`。
- `app/network_alert.dart`：
  - `NetworkRouteTracker`：当前页、是否盖着弹框。
  - `NetworkAlertHost`：探测 → 弹窗 → 重试循环。不弹：配网四个路由（`deviceSearch` / `pairing` / `pairingFailure` / `pairingSuccess`，PRODUCT_RULES §1.6）；盖着别的弹框或进度圈时先记下、关掉后再查（直接盖上去的话 `withBlockingProgress` 收尾 pop 掉的会是网络弹窗）；点「取消」后 3 秒内（同一次操作并发的几条请求会陆续失败）。重试时进度圈至少转 600ms 再探测，否则断网下弹窗关掉又原样弹出，看着像按钮没反应。
  - `NetworkRetryAware`：页面登记。
- `FlowerpotApp`：`navigatorObservers` 加 tracker，`builder` 里包一层 `NetworkAlertHost`（`enabled: !_showSplash`）。
- `AppL10n`：`cancel`、`retry`、`networkErrorTitle`、`networkErrorMessage`（中英）。
- 登记 `reloadForNetworkRetry` 的页面及重试内容：
  | 页面 | 重试时 |
  | --- | --- |
  | 首页 `HomePage` | `reloadDevices` → 进页面检查（植物资料 / 引导窗） |
  | 我的 `MinePage` | `refreshUserInfo` + `loadBasicData` |
  | 个人信息 `ProfilePage` | `refreshUserInfo` |
  | 关于 `AboutPage` | `checkAppVersion` |
  | 协议 / 隐私 `LegalPage` | `loadBasicData` |
  | 帮助中心 `HelpPage` | 回加载态重拉常见问题 |
  | 定制动画 `AnimationsPage` | `refreshAnimations` |
  | 纪念日 `MemorialPage` | `refreshMemorials` |
  | 选择植物 `PlantPickerPage` | 回加载态重拉植物目录 |
  | 植物详情 `PlantDetailPage` | 重拉详情（加载逻辑抽成 `_loadDetail`，进页面与重试共用） |
  | 报表 `ReportsPage` | `reloadDevices` → 重算历史 |
  | 设置 / 其他设置 | `reloadDevices` → `refreshFirmwareUpdate` |
- 测试：`test/app/network_alert_test.dart`（冷启动没网弹 / 有网不弹、取消后冷却、没网重试再弹、恢复后只刷新最上面那页、配网页不弹、等别的弹框关掉再弹）；`flutter_test_config.dart` 把探测固定为有网，其余用例不受影响。
- 文档：PRODUCT_RULES §4、AI_CONTEXT §5。

## 验证结果

- 四个 Dart 自检脚本（lib 293 个文件、test 76 个文件）：OK。
- 人工核对了编译器会抓的点：`setState` 回调不返回 Future（报表页）、可空 Future 不直接 await、mixin 的 `didChangeDependencies` / `dispose` 都调 super、各页已有的 `didChangeDependencies` 都有「只跑一次」的保护（mixin 取 `ModalRoute.of` 会多几次依赖变化）。
- ⚠️ 未跑 `flutter analyze` / `flutter test`，未真机（本机无工具链）。

## 未完成项与风险

- 真机要验：飞行模式冷启动、使用中关 Wi-Fi 后下拉刷新、去系统设置开网回来（2 秒延迟够不够）、AP 配网全程确实不弹。
- 探测只解析 APP 后端域名：若只是这个域名的 DNS 出问题而手机本身有网，也会提示「网络不可用」（此时后端接口本来也不通）。
- 页面自己的失败 toast（如「网络连接失败，请稍后重试」）照旧会出，和弹窗同时出现；产品若觉得重复再收。

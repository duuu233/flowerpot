# 四个状态页的日期能无限往前翻；而且曲线不跟着日期换

> 文档类型：Historical Change Record
> 日期：2026-09-17
> 环境：SSH
> 分支与起始版本：`main` / `e557046`
> 范围：`lib/src/features/devices/presentation/*_status_page.dart`、`lib/src/state.dart`、新增 `features/devices/models/history_period.dart`
> 当前权威文档：[`../../PRODUCT_RULES.md`](../../PRODUCT_RULES.md) §4.5、[`../../../AI_CONTEXT.md`](../../../AI_CONTEXT.md)

## 背景与目标

用户实测报 BUG：**「前面说的日期时间 7 天限制有 BUG，历史数据日期可以无限调。」**

同日上一轮（`e557046`）按需求「app 左右切换日期限制 7 天」做了限制，但**做错了位置**：
我在**报表页**（`reports_page.dart`）新加了一条日期切换条并在那里限制了 7 天，而
**用户日常点的那条日期切换条在四个状态页顶部**（需水 / 光照 / 空气温度 / 相对湿度，
共用 `DateRangeNavigator`）。那四处一行没改，于是：

1. `onPrevious: () => setState(() => periodOffset--)` —— **裸的自减，没有下限**，
   一直点能翻到去年。设备根本没有那些天的数据。往后翻本来就有界（`periodOffset < 0`），
   坏的一直只有往前这一侧。
2. 更要紧的一条：`chartSeries(deviceId, metric, range)` **压根不接受日期，也不看
   `periodOffset`**。所以那条日期条一直只是**标签在动，曲线不动**——翻到 9 月 10 日，
   画的还是今天那条。这是上一轮需求「app 根据日期从 DP 解析对应的值进行渲染」在状态页
   一侧完全没落地。

## 变更内容

### 新增 `lib/src/features/devices/models/history_period.dart`

窗口规则**一处定义、五处共用**（四个状态页 + 报表页），页面不许自己算天数——
这个 BUG 之所以在四个文件里同时存在，就是因为每页各写了一遍。

- `maxBack(range)`：**日 6**（当天 + 往前 6 天 = `TuyaHistoryCodec.maxDailyWindow`）、
  **周 0 / 月 0**（设备的周包 / 月包只有当期那一份，132/133、135/136、138/139 各一条 DP
  就是一整期，滚动覆盖，往前没有第二份可取）。
- `canGoBack(range, offset)` / `canGoForward(offset)`。
- `dayFor(offset)`：offset → 那一天（只到日）。用 `DateTime` 构造函数进位，
  **不用** `add(Duration(days:))`——夏令时那天加 24 小时会落到前一天 23 点。

### `lib/src/state.dart`

- `chartSeries` 加可选命名参数 `date`。日视图且不是今天时取 `DeviceHistory.daySeries(metric, date)`。
- **过去那几天不接实时推送点**：实时值是「现在」的读数，接在历史某天曲线后面就是假曲线
  （昨天的图右端冒出今天的读数）。实时只属于今天。
- 缓存 key 带上日期（`MM-DD`），否则翻了一天还命中前一天那条缓存。
- 新增静态 `_daysAgoOf(date)`。

### 四个状态页

- `onPrevious` / `onNext` 改走 `HistoryPeriod.canGoBack/canGoForward`；
  水位、光照两页按当前 `range` 判（日 6 / 周 0 / 月 0），温度、湿度只有日视图。
- `chartSeries(..., date: HistoryPeriod.dayFor(periodOffset))`，曲线跟着日期换。
- `_dateLabel()` 的日期改由 `HistoryPeriod.dayFor` 算（顺带修掉
  `DateTime.now().add(Duration(days: ...))` 这个夏令时写法）。

### `reports_page.dart`

- 原来内联的 `daysAgo < TuyaHistoryCodec.maxDailyWindow - 1` 改走 `HistoryPeriod`，
  窗口规则收敛到一处（它记的是日期，换算成 `offset = -daysAgo`）。

## 关键决策

- **窗口规则抽成 `HistoryPeriod` 而不是在四个页面各补一句 if。** 这个 BUG 的形状本身就是
  「同一条规则在四处各写一遍、其中四处都漏了下限」。抽出来之后再加第五处控件也不会漏。
- **周 / 月定为「一格都不给往前翻」。** 依据是设备侧只有当期一包，往前取不到数据；
  ⚠️ 这一条是按数据能力推的，**产品没有明确口径**，见下面「未完成项」。
- **过去某天不接实时点。** 否则曲线右端会混进「现在」的读数。
- **空态文案没动。** 翻到设备没报过的那天，四个状态页仍显示各自那句「暂无 XX 历史」。
  报表页有三段式文案（没有历史 DP / 缺这一天 / 从没到过），状态页只有一句固定标题，
  改文案要产品给词，没有自己编。

## 验证结果

⚠️ **未编译、未跑测试、未真机**——本机与内网 nas 都没有 Flutter/Dart 工具链
（见 `更新说明-2026-09-17-第二轮.md` 的同一条说明）。实际做到的：

- 逐段人工复核 + 全部改动文件的括号 / 花括号配平检查（忽略字符串与注释），全部为 0。
- 全仓 `grep` 确认：`chartSeries` 的调用点只有这四个状态页（首页不调）；
  `periodOffset` 的裸自减已无残留；日期切换 UI 全仓只有 `DateRangeNavigator`（四个状态页）
  和报表页的 `_DayPicker` 两处。
- 新增 `test/features/devices/status_history_date_window_test.dart`（**未运行**）：
  - `HistoryPeriod` 四条单测（日窗口 6、周 / 月 为 0、往后翻的边界、offset→日期差天数）；
  - 相对湿度页的 widget 测试：连点 6 次「‹」后按钮禁用、**再点标签不变**（这条就是用户报的
    那个 BUG）、一路点回今天后「›」禁用；
  - 另一条 widget 测试：翻到昨天时图卡消失、显示「暂无湿度历史」——**证明曲线跟着日期换了**
    （演示仓库的设备只有「最新那天」一包；修之前这里画的还是今天那条）。
- 现有测试无一处触碰 `DateRangeNavigator` / `periodOffset`（已 grep），回归面很小。
  `battery_status_page_test` 只断言它**不存在**，不受影响。

## 未完成项与风险

- **周 / 月「不给往前翻」需要产品确认。** 现在两个箭头在周 / 月视图下恒为禁用态，
  看着可能像坏了。另一种做法是**周 / 月干脆不画这条日期条**。等产品一句话。
- 翻到无数据那天的**空态文案**仍是「暂无 XX 历史」，没区分「设备那天没报」。要改需产品给词。
- 真机上要看的两处：① 四个状态页点到 6 天前箭头变灰、再点不动；
  ② 翻日期时曲线确实换了（设备固件要能一次上报 7 天，否则过去几天都是空态——
  这本身是对的）。
- 7 天帧的字节布局仍是推断，核对方式见 `更新说明-2026-09-17-第二轮.md`。

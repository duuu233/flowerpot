# 割草机：蓝牙 / Wi-Fi 图标按通道亮 + 控制前蓝牙检查

> 文档类型：Historical Change Record
> 日期：2026-09-23
> 环境：SSH 开发机
> 分支与起始版本：main / 14fe25a

## 需求（产品原话，先暂缓后确认「按这个改」）

设备详情页：1）蓝牙和 Wi-Fi 图标单独读取涂鸦的数据显示（同时连接就同时亮）；2~5）自动、定点、暂停、回归点击后：
检测蓝牙是否连接，没连就连，连不上提示「无法连接设备蓝牙，请检查设备或靠近设备10米内」【我知道了】；连着再判断信号（阈值先 -50，后改 -80），
不满足提示「因安全要求必须在10米内控制设备」【我知道了】；不满足不下发。追加：「我进来设备正常情况下 wifi 和蓝牙图标应该都是亮的」。

## SDK（7.5.1 解包核对，只用涂鸦 SDK）

`ThingHomeSdk.getBleManager()` → `IThingBleManager`：`isBleLocalOnline(devId)`、`connectBleDevice(List<BleConnectBuilder>)`、
`registerDeviceConnectStatus(devId, BleConnectStatusListener)`（`STATE_CONNECT_SUCCESS` 运行时反射取值）、`readBleRssi(devId, BleRssiListener.onResult(boolean,int))`、
`readRssiByCache(devId)`；`DeviceBean.getCommunicationOnline(CommunicationEnum.BLE|MQTT|LAN)`、`isCloudOnline()`。

## 改动

- 原生：`deviceLinkState`（各分量原样回）、`bleConnectDevice`（发起 + 状态回调 + 每 500ms 看 `isBleLocalOnline`，默认 15 秒超时）、`bleReadRssi`（5 秒没回退缓存值）；后两个加进蓝牙权限名单。
- Dart：仓库 / Mock / 状态层三件套；`MowerDevice.bleLinked / wifiLinked / refreshLink(autoConnect)`，bind 时自动连一次，节流 30 秒；`minBleRssi = -80`。
- 首页：状态卡两个图标按状态亮 / 压淡；每 3 秒刷新；四颗按钮统一 `_guarded` → `_bleReady`（连接 → 信号），检查中不重入；每步进联调日志。
- 用例：进来都亮；连不上提示不下发；-85 拦、-70 放行。

## 口径说明

「信号若大于 -50」字面与意图相反（RSSI 越大越近），按「弱于阈值才拦」实现；阈值同日改为 -80，一个常量。

## 验证

⚠️ 本机无 Flutter 工具链：未编译、未跑用例、未真机；四个 Dart 静态自检 + `kt_dangling_refs` + 括号配平通过，并逐项人工核对 import / 可空泛型 / Kotlin 非局部 return。
真机要看：进页面日志「蓝牙 ✓ 已连上」「图标 ← 蓝牙亮、Wi-Fi亮（分量…）」；点按钮「控制前检查 ✓ 蓝牙已连接，信号 X dBm」。

## 同日追改：蓝牙连不上排查、按钮转圈、去掉设置页问号

- 真机「蓝牙无法连接」：`connectBleDevice` 补带设备 uuid、连接级别 `FORCE`；诊断里加设备 uuid / mac / hasBle / singleBle / BLE 通道 / `getBleConnectAbility` 原值，
  连不上时整行进联调日志。⚠️ 协议 V2.3 §10「蓝牙本地控制：预留（模组固件升级后启用）」——若 `connectAbility` 或 hasBle 显示设备不支持，是固件侧没开。
- 连接中的 loading 从全屏遮罩改为被点那颗按钮换成转圈；检查只返回失败原因，按钮恢复后再弹提示。
- 设置页右上角问号去掉。

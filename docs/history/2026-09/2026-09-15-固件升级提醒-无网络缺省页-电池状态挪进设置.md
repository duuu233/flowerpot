## 背景与目标

产品一次提了五条，中途补充两条：

1. 固件升级看看涂鸦有没有状态返回，能不能给「固件下载 / 固件传输 / 固件安装」几个状态，有就做、没有就不做。
2. 手机没网时不能进「添加设备」页，改为进默认的列表页：文案「当前网络不可用，请检查网络后重试」+ 重试按钮；全局弹窗保留。
3. 电量状态挪到设置里（同步设置页图标样式），删除电量历史记录报表，调整电池状态的图标（同光照、湿度那个问题）。
4. 「充电中」下方的描述固定两行高度，否则会跳。
5. 固件升级按涂鸦返回的升级提醒类型走不同交互：提醒升级（取消 / 立刻更新）、强制升级（只有立刻更新、不能取消）、检测升级（保持红点）；立刻更新跳到其他设置并执行固件升级；设备页全监控，「我的」页不监控。
   - 补充：设备列表页也不监听。
   - 补充：涂鸦平台上三种升级方式的说明（提醒 / 强制 / 检测）。

## 第 1 条：核对结论——没有，不做

- 解包 `thingsmart-device-api` 7.5.1：`DevUpgradeStatusEnum` = DEFAULT 0 / READY 1 / UPGRADING 2 / SUCCESS 3 / FAILURE 4 / WAITEXE 5 / DOWNLOADED 6 / TIMEOUT 7 / PENDING 13 / PREPARATION 14 / LOCALPREPARE 100；`ThingDevUpgradeStatusBean` 带 `status` / `progress` / `statusText` / `statusTitle`，经 `IThingOTAService.registerDevOTAListener(IDevOTAListener.firmwareUpgradeStatus)` 推送。
- 涂鸦官方文档（Android `otaupdate`、iOS `ios-device-firmware`）对应说明：2 升级中、6 固件已下载到设备、13 云端排队、14 云端准备、100 App 准备（连接蓝牙设备、下载固件包）。
- 没有独立的「下载中 / 传输中 / 安装中」。Wi-Fi 设备的 2 是一整段进度；「传输」只在蓝牙直连升级时存在。按「没有就不做」，升级进度保持「升级中 xx%」。

## 变更内容

### 第 5 条：固件升级提醒

- `UpgradeInfoBean` 解包常量：`UPGRADE_TYPE_REMIND = 0`、`UPGRADE_TYPE_FORCED = 2`、`UPGRADE_TYPE_CHECKING = 3`；iOS `ThingSmartFirmwareUpgradeModel.upgradeType` 同一套（官方文档）。
- Android `checkFirmware` 多回 `upgradeType`（`getUpgradeType`），iOS 多回 `pending.upgradeType`；Dart `FirmwareUpdate.upgradeType`（`FirmwareUpgradeType.fromTuya`，认不出 / 老原生包不回 → 检测升级，行为同改前）。
- `FirmwareReminderHost`（挂 `MaterialApp.builder`）：`/devices/` 下除设备列表、搜索、配网三页外算设备页；进设备页对该设备 `refreshFirmwareUpdate`（1 分钟内不重复）；提醒升级弹 `showAppDialog`（取消 / 立刻更新），取消后这次进设备面板不再弹、离开设备页清掉；强制升级弹 `PopScope(canPop:false)` 的 `AppDialog`（只有立刻更新）；检测升级不弹。其他设置页、正在升级（未卡住）、盖着别的弹框时不弹。
- 「立刻更新」→ `pushNamed(deviceOtherSettings, DeviceOtherSettingsArguments(startFirmwareUpgrade: true))`，其他设置页进页即 `_checkFirmware(confirmed: true)`，跳过「检查更新」确认框，直接 `upgradeFirmware` + 进度弹层。
- `AppRoutes.deviceIdOf(RouteSettings)`：从裸字符串和各参数对象里解出设备 id；联调日志观察者也改用它（其他设置的参数不再是字符串）。
- `NetworkRouteTracker` 抽成 `AppRouteTracker`（多监听者），网络弹窗与升级提醒共用。

### 第 2 条：无网络缺省页

- `FlowerpotState._refreshDevicesForSession` 失败时探测一次网络，记 `deviceLoadOffline`（成功 / 清会话时复位）。
- `AppShell`：`devices.isNotEmpty || deviceLoadOffline` 进 `DeviceListPage`，否则仍是 `HomePage`（添加设备）。
- `DeviceListPage`：列表为空且 `deviceLoadOffline` 时画 `_DeviceListOffline`（Wi-Fi 断开图标 + 「当前网络不可用，请检查网络后重试」+「重试」，可下拉）；没网时重试失败不再叠红色 toast（页面文案 + 全局弹窗已经说了）。有网但读失败走原来的错误态 / 页面。

### 第 3、4 条：电池状态

- 首页快捷列表去掉电池状态（`HomeActionKind.battery` 删除），设置页加 `DeviceSettingsMenuKind.battery`（纪念日下、其他设置上，行尾 `xx%`），行首 `_BatteryLinePainter`：品牌青 `#70AFB5`、1.5/24 线宽的描边电池 + 闪电，与该列切图同风格（切图里没有电池）。
- 电池状态页只留摘要卡：删 `DateRangeNavigator`、历史 `FutureBuilder`、`battery_trend_chart_card.dart`。
- 摘要卡底部电量图标改走 `StatusMetricIcon`（可见圆底 40、左沿 26）；`ChargingBatteryBadge` 只剩顶部那枚，去掉 `metric` 参数。
- 描述 `_TwoLineDescription`：用不可见的两行占位撑住最小高度（跟系统字号缩放，超过两行照常换行）。

## 未完成项与风险

- 真机要验：平台把固件配成「提醒 / 强制」后两种弹框；强制升级在设备离线（升级发起失败）时的体验——回到设备页会再次弹，用户只能去设备列表以外的地方。
- iOS 的 `upgradeType` 按官方文档写，本机没有 iOS SDK 头文件，未解包核对。
- 「设备页」按路由前缀 `/devices/` 判定，今后新增设备子页自动纳入；新增非设备页放在这个前缀下时要加进排除表。
- 设置页电池图标是代码画的，设计若给切图再替换。

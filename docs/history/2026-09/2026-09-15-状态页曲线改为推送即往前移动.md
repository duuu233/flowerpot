# 状态页曲线改为推送即往前移动

> 文档类型：Historical Change Record
> 日期：2026-09-15
> 环境：SSH（本机无 Flutter / Dart 工具链）
> 分支与起始版本：main / `1f5cfb4`
> 范围：`lib/src/state.dart`、需水 / 光照 / 空气温度 / 相对湿度四个状态页、`test/support/mock_tuya_repository.dart`、`test/features/devices/status_history_live_test.dart`
> 当前权威文档：`docs/PRODUCT_RULES.md` §4.5；`AI_CONTEXT.md` 状态页与历史 DP 条目

## 背景与目标

上一版（`2026-09-15-状态页曲线跟随涂鸦推送实时刷新.md`，`1f5cfb4`）只在「本页那段历史包变了」时重取曲线，
无关上报不动，温度、湿度不拿实时值画线。产品看过结论后明确：

> 这个问题不需要做特殊的处理，跟以前那些数据一样的渲染就行了。只要涂鸦推送了，你报表就是要实时动，就是往前移动那种效果。

## 变更内容

- 撤掉 `1f5cfb4` 的 `reportedHistory` / `historyReportedSince`、页面里的 `_loadedSeries` 与「曲线已刷新」日志。
- 四个状态页不再用 `historyFor` 的 Future + `FutureBuilder`：build 里和顶部读数一样直接读
  `FlowerpotState.chartSeries(deviceId, metric, range)`，推送一到页面重建、曲线重画（没有「正在读取」态了）。
- `chartSeries`：
  - 日视图 = 设备快照里的历史日包 + 本次登录以来推送的实时值，取最后 `liveChartWindow`（96，与日包点数相同）个；
    新点从右边进，满了挤掉最左边，整条线往前移。
  - 周 / 月视图只画历史包（每天一个平均值，实时值不往里接），推来新包整段换。
  - 同一份数据返回同一个列表实例（按设备历史实例 + 实时点版本号缓存），无关重建不重置图表选中点。
- `_recordLiveSamples`（在 `_applyDeviceUpdate` 里调）：按 `DeviceUpdate.changedDps` 判断——带了 105/106/109/112/114
  就往水位 / 土壤湿度 / 照度 / 温度 / 湿度后面接一个当前值（值没变也接）；同一条推送带了该指标的日包
  （131/134/137）就先清掉之前接的点。设备解绑时清该设备，退出登录时全清。
- 测试 Mock：演示设备自带 `DeviceHistory`（形状与 `getHistory` 同一套生成函数），因为页面不再调 `getHistory`。
- 测试 `status_history_live_test.dart` 重写：推 105 日曲线右边多一个点、周曲线不变；值没变也算一次；电量推送
  返回同一个列表；满 96 点后每推一次首点前移；新日包以包为准；温度页无历史包时推 112 曲线出现、再推往前走。

## 关键决策

- 周 / 月不接实时值：那两张图的每个点是「一天的平均值」，把几秒一次的实时读数当成一天画进去会把图画错。
  产品说的「往前移动」落在日视图上；光照页默认是周视图，要看往前走得切到「日」。
- 实时点只存在内存里（本次登录），不落盘：杀进程后从设备历史包重新开始，与设备为准的口径一致。

  标签与点对应的真实时间不再严格对齐。
- 设备推送频率未知：推得很勤时，日包的 96 个点会很快被实时点挤出去。

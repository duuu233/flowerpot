## 一、周 / 月报表：去掉左右翻页按钮，固定显示当期

### 背景

用户：「去掉水仓、土壤、光照周月报表左右的按钮，周、月固定显示。」

这三个指标的历史都在两个状态页上：**水仓水位 / 土壤湿度**在需水状态页（同页两个指标切换），
**光照**在光照状态页。两页顶部都是「日 / 周 / 月」选择器 + 一条 `DateRangeNavigator`（左箭头 · 日期 · 右箭头）。

2026-09-17 那轮给翻页加了窗口下限（`HistoryPeriod`）之后，**周 / 月的两个箭头其实已经永远是灰的**：
设备的周包、月包只有当期那一份（132/133、135/136、138/139 各一条 DP 就是一整期，滚动覆盖），
往前没有第二份、往后没有「下一期」。灰着的按钮还摆在那儿，只会让人反复去点、以为是卡了。

### 改法

改在 `DateRangeNavigator` 一处：**两个方向都翻不动时（`onPrevious` 与 `onNext` 都为 null），
不画箭头，标签居中**。两个状态页一行没改——它们本来就已经在周 / 月传 null 了。

为什么放在组件里而不是在页面里加条件：这个判断是「这条控件此刻有没有可操作性」，
属于控件自己的事；放页面里就是两页各写一遍，和上一轮那个「四页各写一遍所以四页一起错」的坑同源。

日视图不受影响：它至少有一侧可翻，照旧两个按钮，到边的那侧仍然置灰——
**灰在那里是有意义的**，它告诉用户「这个方向到头了」；而周 / 月是「压根没有这个方向」，两回事。

## 二、固件升级：进安装中之前先把 98% 亮一拍

### 背景

用户：「固件安装中直接把 98 替换掉了，看不到 98%，92% 就直接跳过去了，要必须看到 98%，观感自然一点。」

2026-09-17 产品定过：进度到 **98%** 就换成「固件安装中」+ 不定进度动效、不写数字，
因为涂鸦走到 98 之后要停一大段等设备写固件、重启，停在「固件升级中 98%」像卡死。
那条口径本身没问题，问题出在**过渡**：涂鸦的进度常常从 9x 直接跳到 98/100，
于是 98% 这个数字一闪而过、甚至根本没露过面，用户看到的就是「92% 之后忽然换了一句话」。

### 改法

`_OtaProgressDialog` 由 `StatelessWidget` 改为有状态：收到「进度 ≥ 98」的**第一拍先按升级中显示**
（文案「固件升级中」、进度条钉在 98%、数字写 98%），**900ms 之后**才换成安装中那套。

三条边界：

- **只拦「进度自己走到 98」这条路径**。涂鸦直接报阶段 6（固件已下载到设备）而进度还很低时不做停顿——
  那种情况下假装 98% 是个设备从没报过的数字。
- **只是显示上的一拍**，设备该写固件还写固件；成功事件随时来随时切「升级完成」（非 running 直接跳出）。
- 停顿只发生一次（`_held98`），不会在安装中反复弹回 98%。

模型侧 `OtaProgress.displayStage` 的判定**一个字没改**（`test/state_ota_test.dart` 那条
「98% 起安装中」照旧成立），这一拍纯粹是弹层的展示节奏。

## 验证

- `test/features/devices/device_other_settings_page_test.dart` 的
  「installing firmware waits for the device to report success」按新节奏改写：
  推进度 98 后**先**断言「固件升级中 / 98% / 进度条 0.98」，`pump(900ms)` 后**再**断言
  原来那组「固件安装中 / 空数字 / 不定进度条 / 找不到 98%」——**原断言一条没删，只是挪到了一拍之后**。
- ⚠️ **本机没有 Flutter 工具链**（SSH 开发机与 nas 都没有），`flutter analyze` / `flutter test` 跑不了。
  只做了人工核对 + 括号配平检查。这两处都要真机复看：周 / 月那条看箭头是否消失、日视图是否照旧；
  固件那条要真机走一次升级，确认 98% 露面且之后正常进入安装中。

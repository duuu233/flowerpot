# iOS 涂鸦 SDK 由 7.8 升到 7.11

> 文档类型：Historical Change Record
> 日期：2026-11-24；环境：远程 SSH 服务器
> 分支与起始版本：main / dfb896b

## 依据与范围

打 iOS 包时，`ios/Podfile` 要求 `ThingSmartHomeKit ~> 7.8.0`，而涂鸦平台按当前 Bundle ID `com.common.yikaltdtext` 导出的安全组件（`ios_core_sdk.tar.gz`）配套 7.11，本机已用 7.11 验证能打包。用户确认导出的 SDK 为 7.11，要求核对影响后去掉 7.8 的要求。

## 7.8 的来历

2026-08-20 接入 iOS 时，版本由 7.5 改为 7.8，跟随当时安全组件包附带的官方 Podfile（见 `2026-08/2026-08-20-dp-live-updates-and-ios-bridge.md`）。当时 iOS Bundle ID 仍是 `com.common.yikaltd`；2026-11-13 改为 `com.common.yikaltdtext` 后重新取了安全组件，Podfile 版本未跟着改。旧 7.8 组件属于旧包名时期，不再使用。

## 改动

- `ios/Podfile`：`pod 'ThingSmartHomeKit', '~> 7.8.0'` 改为 `'~> 7.11.0'`。其余（`ThingSmartCryption` 本地路径、模拟器 arm64 排除）不变。仓库不跟踪 `Podfile.lock`。

## 影响核对

依据涂鸦公开 pod 仓库（tuya-pod-specs）中 `ThingSmartHomeKit` 7.8.0.6 与 7.11.0.3 的 podspec，以及所用模块两个版本的公开头文件：

- 依赖的 pod 种类相同，只有小版本升级；最低 iOS 均为 11.0（项目为 13.0）。中间没有 7.9 / 7.10。
- 项目用到的模块：DeviceCoreKit 5.29.0.2 → 5.29.8、BLEKit 5.17.0 → 5.19.7、BLECoreKit 5.16.0 → 5.17.4、ActivatorCoreKit 5.10.2 → 5.10.4、BaseKit 5.8.12.1 → 5.8.15、MessageKit 5.7.0 → 5.7.1；DeviceKit 5.16.0 未变。
- 头文件差异只有新增（验证码登录、蓝牙离线升级相关字段、`queryWifiList:` 等）和一处删除：DeviceCoreKit 去掉 `ThingSmartDeviceAdvancedAbility`（高功耗能力），项目未使用。`AppDelegate.swift` 用到的设备、DP 下发、OTA、配网、蓝牙双模配网、用户、家庭、消息接口签名均未变。
- 只看了头文件，没有看 SDK 内部行为的变更说明。

## Mac 编译与签名验证（2026-11-24）

在 `cb46854` 的独立工作区安装了 `ThingSmartHomeKit` 7.11.0.2。Xcode 归档先因 Flutter 配置未加载 CocoaPods 的 `PODS_ROOT` 而失败。接入 Debug 和 Release 的 Pods xcconfig 后，Swift 编译仍报可选性、枚举及部分方法名不匹配。

- `ios/Flutter/Debug.xcconfig` 和 `ios/Flutter/Release.xcconfig` 加载 CocoaPods 生成的 Runner 配置。
- `ios/Runner/AppDelegate.swift` 按 7.11 在 Swift 中实际导入的类型和方法适配 SDK、账户、设备、配网及 OTA 回调。设备移除优先按监听实例反查 ID，家庭通知采用 7.11 头文件中的 `home:didRemoveDeivice:`。
- 构建号 22 的 Release 归档和 Ad Hoc 导出通过。已核对签名、嵌入描述文件和 Wi-Fi 信息、热点配置两项权限。登录、配网、解绑与 OTA 行为待真机验证。
- 如果要撤回本次修复，先确认目标 SDK，以及该版本安全组件和 Swift 接口的对应关系，再回退 CocoaPods 配置或原生桥接变更。

## 回滚

`ios/Podfile` 改回 `~> 7.8.0`，同时换回与之配套的安全组件（须与当前 Bundle ID 一致）。

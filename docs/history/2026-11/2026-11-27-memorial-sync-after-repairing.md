# 重新配网后 App 不显示自定义纪念日；设备改名核对

> 文档类型：Historical Change Record
> 日期：2026-11-27；环境：远程 SSH 服务器
> 分支与起始版本：main / e1a4a71

## 依据与范围

测试反馈（花盆）：

- 设置自定义纪念日后「移除设备 → 重新配网」，App 有移除前的纪念日；
- 设置后用「重新配网」（DP150），设备上仍有纪念日，联网后也重新上报了 DP154，但 App 没有同步。

同时核对两点：设置设备名称是否正确调用涂鸦 SDK；设备名称末尾数字跳动（涂鸦在同一账号下添加同名设备时自动加序号），是否与授权码、绑定关系有关。

## 原因

- App 把 DP154 当成只写：设备的 154 上报一律丢弃，自定义纪念日列表只认后端 `getProductAnniversaryList` 按涂鸦设备 id 查到的结果（返回行再按 `deviceId` 过滤一次）。
- 功能点表里 154 是「可下发可上报（rw）」，设备联网后会把自己存着的条目再报上来，帧里的 ID 就是后端的 `anniversaryId`。
- 「移除再配网」能看到，说明这条路径下后端按设备 id 能查到；「重新配网」看不到，最可能的是这次激活后涂鸦设备 id 与保存时不同，后端那几条挂在旧 id 上，按新 id 查不出来。服务器上无法真机确认，本次加了日志直接对比（见下），代码按两种情况都能补回来处理。

## 改动

- `TuyaMemorialCodec.decodeFrames`：把一条 154 上报拆成多帧（单帧或几帧首尾相接），认出删除帧（日期 `111111`）。残缺的尾巴丢弃。
- `FlowerpotState`：
  - 收到花盆的 DP154 上报时记下各条目，按条目 id 补齐列表里缺的。
    - **接后端**：按 id 取详情。如果挂在别的设备 id 上，就调用 `editUserProductAnniversary` 改挂到当前设备，再补进列表；如果挂在当前设备上，直接补上。
    - **后端已没有这条**：按设备上的内容在后端重建（标题用「自定义纪念日」，用户可改），再把新 id 写进设备并删掉设备上的旧 id。停用帧没有内容，跳过。
    - **没接后端**：按帧内容补进本机清单。
  - 补齐按设备串行。保存中的条目（设备会回显同一帧）和本次删掉的条目不补。进纪念日页刷新后端列表后会再补一次。
  - 重新配网（DP150 已受理）时记下设备 id 与 uuid / mac。下次配网成功后比对：id 没变记「设备 ID 未变」；id 变了且 uuid / mac 相同，就把旧 id 名下的本机清单和后端纪念日改挂到新 id；对不上的不当成同一台。
  - 联调日志：配网成功写设备 ID、是否列表已有同 ID、uuid / mac、激活时间、涂鸦设备名，并提示列表里有没有同 uuid / mac 的其他设备；「设备列表快照」每台加 uuid / mac 与激活时间；DP154 上报与补齐结果都留痕。
  - 退出登录时清掉本次会话的 154 记录（本机纪念日清单照旧保留）。
- 测试：`memorial_codec_test.dart` 加多帧拆分；`memorial_page_test.dart` 加三例：后端条目挂在旧 id 上时改挂回来、后端没有时重建并替换设备旧 id、保存后设备回显不会重复。

## 设备改名核对（未改代码）

- 设备信息页改名走 `FlowerpotState.renameDevice` → `MethodChannelTuyaRepository.renameDevice`。Android 反射调用涂鸦设备实例的 `renameDevice(name, IResultCallback)`；iOS 调用 `ThingSmartDevice.updateName(_:success:failure:)`。两端都是涂鸦 SDK 的改名接口，成功后本机记下自定义名。后端改名（`editUserProduct`）的映射从未填充，实际不调用，那组接口已下线。
- 名称末尾数字是涂鸦云端在激活时生成的：同一账号下已有同名设备，新激活的设备就加序号。App 改名只改当时那个设备 id 的名称；再次激活后云端重新取名，自定义名与涂鸦名对不上，显示规则会退回产品名。
- 授权码 / 绑定关系：若两台实物设备烧了同一个授权（uuid），涂鸦会把它们当成同一台（后配的顶掉先配的）。若同一台设备每次重新配网都拿到新的设备 id，旧 id 会留在账号下，名称就会继续加序号。用新加的日志可以区分：
  - 看「配网成功」与「重新配网 ⚠️ / ✓」两行：重新配网前后设备 ID 有没有变；
  - 看设备列表快照的 uuid / mac：两台实物的 uuid 是否相同。相同即授权重复，需要设备端 / 模组厂核查。

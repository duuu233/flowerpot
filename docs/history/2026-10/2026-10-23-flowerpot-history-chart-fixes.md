# 花盆历史曲线：负温、未采集、日视图刻度、过去日帧定长

> 分支与起始版本：main / 2d3c294
> 依据：`docs/history/other/app_DP_问题修正说明.md` §4（日 / 周 / 月历史帧格式与必读坑位）

## 范围

核对 §4 后补齐曲线展示层：

1. 空气温度曲线支持零下（解码早已对，曲线把负值压在 0 基线上）。
2. 日视图横轴与时间对齐（今天那帧只到现在，却按 00:00–24:00 拉满）。
3. 设备以 0 补齐的「未采集」槽位灰显 / 断线（§4.5 第 2 条）。
4. 过去 6 天的日帧必须满 96 点（§4.2 定长，§4.5 第 8 条帧长自检）。

顺带修复：`chartSeries` 对周 / 月也按 96 截尾，月曲线（最多 180 点）只剩最近 96 天，违反 §4.5 第 1 条。

## 改动

- `HistoryFrameBuffer.addDay`：以最新日期为准，**早于昨天**且不满 96 点的日帧丢弃；昨天放宽（跨 0 点时手里那份是它还是今天时收到的，0 点全量会补满）。
- `DeviceHistory`：新增 `_latestDays`（每个指标日视图那天）、`dayGaps` / `latestDayGaps`。某一槽「这天所有有数据的指标都是 0、且至少两个指标到了」判为没采到——单看一个指标分不出（夜里光照、空水箱都是真 0），空气湿度不会是真 0。
- `FlowerpotState.chartData` → `HistoryChart`（`values`、日视图每点距 00:00 的 `minutes`、`gaps`）；`chartSeries` 保留为 `.values`。实时点记收到时刻；跨 0 点 +1440，钟差不倒退。只有日视图按 96 截尾，周 / 月不截。
- `HistoryPeriod.timeTicks`：按点的时刻取整点刻度（15 分钟 ~ 6 小时自动选，最多 6 个），返回刻度文字和落点（点下标，可插值）。满一天显示 00:00/04:00/…/20:00；上午十点只标到 10:00。
- `WaterTrendLineChart`：
  - 负值：0 以上仍 5 格，按同格距往下加格（最多 5 格），0 线画实，零下线段与填充改 `AppColors.info`，零下刻度数字同色；填充到 0 线。
  - 未采集：线断开，底下铺灰并写「未采集」（太窄不写字）；选中显示「未采集」；默认选中点避开未采集。
  - `labelPositions`：标签画在对应点上。
- 需水 / 光照（日）/ 空气温度 / 相对湿度四个状态页改用 `chartData` 与 `timeTicks`。
- 测试：重写 `test/tuya/tuya_history_codec_test.dart`（原文件调用已删除的 `decodeDaily` / `variableLength` / `monthSegment`，编译不过）；`status_history_live_test.dart` 加月 180 点不截、日视图带时刻；新增 `water_trend_line_chart_test.dart`（负值、未采集、默认选中、边界）。
- `AI_CONTEXT.md` 历史一节按当前单帧实现重写（原文仍是已删除的 7 天整包 / `variableLength` 口径）。

## 决策

- 今天的曲线保持 2026-09-15 产品口径「推送一到往前移」（满 96 点挤掉最左），不改成固定 0–24 点的轴；改为**标签按点的真实时刻**生成，移动效果与时间刻度同时成立。
- 未采集不能见 0 就判：按同一槽所有指标同时为 0 判定。代价：设备没有 164/165 时，夜里 + 空水箱 + 土壤 0 三者同时为 0 会被当成未采集。
- 零下配色用现有 `AppColors.info`，不新增色值。
- 报表页（`ReportsPage`）当前无入口，未接未采集与时刻刻度。

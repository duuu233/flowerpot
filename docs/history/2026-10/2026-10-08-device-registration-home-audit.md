## 背景与目标

花盆偶现设备云端丢失，割草机暂未观察到。对比两类设备注册逻辑，先核实客户端家庭 ID 与账号归属处理是否存在产品差异。

## 变更内容

- 校正 `BACKEND_TUYA_HOME_ID.md`：缓存键使用账号键，Android 优先家庭标记再按设备数和 ID 排序，iOS 优先标记再按 ID 排序；空列表自愈有固定家庭前提，部分设备缺失不会触发。
- 补充注册共用范围与现场证据边界；更新文档导航和本记录索引。
- 本轮没有修改业务源码、测试源码、依赖或平台配置。

## 关键决策

1. Android 当前两类产品均走同一 BLE 双模配网和家庭解析流程，配网配置使用同一会话家庭 `gid`，没有按产品选择另一家庭或后端注册的分支。
2. 同一账号并不自动意味着全部设备属于同一个家庭。当前清单只查一个家庭，列表非空时不会寻找其他家庭中的花盆，不能宣称家庭问题已完全排除。
3. 原生令牌缓存没有家庭 ID，家庭切换不作废令牌；正常成功回调没有立即核对目标设备是否出现在家庭清单。两点均属共用边界，未在现场复现。
4. SDK 支持部分双模产品的蓝牙兜底本地激活，当前成功路径没有独立核对 `wifiEnable`。尚不知本次花盆是否支持该能力，不能据此认定根因。官方依据见当前权威文档。
5. 花盆有 DP141 + SDK `resetFactory` 的恢复出厂 / 重新配网入口，割草机当前仅普通删除。普通配网成功流程未发现自动解绑调用。
6. 设备移除事件会删本地清单，设备离线只改状态；应先分清 APP 清单缺失、账号家庭归属变化、云端解绑与单纯离线。

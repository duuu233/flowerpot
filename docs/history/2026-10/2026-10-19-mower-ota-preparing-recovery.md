# 割草机 OTA 准备阶段与进度恢复

> 文档类型：Historical Change Record
> 日期：2026-10-19
> 环境：办公室 Windows / work
> 分支与基线：main / b13ee84421d3058f2cb56024f4afa3750a0583ce
> 状态：代码与自动化验证完成，真实设备待验收

## 背景与确定缺口

用户反馈割草机长期显示“固件准备中”，此前也有同设备比涂鸦 App 慢的反馈。实际代码使用旧 OTA 接口；旧监听只收部分状态，独立状态 3/4/7 未收尾；明确阶段 2 在无有效百分比时仍显示准备中；没有主动查询补漏及窗口内停滞提示，重复事件又持续延长等待。这些是确定代码缺口，但没有真实设备回调和设备下载/烧录时间线，不能归为现场唯一原因，也不能声称已缩短到某分钟。

## 修改与边界

- 核对官方固件升级说明与实际 SDK 7.5.1 AAR，Android 优先 OTA Service，注册后按目标版本及组件重新查询再启动；旧 SDK 保留兼容路径。Home/Expansion 版本未改。
- Service 回调和每 8 秒进度快照共用解码，补齐 3/4/7；过滤其他设备、组件、旧尝试及无当前推进的缓存终态快照。-1/非法进度忽略，百分比及阶段不倒退。预检拒绝与弱信号 5005 不自动绕过。
- SDK 固件状态 2/5 表示已有任务，只重新挂接，不重复下发，也不把它当普通新版本提醒。新任务仍按充电条件和弹框退场顺序启动。
- SDK 阶段 2 无数值也显示升级中，使用动画；无阶段无进度仍显示准备中。准备 2 分钟/其他阶段 10 分钟无真实推进时提示“暂未收到升级进度”，允许关闭窗口但不停止设备、不判失败、不自动重试。窗口每秒检查；启动方法 30 秒无答复时仍转入等待事件。
- 首终态及安装阶段版本兜底保留，DP112/148 必须为本次真实上报且匹配目标，不能把超时或旧快照判为成功。设备固件、差分配置及 iOS 原生 API 未改；App 重启后仅手动查询接回 SDK 可识别的任务，不承诺自动恢复。

## 验证

- 基线干净源码相关测试 119 项通过；精确提交候选覆盖后 127 项通过（新增恢复测试 8 项）。保留用户原修改的当前工作区中新增 8 项也通过。
- 真实 SDK 7.5.1 类型编译并运行旧监听 26 项、Service 21 项，共 47 项断言通过。
- 最终 `:app:compileDebugKotlin -Ptarget-platform=android-arm64 --offline` 通过（最终对齐候选复编译 9 秒）。未生成/安装 APK，未发起真实 OTA。
- 对涉及的 7 个 Dart 源码/测试文件分析，无新增诊断；保留既有 `_filterToOurProduct` unused warning 与注释尖括号 info。
- 当前本地原有 DP 修改会使旧 OTA 测试引用已移除的 `otaResult` 而无法编译，历史数据用例还存在预期 50/实际 100 的基线失败；没有借 OTA 修复更改这些独立改动。为此另以干净基线与精确提交内容做独立验证，不将原工作区说成全量通过。

## 本地改动保护与交付

开始前按用户授权暂存、pull 后带 index 恢复，21 个原路径内容及原已暂存删除均核验。提交通过单独索引仅纳入本轮 OTA 补丁，state/models/repository 中既有 DP 调整不混入，原未跟踪文档/校准页不提交。相关实现契约更新在 Active 文档及索引中。

## 真机验收与回退

需用同一设备、相同起始/目标版本及组件记录启动、SDK 阶段/百分比、DP112/116、重启上线和完成时间；核实是否实际安装已结束但回调缺失，或设备下载/校验本身慢。正常成功、失败、无回调、重复快照及重新进入要分别检查。Windows 未进行 iOS 编译或真机验证。

回退仅反向撤销本轮提交，不 reset/覆盖用户原有修改。引用：[涂鸦官方固件升级](https://developer.tuya.com/en/docs/app-development/otaupdate?id=Ka6ki8la8wnr9)；当前规则见 [OTA 实现说明](../../OTA_实现说明.md)。

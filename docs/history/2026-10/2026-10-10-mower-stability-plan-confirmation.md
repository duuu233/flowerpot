# 割草机删除确认复核与首页稳定性

> 文档类型：Historical Change Record
> 日期：2026-10-10
> 环境：办公室 Windows
> 分支与起始版本：main / 8ce4749
> 范围：割草计划、首页控制、设备绑定与 Android 下发桥接
> 当前权威文档：PRODUCT_RULES.md §4.19、MOWER_DP_GAP_REPORT.md

## 背景与目标

用户再次要求长按计划时间必须二次确认，并反馈 Android 测试割草机时偶发闪退，后来缩小到首页操作；没有明确触发按钮、设备状态或崩溃堆栈。

当前分支已经包含 10 月 9 日的确认弹窗；原有 9 项长按回归均通过。未发现另一条直接删除入口。本轮保留既有二次确认，补上确认期间设备上报变化与重复触发保护。

## 变更内容

- `mower_plan_page.dart`：取消 / 返回 / 遮罩不下发，确认只删除目标；目标时间已变化时提示重新长按，其余时段和修边取最新值。防止重复弹删除框。
- `mower_device.dart`：绑定会话版本隔离旧异步回调；取消旧队列中未发送的指令，新队列不等待旧请求；后台连接刷新合并；快照、连接、回弹和上报流异常兜底；发送前再次拦截 DP113 已关机设备。
- `mower_control_page.dart`：自动、定点、回归、停止 / 继续共用防重入和异常提示，失败恢复 loading；异常 RSSI 走检查失败，保持原蓝牙检查总闸。
- `MainActivity.kt`：DP 下发复用已监听实例；临时设备控制实例在成功、失败、同步异常时回收，共享实例不提前销毁。
- 测试：新增 9 项生命周期与异常回归、4 项按钮异常、2 项删除期间上报变化。现有告警测试等待弹窗帧和动画完成；设备测试停用无关轮询，取消全局流不阻塞假时钟，BLE 操作使用真实异步区。日志断言区分原始上报与一次性的关机判定，并适配已有通道诊断字段。

## 关键决策

不把防护修复当作已经定位闪退根因。Dart 层的未处理异常不等价于 Android 进程崩溃。已进入 SDK 的请求不能取消；本轮隔离的是旧请求的页面回调和未发送队列。

原生回收沿用现有桥接已使用的 `IThingDevice.onDestroy`，资源回收要求参考 [涂鸦设备管理](https://developer.tuya.com/en/docs/app-development/devicemanage?id=Ka6ki8r2rfiuu)。没有新增蓝牙 SDK 或接口，没有修改 DP 编码、通道选择或生产数据来源。

## 外部操作

开始前显式 pull origin main，已为最新；CodeGraph 已同步。未操作真实设备和业务数据，未发布或安装 APK。

## 验证结果

- 页面回归 34 项通过；设备、生命周期、协议三组 42 项通过，共 76 项。
- 修改涉及的 6 个 Dart 源码 / 测试文件 analyze 无问题；四项 Dart 自检扫描 340 文件通过；原生 kt_dangling_refs 检查通过。
- Android `:app:compileDebugKotlin -Ptarget-platform=android-arm64` 编译通过（1m07s）。首次离线编译缺少当前 Flutter 引擎缓存，联网补齐后成功；没有生成 APK。原有 Wi-Fi API 与 Gradle 弃用警告仍存在。

## 未完成项与风险

没有连接 Android 真机，没有 crash buffer / FATAL EXCEPTION 堆栈，不能证明偶发闪退已消失。Android 需回归连续控制、离线 / 蓝牙降级、关机、操作期间返回再进入、切计划 / 设置和故障弹窗。

复现后优先保留 `adb logcat -b crash -d`，结合触发按钮、系统版本和设备在线状态定位。本文不记录设备标识或凭据。本轮未生成测试 APK，pubspec build number 不变。

## 回滚或恢复

需要回滚时撤销本轮提交；不清理设备计划或 SDK 数据，不覆盖本机秘密配置。

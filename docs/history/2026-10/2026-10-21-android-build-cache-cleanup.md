# Android 构建中间目录清理

> 文档类型：Historical Change Record
> 日期：2026-10-21
> 环境：办公室（work）
> 分支与起始版本：main / 81ca3d5
> 范围：本机 build/app 可再生中间文件及构建维护说明
> 当前权威文档：[用户版 Android 构建](../../USER_RELEASE_BUILD.md)

## 背景与目标

用户要求检查 build/app 占用，清掉不需要的文件并保留打包能力。先核实当前 main 干净、origin 和远端同名分支，显式 pull --ff-only 成功；读取项目文档、查询 CodeGraph 并核对 Android Gradle 构建目录配置。

## 变更内容与关键决策

仅删除 build/app 下 intermediates、generated、tmp、kotlin、kotlinToolingMetadata 五个可再生目录；保留 outputs 和 deeplink.json。源码、打包参数和依赖未变。文档新增清理范围、保留产物和完整 clean 的区别，登记历史并更新文档索引。

## 外部操作

只操作本机当前项目内已忽略的生成目录，未连接设备、接口或发布平台。递归删除前验证目标绝对路径边界、根目录和子目录不存在链接/联接点；检查没有活跃的 Flutter/Gradle 构建，只有常驻守护进程，最近编译文件写入已超过两分钟。未停止共享守护进程。

## 验证结果

| 项目 | 结果 |
| --- | --- |
| 清理前 | 1,676,886,857 字节，约 1.56 GiB，2,978 文件。 |
| 主要占用 | intermediates 约 1.15 GiB；outputs 约 388.12 MiB。 |
| 清理后 | 406,973,399 字节，约 388.12 MiB。 |
| 删除的逻辑文件大小 | 1,269,913,458 字节，约 1.18 GiB。 |
| 输出保留 | outputs 的 25 个文件路径、长度、SHA-256 前后完全一致，含全部 APK、混淆映射和原生符号。 |
| 构建输入 | 本机属性、签名配置和涂鸦安全 AAR 的存在状态前后不变，删除路径均与这些文件隔离；未读取或记录密钥。 |
| Git | build/app 无跟踪文件且被忽略；清理后业务工作区仍干净，只有随后新增的维护文档变更。 |

原生合并库、多 ABI 和 debug/release 的重复中间结果是主要占用原因；单个最终 ARM64 APK 约 55.58 MiB、ARMv7 APK 约 47.09 MiB，不应把 build/app 总占用当成安装包大小。

## 未完成项与风险

没有重新执行完整打包或业务测试；本轮不改代码，重新构建会立刻生成刚清掉的缓存，因此用产物哈希和路径边界验证。下一次打包仍按原文档命令执行，首次重新编译耗时增加。没有重建、替换或更新现有 APK，也没有删除旧架构安装包。

## 回滚或恢复

缓存没有另做副本；需要时由原打包命令重新生成。已有安装包和排障产物保留，无需恢复。维护文档可通过 Git 回退，本轮不涉及源码或配置回退。

> 文档类型：Historical Change Record

> 当前权威文档：[用户包构建](../../USER_RELEASE_BUILD.md)、[产品规则](../../PRODUCT_RULES.md)

## 背景与目标

用户需要面向普通用户、关闭调试台与日志的安卓包，同时保留原来的联调能力和业务逻辑；最后明确只需要安卓。本轮开始工作区干净，显式 pull origin main 成功，继续当前分支，没有切分支或处理其它人的改动。

## 变更内容

- 新增 APP_DEBUG_TOOLS 编译开关，默认 true 保持原联调方式；false 时运行时 interactionLog 开关也无法重新开启。
- 统一关闭全局日志采集/浮层、计划解析台、花盆消息监控及其历史对照数据/额外查询、设备 DP 诊断、空列表会话诊断、配网日志与原始连接诊断、植物接口体检及原始响应调试显示。
- 调试关闭时应用自有 Dart/Android 日志停止输出，原生配网诊断事件停止发送；真实设备更新和其它事件通道继续运行。Android 涂鸦 SDK release 调试模式关闭。
- 计划编辑使用中文业务说明；消息通知中的日志/提醒/告警保留原取数和分类，计划保存、设备回读与 OTA 门禁保持。
- 当前版本 1.0.0+3，正式签名产出 ARM64 与 ARMv7 APK，分别 versionCode 2003/1003；不发布旧 x86_64 产物。所有平台共享 Flutter 调试开关，本轮没有 iOS 原生差异或 iOS 构建。
- 新增用户构建手册和双模式回归，更新产品规则及文档入口；旧运行章节中 TUYA_ENABLED/Mock/调试路由说明标为历史流程，当前真实仓库默认启用。

## 关键决策

保留所有联调代码，开关作为构建配置，不修改业务控制协议或账号/设备存储。用户包不把业务日志当调试数据删除。构建不改变包名或证书；第三方库及系统自身错误日志不承诺完全消失。

## 外部操作

仅本地构建、验证和 Git 同步。无云端配置修改、商店上架、发布、部署、真实设备控制或真实账号接口查询。签名材料和安全组件使用已有本机配置，未修改或提交。

## 未完成项与风险

adb 无设备连接，因此没有实际覆盖手机安装、启动、登录、云端消息、计划及升级验收；不能保证用户手机上任意旧 APK 的签名/版本与本机旧包相同。旧包若为另一证书签名或更高版本号，应提供同签名材料或提高构建号；不能直接保证覆盖。此包完成本次调试隔离和正式签名构建，不代表商店审核或全部历史发布问题均已验收。

## 回滚或恢复

联调打包传 APP_DEBUG_TOOLS=true 或省略参数即可恢复；相同包名只允许两种包互相覆盖，不能并装，反向覆盖仍需满足签名和版本规则。源码可回滚本次提交，保留本机签名与账号/设备数据。

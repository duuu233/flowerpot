## 1. 通信约定

| DP 类型 | 传输格式 | App 下发 | 设备上报 |
|---|---|---|---|
| bool | 1 字节 0/1 | `false`/`true` | 同左 |
| value | 4 字节大端整数 | 数值(按各 DP 范围) | 数值 |
| enum | 1 字节枚举序 | 枚举字符串(序号=传输值, **不可重排**) | 枚举字符串 |
| string | 字节流 | UTF-8/ASCII 文本或 JSON | 文本/JSON |
| raw | 字节流 | 十六进制字节流 | 十六进制字节流 |
| bitmap | 位图 | —(只上报) | 位图 |

### 1.1 下发结果怎么判断(核心约定)

| 通道 | 说明 |
|---|---|
| **① 结果帧(DP115)** | **每条下发**处理完, 设备立即回 1 帧 `{"code":N,"seq":N,"dp":N,"val":N}`。**`code` 是唯一权威判据**(`0`=成功; 非 0=拒绝理由码, 见 §8.2) |
| ② 回显 | **动作类**(DP2/DP3)即使被拒也**回显真实值** ⇒ 控件会弹回; **参数类**(101/102/103/104/105/106/107/108/109/110/114/119)被拒**不回显** |
| ③ 状态上报 | DP2/DP3/DP5/DP13/DP18/DP111/DP117/DP118 变化即报(1s 采样 + 60s 兜底), 可作为最终对账 |
| ⚠️ 例外 | **OTA 期间不发结果帧**(也不上报任何 DP); 开机后**从未下发过**时, 全量查询不回读结果帧 |

> **推荐做法**: 逐条下发 + 等结果帧; 超时(建议 5s)后**看 DP5/DP3/DP2 实际状态**判断是否已生效, 再决定是否重发。
> **重复下发是安全的**: 设备对"目标状态已达成"的重复命令会回 `code=0`(成功), 不会重复执行。

## 3. 控制类 DP

### 3.1 DP2 `switch_go` 工作开关(bool, rw)

**语义(2026-10 起定为"继续 / 停止")**：

| 下发 | 含义 | 设备行为 |
|---|---|---|
| `false` | **停止(=进急停)** | 与**按下面板急停键完全同源**：停轮/停刀 + 记录停机前工作点(供"继续工作") + 上锁 + 急停页 + 静音。**不再有"远程暂停态"** |
| `true` | **继续 / 启动** | ①急停态 ⇒ 恢复(**免输 PIN**；按急停位"继续工作"，有现成计划则沿用)；②待机 ⇒ 按 App **最后下发的 DP3 模式**启动(smart/spot/回桩)；③作业中 ⇒ 幂等成功 |

**逐状态行为矩阵(App 可直接照此做 UI 禁用态)**：

| 设备当前状态 | 下发 | 结果 | `code`(失败时) |
|---|---|---|---|
| 割草 / 沿边 / 定点 / 回充中 | `false` | ✅ 进急停 | — |
| 在桩等待(等充电/等雨停) | `false` | ❌ 拒绝(仅静音, 不动状态机) | `49 REJ_ON_PILE_WAIT` |
| 已急停 | `false` | ❌ 拒绝(已在急停) | `19 REJ_ESTOP` |
| 待机 / 自检中 | `false` | ❌ 拒绝(仅静音) | `17 REJ_SELFTEST` / `48 REJ_NO_MODE` |
| 等关盖(半启动) | `false` | ❌ 拒绝 | `21 REJ_COVER_OPEN` |
| 定点中 | `false` | ✅ 取消计划回待机(等同 standby) | — |
| 急停态 | `true` | ✅ 恢复(免 PIN)：有停机前工作点则**继续原任务**；否则取消回主页 | — |
| 待机(野外) | `true` | ✅ 按最后 DP3 启动(smart⇒新建计划 / spot / 回桩) | — |
| 作业中 | `true` | ✅ 幂等成功 | — |
| 待机(在桩) | `true` | ✅ 由自检链按电量分流(可能回充后出发) | — |
| 待机 + 未选过模式 | `true` | ❌ 拒绝 | `48 REJ_NO_MODE` |
| **上次任务是"被取消"的** | `true` | ❌ 拒绝(防止"取消后又被开关拉起来干活") | `52 REJ_TASK_CANCELLED` |
| 故障态(ABNORMAL) | `true` | 见 §8.6 自带清理 | `26 REJ_FAULT_ACTIVE`(不能清时) |
| 故障态(ABNORMAL) | `false` | ❌ **拒绝且不做任何事**(保持故障态) —— "暂停"不携带"清除故障"副作用 | `26 REJ_FAULT_ACTIVE` |
| 关机中 / 盖子未关 | `true`/`false` | ❌ 拒绝 | `16 REJ_POWER_OFF` / `21 REJ_COVER_OPEN` |

### 3.2 DP3 `mode` 工作模式(enum, rw)

**枚举定义(8 值, 序号=传输值, 不可重排)**：

| 值 | 名称 | 可下发 | 说明 |
|---|---|---|---|
| 0 | standby | ✅ | 取消工作回待机主页 |
| 1 | smart | ✅ | 随机割草(原 random 语义并入) |
| 2 | spot | ✅ | 定点割草 |
| 3 | goto_charge | ✅ | 回桩 |
| 4 | edge_mowing | ❌ | 沿边割草(机器端自动状态, 上报用) |
| 5 | secondary | ❌ | 第二区域割草(机器端自动状态) |
| 6 | wait_charge | ❌ | 在桩等待充电(上报用) |
| 7 | wait_rain | ❌ | 在桩等待雨停(上报用) |

> 下发 4~7 或更大枚举 ⇒ 拒绝 `64 REJ_BAD_ENUM`。

**下发示例(App 侧按枚举名选, 链路上是 1 字节序号)**:

| App 选择 | 链路传输值 | 结果帧示例 |
|---|---|---|
| smart(随机割草) | `1` | `{"code":0,"seq":7,"dp":3,"val":1}` |
| spot(定点割草) | `2` | `{"code":0,"seq":8,"dp":3,"val":2}` |
| goto_charge(回桩) | `3` | `{"code":0,"seq":9,"dp":3,"val":3}` |
| standby(取消) | `0` | `{"code":0,"seq":10,"dp":3,"val":0}` |
| (不支持) | `4` | `{"code":64,"seq":11,"dp":3,"val":4}` ← 64 非法枚举 |

**逐状态行为矩阵**：

| 设备当前状态 | 下发 DP3 | 结果 | 计划(schedule)影响 |
|---|---|---|---|
| 割草 / 沿边中 | spot | ✅ 转定点(定点进度重置) | **沿用**现有计划 |
| 割草家族中 | smart | ✅ 幂等成功 | 不动 |
| 定点中 | smart | ✅ 转割草 | **沿用** |
| 回充中(未触桩) + **低电回桩** | smart / spot | ❌ 拒绝(④ 中断原因门 PWR) `34 REJ_LOW_CHARGE` | 不动 |
| 回充中(未触桩) + **雨天回桩** | smart / spot | ❌ 拒绝(④ 中断原因门 PWR) `35 REJ_RAIN` | 不动 |
| 回充中(未触桩) + **手动/计划完成回桩** | smart | ✅ 转割草 | **沿用**(有则) / 补建 |
| 待机(野外) | smart | ✅ 新建任务开工 | **新建** |
| 待机(野外) + **机器在界外**(双外确认) | smart | ❌ 拒绝(④' 圈外门) `33 REJ_OFF_BOUNDARY` | 不动 |
| 待机(野外) | spot | ✅ 定点开工 | 有则沿用 / 无则补建 |
| 待机(野外) | goto_charge | ✅ 回桩（**手动回充 = 取消任务**） | 清空 |
| 待机 / 作业中 | standby | ✅ 取消回待机 | 清空 |
| 在桩等待 | smart / spot / standby | ❌ 拒绝(不打断等待状态机) | 不动 |
| 等关盖(半启动) | standby | ✅ 取消待启动 | 清空 |
| 作业中(割草/回充) | standby | ✅ 取消回待机 | 清空 |
| 已待机 | standby | ✅ 幂等成功 | 不动 |
| **急停态** | 任意(0/1/2/3) | ✅ **先退急停, 再按该模式执行**；退急停时若有**未结算的旧计划**，会先记入工作日志(终止)再执行新命令 | 见左 |

> ⚠️ **中断原因门（PWR）**：`circularize` 通知位 **低电 / 雨天** 置位期间，**`DP3=smart` 与 `DP3=spot` 一律被拒**（`34 REJ_LOW_CHARGE` / `35 REJ_RAIN`）—— 这是对"回桩原因不是收工"的保护：低电/雨天回桩**保留计划**，等充满/雨停后由设备**自动出发继续** ✅
>
> ⚠️ **圈外门（④'，2026-10-10 新增）**：边界模块**双外确认**（`circularize` 的 `ILLEGAL_AREA` 位置位）且**不在桩**时，`DP3=smart` **与** `DP2=true`（按 smart 启动）会被拒 **`33 REJ_OFF_BOUNDARY`**。
> 不拦的话会出现"**命令回 `code=0`、设备随后进报警**"（自检链会清事件+报 `ERROR_ILLEGAL_AREA`+蜂鸣+进 ABNORMAL）⇒ 用户以为成功了却要清一次故障 ✗。
> 判据与自检链**完全同一处**；App 提示："机器在割草区域外，请移回界内再启动" ✅
> ⚠️ 顺序：**先信号门禁（`24`/`25`）后圈外门（`33`）** —— 未锁定时优先提示"还没找到线"。
> App 可从 **DP111 的 `circularize` 键**看出：`4`=低电、`2`=雨天 ⇒ 可提示"回桩充电/避雨中，稍后自动继续"。
> 解除条件：低电 ⇒ 电量回升（`battery.c`）；雨天 ⇒ 雨停（`sensor.c`）或 App 关闭"雨淋检测"（`DP104=false`）。
| **故障态(ABNORMAL)** | 任意(0/1/2/3) | 见 §8.6：能清 ⇒ 先清故障再执行；不能清 ⇒ 拒绝 `26` | 见 §8.6 |
| 关机 / 自检窗 / OTA 中 / 盖子未关 | smart / spot / goto_charge | ❌ 拒绝 | 不动 |
| 未锁定边界信号 | smart / spot | ❌ 拒绝(见 §8.7) | 不动 |

> 说明: **急停态或故障态下点"启动/换模式"时, App 不需要先发"清除"指令** —— 清除由设备在被执行的命令内自动完成(§8.6)。

## 4. 状态上报类 DP(设备 → App, 只读)

### 4.1 DP5 `status` 工作状态(enum 12 值)

| 值 | 名称 | 何时上报 |
|---|---|---|
| 0 | standby 待机 | 待机主页(含刚退急停/报警后的待机) |
| 1 | mowing 割草中 | 随机割草(含找线/起步阶段) |
| 2 | sleep 休眠 | **总电源关机中**(`system_power_on_flag == 0`) |
| 3 | spot_mowing 定点割草中 | 定点螺旋作业中 |
| 4 | goto_charge 回充中 | 回充行驶(离桩 → 触桩) |
| 5 | paused 暂停 | ⚠️ **设备已不再上报此值**(远程暂停态已删除) |
| 6 | fault 故障 | 报警停机(ABNORMAL)：需处理/清除 |
| 7 | stop 急停 | **急停态**(面板急停键或 App `DP2=false`) |
| 8 | edge_mowing 沿边割草中 | 沿边作业中 |
| 9 | wait_charge 等待充电(在桩) | 在桩等待充电 |
| 10 | wait_rain 等待雨停(在桩) | 在桩等待雨停 |
| 11 | secondary 第二区域割草中 | 去第二区域/第二区域作业 |

> 优先级: 关机 > 急停 > 故障 > 回充 > 在桩等待 > 沿边 > 定点 > 割草。

### 4.2 DP13 `battery_percentage` 剩余电量(value 0~100)

变化 ≥1% 即报; 查询全量回读。`val` = 百分比整数。

### 4.3 DP18 `fault` 故障告警位图(bitmap, 4 字节)

**平台位表 22 位; 固件当前使用 bit0~12, bit13~21 保留恒 0。**

| bit | 名称 | 含义 |
|---|---|---|
| 0 | left_wheel | 左轮异常(霍尔/程序/过流/过温) |
| 1 | right_wheel | 右轮异常(霍尔/程序/过流/过温) |
| 2 | battery | 电池异常(硬件类) |
| 3 | pose | 姿态异常(倾覆/抬起) |
| 4 | lift | 抬起 |
| 5 | boundary | 边界错误(丢信号升级为错误时) |
| 6 | blade_ocp | 刀盘过流 |
| 7 | blade_otmp | 刀盘过温 |
| 8 | blade_stall | 刀盘堵转 |
| 9 | outside | 机器在界外(含"未找到线禁止出桩") |
| 10 | spot_out_boundary | 定点不在界内 |
| 11 | trap | 机器陷坑(功能类) |
| 12 | blade_motor | 刀盘电机异常 |

> **纯故障视图**: 只映射 `device`(硬件类)/`error`(危险类)/`function`(功能类) 三层; 通知类(circularize: 碰撞/雨滴/低电/密草/抬起通知等) **不进位图**，走 **DP111**。
> 变化即报(1s 采样 + 60s 兜底)。

### 4.4 DP111 `fault_alarm` 四层故障位域(string, JSON)

**格式(2026-09 重定义, 无词表零翻译)**：

```json
{"device":0,"error":0,"function":0,"circularize":0}
```

| 键 | 级别(语义) | 说明 |
|---|---|---|
| `device` | fault(硬件类, 挂了完全不能用) | 32 位原始位域(见固件 `alarm.h` 的 device 枚举) |
| `error` | error(错误类, 会导致危险) | 32 位原始位域 |
| `function` | warning(功能类, 出现后机器无法执行任务) | 当前实际只用到"陷坑"位 |
| `circularize` | notice(通知类, 机器能自动处理) | 32 位原始位域 |

- 值=该层报警位组的 32 位原始值按位或(无告警时为 `0`); **App 建议只做"有没有/哪一层"的粗提示**，精细文案可自行按位表翻译。
- 变化即报; 无变化 60s 兜底重报。
- ⚠️ **App 精细用途**: DP115 回 `code=26`(故障未排除) 时, 用 **`device`(硬件类) + `error`(错误类)** 两层定位"还剩哪些故障", 按优先级提示 ⇒ 见 **§8.6.1**。
- ⚠️ 与 DP18 的关系: **DP18 = 平台故障码视图(报警用)**, **DP111 = 四层原始位域(诊断/精细提示用)**; 两者数据源相同、视角不同。

**示例**(位值取自固件 `alarm.h`):

```json
{"device":0,"error":0,"function":0,"circularize":0}    // 无任何告警(四键全 0)
{"device":0,"error":2,"function":0,"circularize":0}    // 抬起(error bit1 = 2)
{"device":0,"error":4,"function":0,"circularize":0}    // 边界信号异常(error bit2 = 4)
{"device":0,"error":0,"function":0,"circularize":2}    // 雨滴积水通知(circularize = 2)
{"device":0,"error":6,"function":2,"circularize":4}    // 抬起+边界异常(error=2|4=6) + 陷坑(function=2) + 低电(circularize=4)
```

**常见位值速查**(App 若要精细文案, 按位与判断即可):

| 层 | 位值 | 含义 |
|---|---|---|
| error | 1 / 2 / 4 | 位姿异常 / 抬起 / 边界信号异常 |
| circularize | 2 / 4 | 雨滴积水 / 工作电量过低 |
| function | 2 | 机器陷坑 |
| device | (硬件类, 见固件 alarm.h) | 电池/左右轮/刀盘电机等 |

> 注: 同一时刻多位并存时, 键值是**按位或**的结果(如上例 `error=6` = 抬起+边界异常)。

### 4.5 DP115 `command_results` 命令结果(string, JSON) 🆕 ★

**这是 App 判断"下发有没有生效、为什么没生效"的唯一权威通道** —— 完整契约见 **§8**。

**最快上手(可直接照抄的 4 个例子)**:

```json
发 DP2=true  成功         : {"code":0,"seq":1,"dp":2,"val":1}
发 DP3=smart 被拒(没找到线): {"code":24,"seq":2,"dp":3,"val":1}
发 DP101    被拒(长度不对) : {"code":65,"seq":3,"dp":101,"val":88}
发 DP115(只读, 不该发)     : {"code":68,"seq":4,"dp":115}
```

| 字段 | 本例含义 |
|---|---|
| `code` | `0`=成功(`24`=24 信号搜索中, `65`=65 长度不合法, `68`=68 只读不可写) |
| `seq` | 本设备本次上电内第几次下发(每次 +1, 0~255 回绕) |
| `dp` | 你刚下发的那条 DP 号 |
| `val` | bool/enum/value = 你下发的**数值**; **raw/string = 载荷长度**(如 DP101 的 88), **不回内容**; 未知 DP 场景可省略 |

### 4.6 DP117 `charging` 充电状态(enum 3 值)

| 值 | 名称 | 含义 |
|---|---|---|
| 0 | not_charging | 未在充电 |
| 1 | charging | 在充电(等雨停挂桩也算 charging) |
| 2 | full | 已充满 |

变化即报; 查询全量回读。

`1`=合盖, `0`=开盖(FLIP 霍尔, 200ms 防抖)。变化即报。

### 4.8 DP113 `shutdown_report` 关机上报(bool, ro)

- 设备**非在桩关机**时上报 `true`, 并在 1s 断电窗口内 **100ms 重发 ≈9 次**(最大化到达率); App 可秒级感知关机(设备离线判定是分钟级)。
- 在桩关机会复位重启, **不报** true。
- 开机连云时自动复位 `false`, 查询全量也回当前标志 ⇒ 复位上次关机残留的 true。

## 5. 计划与区域类 DP

### 5.1 DP101 `mow_schedule` 割草计划(raw 88 字节, rw)★

**2026-10-15 产品按 DP101 备注确认的修订**：此前本节组号与设备实际约定不一致，以以下布局为准。

**布局 = 8 组 × 11 字节**（组 0 = 全部设置，组 1~7 = 周一~周日）。组0任一时段有效（有效位非0且start<end≤1440）时，其余77字节必须全00，设备将组0广播为每天；组0全00时按1~7逐日处理。每次下发全量覆盖七天，未包含的日期不执行；有效时段须大于10分钟。查询和首报使用同一布局。

| 偏移 | 长度 | 含义 |
|---|---|---|
| +0 | 2 | 时段1 开始(分钟, **小端** uint16, 0~1440) |
| +2 | 2 | 时段1 结束(小端) |
| +4 | 2 | 时段2 开始(小端) |
| +6 | 2 | 时段2 结束(小端) |
| +8 | 1 | 绕边使能(非 0 = 该日绕边开启) |
| +9 | 1 | 时段1 有效标志(非 0 且 开始<结束 且 结束≤1440 才有效) |
| +10 | 1 | 时段2 有效标志(同上) |

**校验与拒绝**(失败回 DP115 结果帧)：

| 情况 | `code` |
|---|---|
| 长度 ≠ 88 | `65 REJ_BAD_LENGTH` |
| 解析失败(字段非法) | `66 REJ_PARSE_FAIL` |
| 组 0 标志置位但两个时段都非法(起止倒置/越界) | `64 REJ_BAD_ENUM` |
| 某有效时段时长 ≤ 10 分钟(整包拒绝, 不半写入) | `65 REJ_BAD_LENGTH` |

> 成功下发后设备会**全量回读 DP101**(App 可直接用回读值刷新 UI); 计划内容会影响"继续工作"的窗口判定(见 §8.6)。

**完整示例(最常用: 周一~周五 09:00-12:00 + 14:00-18:00, 开绕边; 周末关闭)**

88 字节十六进制(下面分组仅为便于阅读, **传输时不带空格/换行**):

```
0000000000000000 000000   <- 组0 全部设置: 留零，按天执行
1C02D00248033804 010101   <- 组1 周一: 09:00-12:00 + 14:00-18:00, 绕边开, 两时段有效
1C02D00248033804 010101   <- 组2 周二: 同上
1C02D00248033804 010101   <- 组3 周三: 同上
1C02D00248033804 010101   <- 组4 周四: 同上
1C02D00248033804 010101   <- 组5 周五: 同上
0000000000000000 000000   <- 组6 周六: 关闭
0000000000000000 000000   <- 组7 周日: 关闭
```

**解码(以组1为例)**:

| 字节 | 值 | 计算 | 含义 |
|---|---|---|---|
| `1C 02` | 0x021C | 540 分 | 时段1开始 = 09:00(小端: 低字节在前) |
| `D0 02` | 0x02D0 | 720 分 | 时段1结束 = 12:00 |
| `48 03` | 0x0348 | 840 分 | 时段2开始 = 14:00 |
| `38 04` | 0x0438 | 1080 分 | 时段2结束 = 18:00 |
| `01` | 1 | — | 绕边使能开 |
| `01` | 1 | — | 时段1有效 |
| `01` | 1 | — | 时段2有效 |

> **只做一个时段**的写法: 把时段2 的 `valid` 置 0 即可(如 `1C02D00200000000 010100` = 仅 09:00-12:00); 整天关闭 ⇒ 该组 11 字节全 0(此时 `valid` 也是 0, 不会被判非法)。

### 5.2 DP103 `zone_config` 区域配置(raw 25 字节, rw)★

**布局 = 5 区 × 5 字节**:

| 偏移 | 长度 | 含义 |
|---|---|---|
| +0 | 1 | 区号(1~5; 传 0 时设备按序号兜底) |
| +1 | 1 | 该区百分比(>100 时限幅为 100; **百分比 0 = 该区关闭**) |
| +2 | 2 | 距离(小端 uint16) |
| +4 | 1 | 有效标志(非 0 = 该区使能) |

**校验与拒绝**：

| 情况 | `code` |
|---|---|
| 长度 ≠ 25 | `65 REJ_BAD_LENGTH` |
| 解析失败 | `66 REJ_PARSE_FAIL` |
| 区号越界(不在 1~5) | `64 REJ_BAD_ENUM` |
| 各区百分比之和 > 100 | `64 REJ_BAD_ENUM` |

> 全量替换写入; 成功后会全量回读 DP103。

**完整示例(区1 占 50%、距离 1200; 区2 占 30%、距离 800; 区3~5 关闭)**

25 字节十六进制(**传输时不带空格**):

```
0132B00401   02 1E 20 03 01   0300000000   0400000000   0500000000
```

**解码**:

| 区 | 字节 | 解读 |
|---|---|---|
| 1 | `01 32 B0 04 01` | 区号1 / 百分比 50=50% / 距离 0x04B0=1200(小端) / 使能=1 |
| 2 | `02 1E 20 03 01` | 区号2 / 百分比 0x1E=30% / 距离 0x0320=800 / 使能=1 |
| 3 | `03 00 00 00 00` | 区号3 / 0% / 距离0 / 使能=0(**该区关闭**) |
| 4 | `04 00 00 00 00` | 关闭 |
| 5 | `05 00 00 00 00` | 关闭 |

> 百分比之和必须 ≤ 100(本例 50+30=80 ✅); 想"删掉某个区"就把该区 5 字节全 0。

## 6. 时间类 DP(DP106 / 107 / 108 / 114)

| DP | 标识符 | 类型 | 说明 / 拒绝 |
|---|---|---|---|
| 106 | time_sync_enable | bool rw | **自动同步开关**; `false` 时 DP114 会被拒(`69 REJ_TIME_SYNC_OFF`) |
| 107 | timezone | enum rw | 时区 `0~24`(0=UTC-12 口径由平台定义); **>24 ⇒ `64`** |
| 108 | dst_enable | bool rw | 夏令时开关 |
| 114 | device_time | string rw | **10 位十进制 UTC 秒**(如 `1758765432`) |

**DP114 校验与拒绝**：

| 情况 | `code` |
|---|---|
| 长度 ≠ 10 或首位为 `0` | `65 REJ_BAD_LENGTH` |
| 含非数字字符 | `66 REJ_PARSE_FAIL` |
| 数值溢出(>429496729) | `66 REJ_PARSE_FAIL` |
| 时间过早(<2001-09 对应值) | `64 REJ_BAD_ENUM` |
| DP106 自动同步关闭 | `69 REJ_TIME_SYNC_OFF` |

> 成功 ⇒ 直接写入 RTC(带时区换算); App 对时流程见 §9.6。

**示例**：

| 下发值 | 结果 | `code` |
|---|---|---|
| `"1758765432"` | ✅ 10 位十进制 | `0` |
| `"01758765432"` | ❌ 首位为 0(且长度 11) | `65` |
| `"17587654a2"` | ❌ 含非数字 | `66` |
| `"9999999999"` | ❌ 大于 429496729(会溢出) | `66` |
| `"1000000000"` | ❌ 时间过早(<2001-09) | `64` |
| `"1758765432"`(DP106=false 时) | ❌ 自动同步关闭 | `69` |

> 10 位 = **UTC 秒**(不是毫秒); 设备按 DP107 时区换算后写入本地时间。

## 8. 拒绝语义汇总(App 失败提示参考)★

### 8.1 结果帧载荷

```json
{"code":0,"seq":18,"dp":2,"val":1}          // 成功
{"code":26,"seq":17,"dp":3,"val":1}         // 失败(26=26 故障未解决)
{"code":65,"seq":19,"dp":101,"val":88}      // 参数类失败(65=65 长度不合法; val=载荷长度)
```

| 字段 | 必填 | 含义 |
|---|---|---|
| `code` | ✅ | 结果/理由码(§8.2)。**`0` = 成功**; 非 0 = 拒绝 |
| `seq` | ✅ | 每次下发 +1(0~255 回绕) ⇒ 区分"本次结果 / 全量回读的旧结果" |
| `dp` | ✅ | 被处理/被拒的 **DP 号** |
| `val` | 可选 | 回显下发值: bool/enum/value 类 = **下发数值**; **raw/string 类 = 载荷长度**(不回内容) |

**解析要求**：① 忽略未知字段(前向兼容); ② **遇未知 `code` 不要猜动作**，只给通用提示"操作未生效(码 X)"; ③ 现有 `code` 见下表。

### 8.2 理由码全表(30 个)

> ⚠️ **进制**: 下表码值为**十进制**，与帧内 `code` 字段**完全一致**(固件用 `%u` 格式化)。固件源码/早期文档写作十六进制(如 `0x1A`)，等于本表的 `26` —— 解析成整数后直接比较, **不要做进制转换**。

**结果码(0~15)**

| code | 名称 | 含义 / App 建议 |
|---|---|---|
| `0` | RES_OK | **成功**(含"目标已达成"的幂等) ⇒ 按成功处理 |
| `1` | RES_ALREADY | **保留未用**(成功码不细分 ⇒ 幂等也回 `0`) |
| `2` | RES_NONE | **保留未用**(上电未下发过时不发帧) |
| `3` | RES_INTERNAL_FAIL | 设备内部写失败 ⇒ 提示"稍后重试" |

**状态类拒绝(16~31)**

| code | 名称 | 含义 / App 建议 |
|---|---|---|
| `16` | REJ_POWER_OFF | 设备关机中 ⇒ 提示"机器已关机" |
| `17` | REJ_SELFTEST | 开机自检中 ⇒ 提示"开机自检中，请稍候"(自检结束可重发) |
| `18` | REJ_OTA_BUSY | 升级中 ⇒ 稍后再试 |
| `19` | REJ_ESTOP | 已处于急停 ⇒ 提示"机器处于急停"；要恢复请发 `DP2=true` |
| ~~`20`~~ | ~~REJ_FAULT~~ | **已去掉**(2026-10-10; 故障相关统一用 `26`) |
| `21` | REJ_COVER_OPEN | 盖子未关 ⇒ 提示"请盖上盖子"(**无需重发**，关盖后设备自己往下走) |
| `22` | REJ_LOCKED | 面板锁/PIN 态(**当前固件不产生**，App 可保留分支) |
| `23` | REJ_ESTOP_NOT_RELEASED | 急停按钮未释放 ⇒ 提示"请松开急停按钮" |
| `24` | REJ_SIGNAL_SEARCH | **还没找到边界线**(本次开机未锁定) ⇒ 提示"机器正在找线，请稍候或放回线内" |
| `25` | REJ_SIGNAL_LOST | **边界信号丢失**(无帧) ⇒ 提示"检查边界线供电/机器位置" |
| `26` | REJ_FAULT_ACTIVE | **故障未排除**(DP111 的 `device`/`error` 层仍有位没清) ⇒ **必须读 DP111 定位后再出文案**(§8.6.1)；**故障态下唯一会出现的拒绝码** |

**场景类拒绝(32~47)**

| code | 名称 | 含义 / App 建议 |
|---|---|---|
| `32` | REJ_ON_PILE | 机器在充电桩上 ⇒ 提示"机器在桩上"(定点/回桩场景) |
| `33` | REJ_OFF_BOUNDARY | 机器在**界外/骑线** ⇒ 提示"把机器移回界内" |
| `34` | REJ_LOW_CHARGE | 因低电正处于回桩/等待 ⇒ 提示"电量低，先充电" |
| `35` | REJ_RAIN | 因雨天正处于回桩/等待 ⇒ 提示"雨天暂停中" |

**任务类拒绝(48~63)**

| code | 名称 | 含义 / App 建议 |
|---|---|---|
| `48` | REJ_NO_MODE | 还没选过工作模式 ⇒ 提示"请先选择工作模式" |
| `49` | REJ_ON_PILE_WAIT | 机器在桩等待(等充电/等雨停) ⇒ 提示"机器在桩等待中" |
| `50`/`51` | (保留) | 原"暂停类"码, **不再产生** |
| `52` | REJ_TASK_CANCELLED | 上次任务已被**取消** ⇒ 需**重新选模式**再启动(开关拉不起来) |
| `53` | REJ_BUSY | 设备正忙/状态不允许(兜底) ⇒ 稍后重试 |

**参数/协议类拒绝(64~79)**

| code | 名称 | 含义 / App 建议 |
|---|---|---|
| `64` | REJ_BAD_ENUM | 枚举值非法/越界 ⇒ 检查枚举定义与范围 |
| `65` | REJ_BAD_LENGTH | 长度不合法(如 DP101≠88B、DP114≠10 字符) ⇒ 检查打包 |
| `66` | REJ_PARSE_FAIL | 解析失败(内容不合法) ⇒ 检查格式 |
| `67` | REJ_BAD_TYPE | **DP 类型不符**(如把 bool DP 按 enum 下发) ⇒ 检查平台 DP 配置 |
| `68` | REJ_NOT_WRITABLE | **该 DP 只上报、不可下发**(如 5/13/18/111/112/113/115/116/117/118) ⇒ **改 App，不要下发** |
| `69` | REJ_TIME_SYNC_OFF | 自动同步关闭(DP106=false)时下发 DP114 ⇒ 先开 DP106 |
| `70` | REJ_UNKNOWN_DPID | **设备不认识这个 DP 号** ⇒ 检查 DP 配置/固件版本 |
| `255` | REJ_UNSPECIFIED | 未归类拒绝(**兜底**) ⇒ 给通用失败提示 |

### 8.3 回显规则(影响控件状态)

| 类别 | 拒绝时 | App 需要做的 |
|---|---|---|
| **动作类**(DP2 开关 / DP3 模式) | **回显设备真实值** ⇒ 控件会自动弹回 | 直接采纳回显值刷新控件; **不要**自己乐观置新值后不管 |
| **参数类**(101/102/103/104/105/106/107/108/109/110/114/119) | **不回显** | 失败时**主动重读**该 DP(或用回读机制)恢复 UI |

### 8.4 以前"静默成功"、现在会拒绝的格子(R1~R7)

> 这些格子过去设备会"静音 + 回显成功"，V2.6 起改为**明确拒绝 + 理由码**。App 若原先依赖"成功"判断，需适配。

| 场景 | 现在返回 |
|---|---|
| 已急停再收到 `DP2=false` | `19 REJ_ESTOP` |
| 待机/自检期收到 `DP2=false` | `48 REJ_NO_MODE` / `17 REJ_SELFTEST` |
| 等关盖收到 `DP2=false` | `21 REJ_COVER_OPEN` |
| 在桩等待收到 `DP2=false`(或 `DP3=standby`) | `49 REJ_ON_PILE_WAIT` |
| 上次任务被取消后再打开开关 | `52 REJ_TASK_CANCELLED` |
| 待机 + 未选模式时打开开关 | `48 REJ_NO_MODE` |
| 作业中收到 `DP2=false` 但已在急停 | `19 REJ_ESTOP` |
| **故障态收到 `DP2=false`**(暂停不承担清除职责) | `26 REJ_FAULT_ACTIVE` |

### 8.5 幂等(重复下发是安全的)

| 情况 | 结果 |
|---|---|
| 已在割草再发 `DP3=smart` | `0` 成功(不动计划) |
| 已待机再发 `DP3=standby` | `0` 成功 |
| 已在定点再发 `DP3=spot` | `0` 成功 |
| 作业中再发 `DP2=true` | `0` 成功 |
| 重复发同一参数(值未变) | `0` 成功 |

### 8.6 故障态"自带清理"(App 最重要的一条流程)

**用户看到的**: 设备故障时(App 侧 `DP5=6 fault`), 用户点**启动类按钮** ⇒ 弹窗"**请确认故障已解决**" ⇒ 用户点**确定** ⇒ **App 直接重发原来那条命令**(`DP3=smart/spot/回桩` 或 `DP2=true`) ⇒ 设备自行判断能否清除:

> ⚠️ 例外: **`DP2=false`(暂停)不属于"清除入口"** —— 故障态下发它会被直接拒绝(`26`, 零副作用)。若 App 想提供"只清错不启动"，用 `DP3=standby`。

| 设备内部情况 | 设备行为 | 结果帧 `code` |
|---|---|---|
| 错误已排除 + (`DP2=true` 且 有可继续的工作点) | **清除故障 + 继续原任务**(沿用原计划) | `0` |
| 错误已排除 + (`DP2=true` 但无可继续点) | 清除故障 + 回待机 ⇒ 按最后模式启动 | `0` |
| 错误已排除 + `DP3=smart/spot/回桩` | 清除故障(复位) + 按该模式**启动新任务** | `0` |
| 错误已排除 + `DP3=standby` | 清除故障 + 取消回待机主页 | `0` |
| 错误已排除 + **`DP2=false`** | **拒绝、保持故障态**（暂停不承担清除职责） | `26 REJ_FAULT_ACTIVE` |
| **错误仍在** | **什么都不做**(保持故障态), 不动状态 | `26 REJ_FAULT_ACTIVE` |

**App 侧规则**：
1. 弹窗**点"取消"就什么都不要发**(设备保持故障态, 这是正常的);
2. 点"确定"后**只发那一条原命令**, **不要**先发额外的"清除"指令(固件没有独立的清除 DP);
3. 收到 `26` ⇒ **先读 DP111 的 `device`/`error` 两层**(见 §8.6.1), 按优先级提示"**具体是哪一项没排除**"; **不要**只提示一句"机器故障";
4. 收到 `0` ⇒ 关闭弹窗; 之后看 **DP5/DP3** 即可知道设备进入"接着干"还是"待机"。

### 8.6.1 收到 `26` 后怎么报: 读 DP111 的 `device` / `error` 两层, 按优先级提示 🆕

**设备侧判据只有一句话**(固件 `panel.c: alarm_recover_check()`): 先做一次"软性错误重判 + 丢信号升级", 然后要求
**`device == 0` 且 `error == 0`**; 不满足 ⇒ 原样保持 ABNORMAL、**不做任何清理**、只回 `26`。

> ⇒ **`26` 的含义是"DP111 里还剩东西", 而不是"机器坏了"**。具体剩的是哪一项, 只有 DP111 说得清 —— App 必须读它再出文案。

| DP111 键 | 参与 `26` 判据？ | 说明 |
|---|---|---|
| `device` | ✅ **参与** | 硬件类(挂了完全不能用) |
| `error` | ✅ **参与** | 错误类(出现会导致危险) |
| `function` | ❌ 不参与 | 只有"陷坑"位; 设备在判定前会**自动清掉**它 ⇒ 单独非 0 **不会**造成 `26` |
| `circularize` | ❌ 不参与 | 通知类(雨滴/低电/碰撞/密草/刀盘电流分级/抬起通知/圈外通知…) ⇒ **不会**造成 `26`; **唯一例外**见下面"丢信号" |

**App 三步(照此实现)**:

1. 收到 `26` ⇒ **重读一次 DP111**(触发全量查询, 或等"变化即报");
   ⚠️ **不要沿用缓存的旧 DP111** —— `26` 是"判定那一刻"的结果, 而 DP111 采样周期为 1s, 旧快照可能差几秒。
2. **只解析 `device` 与 `error` 两个键**, 按下表**取优先级最高的一条**出提示(多项并存时可列前 2~3 条; `device` 优先于 `error`)。
3. 用户现场处理完 ⇒ **重发原来那条命令**; 两层都变 `0`(或 `DP5` 不再是 `6`) ⇒ 故障已解除 ✅

**优先级 / 位值 / 文案 / 何时自动清**(位值 = DP111 JSON 里的**十进制**整数, 用**按位与**判断; 括号内十六进制仅供对照):

| 优先级 | 层 | 位值 | 含义 | 建议文案 | 什么时候会清 |
|---|---|---|---|---|---|
| **P0** | `device` | `1` (0x01) | 电池异常(电压 <10V 或 >22V 持续 5s) | 电池异常，请断电重启并检查充电；仍提示请联系售后 | 电压回到 10~22V 自动清 |
| **P0** | `device` | `2` (0x02) | IMU(姿态传感器)异常 | 姿态传感器异常，请断电重启；仍提示请联系售后 | 芯片重新初始化成功才清 |
| **P0** | `device` | `4` (0x04) | 外部 FLASH 异常 | 存储异常，请断电重启；仍提示请联系售后 | 读写恢复正常才清 |
| **P0** | `device` | `8` / `16` / `32` | 左轮 / 右轮 / 刀盘电机**无应答**(通信超时) | 电机通信异常，请断电重启；仍提示请联系售后 | 电机板恢复应答即清 |
| **P0** | `device` | `64` (0x40) | 保留位(固件从不置位) | 忽略; 若出现请反馈固件问题 | — |
| **P1** | `error` | `1` (0x0001) | 位姿异常(翻倒/侧翻/前后倾) | 机器姿态异常，请把它扶正放平 | 姿态回正(实时判定)自动清 |
| **P1** | `error` | `2` (0x0002) | 机器被**抬起** | 机器被抬起，请放回地面(并合上盖子) | 抬起条件消失**自动清**; ⚠️ **远程清不掉**, 必须现场放平 |
| **P1** | `error` | `4` (0x0004) | 边界线信号异常(丢信号/传感器异常) | 请检查边界线供电，并把机器放回线内 | 信号恢复稳定 ~1s **自动清** |
| **P1** | `error` | `8` / `16` / `32` | 左轮 过流 / 过温 / 霍尔 | 左轮异常，请清理缠绕物/障碍物并等冷却 | 电机板报"正常"即清 |
| **P1** | `error` | `64` / `128` / `256` | 右轮 过流 / 过温 / 霍尔 | 右轮异常，请清理缠绕物/障碍物并等冷却 | 同上 |
| **P1** | `error` | `512` / `1024` / `2048` / `4096` | 刀盘 过流 / 过温 / 霍尔 / **堵转** | 刀盘异常，请清理刀盘下方异物并等冷却 | 同上 |
| **P2** | `error` | `16384` (0x4000) | 越界 / 在界外启动(圈外) | 机器在割草区域外，请移回界内再启动 | 左右边界传感器都回到线内**自动清** |
| **P2** | `error` | `32768` (0x8000) | 定点位置不在界内 | 请把机器移到边界线内(并离开充电桩)再定点 | 不在桩 + 左右都在线内**自动清** |
| — | `error` | `8192` (0x2000) | 保留位(固件从不置位, 死位) | 忽略; 若出现请反馈固件问题 | — |

> ⚠️ **同一数值在不同层含义不同**: `4` 在 `device` 层=FLASH 异常, 在 `error` 层=边界信号异常 ⇒ App 必须**按层解析**, 不能只看数值。

**唯一例外: 丢信号会把 `error` "补"出一个 `4`**

设备在判定前会把 `circularize` 的三个丢信号族通知 —— `16`(丢信号)、`131072`(combined_status 卡死超时)、`262144`(停止确认超时) —— **升级成 `error` 的 `4`(边界信号异常)**。因此会出现:

```
App 读到 DP111: {"device":0,"error":0,"function":0,"circularize":16}   ← 看起来"没有错误"
App 发 DP3=smart ⇒ 设备 DP115 {"code":26,...}                          ← 被判"错误仍在"(丢信号升级为 error=4)
下一秒 DP111:   {"device":0,"error":4,...}                             ← error 补上了 ✅
```

⇒ ① 出文案**以"重读后"的值为准**; ② 若重读后 `error=0` 但 `circularize` 含 `16` / `131072` / `262144` 之一, 文案**仍按"边界信号"**出(检查边界线供电、把机器放回线内); ③ 想**提前预警**, App 可在故障弹窗里做同样的预判。

**其它注意**:

- **`26` 不区分"硬件坏了"和"现场条件没满足"** ⇒ 文案必须由 DP111 决定; `device` 非 0 才引导"重启/联系售后", `error` 非 0 一律先引导现场处理;
- **不要自动重试轰炸**: 现场条件没解除时每次都是 `26`; 请让用户处理完再手动重发(与 §8.6 规则 3 一致);
- 刚清完就重发**建议间隔 ≥1~2s**(`error` 清位自带 ~1s 恢复确认 + DP111 采样 1s);
- 若 `device=0 && error=0`(四键全 0)但 `DP5` 仍是 `6`: 说明设备还停在报警页没复位, 等 1~2s **重发一次**即可 ✅;
- 精细文案也可以直接用 **DP18 位图**做粗提示(§4.3), 但 **`26` 的定位请以 DP111 为准**(DP111 是原始位域, DP18 是平台视图)。

### 8.7 信号门禁 + 圈外门(启动类命令的前置检查)

以下命令在"**要出桩干活**"但边界信号未就绪时会被拒:

| 命令 | 未就绪时的 `code` |
|---|---|
| `DP3=smart` / `DP3=spot`(待机出发) | `24`(还没找到线) 或 `25`(无信号/丢帧) |
| `DP2=true` 且最后模式为 smart/spot | 同上 |
| **不受信号门禁**: 回充 `DP3=goto_charge`、`DP2=false`、`DP3=standby`、所有参数类 DP | — |

**圈外门（④'，2026-10-10 新增）**:

| 命令 | 机器**双外确认**(界外)且不在桩时的 `code` |
|---|---|
| `DP3=smart`（待机出发） | ❌ **`33 REJ_OFF_BOUNDARY`** |
| `DP2=true` 且最后模式=smart | ❌ **`33`** |
| `DP3=spot` | ❌ **`33`**（本来就有位置门，同码） |
| **不受此门禁**: 回充、`DP2=false`、`DP3=standby`、参数类 | — |

> 意义：不加这道门时，上表前两行会**回 `code=0`**，然后**自检链让设备进 ABNORMAL + 蜂鸣 + 报警页**（用户白高兴一场还要清故障）⚠️；加了以后就是一条带理由的拒绝，**设备不进报警** ✅

> 好处: 过去这种情况会"命令回成功 ⇒ 设备随后报故障进报警态", 现在变成**一条带理由的拒绝**(设备不进入故障态、不中止计划)。

### 8.8 只读 / 未知 / 类型不符

| 情况 | `code` |
|---|---|
| 下发**只上报**的 DP(5/13/18/111/112/113/115/116/117/118) | `68 REJ_NOT_WRITABLE` |
| 下发设备**不认识**的 DP 号 | `70 REJ_UNKNOWN_DPID` |
| DP 号认识但**类型不符** | `67 REJ_BAD_TYPE` |

### 8.9 已知例外(必须容忍)

| 例外 | App 应对 |
|---|---|
| **OTA 期间**不发结果帧、不上报任何 DP | 升级流程里不要依赖结果帧; 用 DP112/DP116 判断结果 |
| 开机后**从未下发过**时, 全量查询不回读结果帧 | 把"无结果"当正常, 不要报错 |
| `seq` 0~255 **回绕** | 只做等值比较, 不做大小比较 |
| 设备 10 分钟无操作可能**断电复位**(待机+非在桩) | 复位后重发命令; 结果帧里的 `seq` 会从 0 重新计数 |

## 9. 典型对接时序(App 开发照此串联)

> 通用约定: **逐条下发 + 等结果帧**; 收到 `code=0` 视为成功。

### 9.1 连接后初始化

1. 订阅 DP2/3/5/13/18/111/117/118(状态类, 设备会变化即报);
2. 触发一次全量查询(平台侧"查询设备状态") ⇒ 设备分批回读全部 24 项(含 DP101/103/114 等);
3. 用 DP5 决定主界面状态; 用 DP112 记录固件版本。

### 9.2 启动割草(待机 → 割草)

```
App: 下发 DP3=smart
设备: DP115 {"code":0,"seq":1,"dp":3,"val":1}      // 已受理
设备: DP5=1 mowing; DP3 回显 smart                 // 状态随后变化
失败: {"code":24,...}(24 还没找到线) ⇒ 提示用户, 不要重试轰炸
```

### 9.3 停止 / 恢复(注意: 2026-10 起是"急停"语义)

```
停止: DP2=false  ⇒ code=0; 设备进急停(DP5=7 stop, 面板显示急停页)
恢复: DP2=true   ⇒ code=0; 设备"继续工作"(免 PIN)
        - 有停机前工作点 ⇒ 继续原任务(同一计划)
        - 无(如定点/待机中被打断) ⇒ 取消回待机
失败: 19(已急停) / 23(急停按钮没松开) / 21(盖子没关) / 26(故障)
```

### 9.4 取消工作(回待机)

```
DP3=standby ⇒ code=0(幂等也回 0)
在桩等待时会拒绝: 49 REJ_ON_PILE_WAIT
```

### 9.5 回桩（⚠️ 分两类，对 App 很重要）

```
DP3=goto_charge ⇒ code=0; DP5=4 goto_charge
在桩时拒绝: 32 REJ_ON_PILE
```

| 回桩类型 | 谁触发 | **计划** | 之后会怎样 |
|---|---|---|---|
| **手动回充**（App 点回充 / 面板长按 HOME） | 人 | **取消**（清计划） | 停在桩上，**不会自己再去割**（App 语义=收工）✅ |
| **低电回桩 / 雨天回桩** | **设备自动** | **保留计划** ✅ | **充满/雨停后自动出发继续**；期间发 `DP3=smart/spot` 一律被拒（`34`/`35`）⚠️ |
| 计划完成回桩 | 设备自动 | 计划**正常结束** | 回桩待机 |

> **App 如何区分**？看 **DP111 的 `circularize` 键**：`4`=低电回桩、`2`=雨天回桩（**这两类会继续**）；没有这两位而 `DP5=4` ⇒ 多为手动/完成回桩（**不会继续**）✅
> **App 点"回充"= 取消当前任务**：确认弹窗文案要写明"回充将取消当前任务，之后需重新开始" ✅

### 9.6 对时(含时区)

```
1) DP106=true           (自动同步开关)
2) DP107=<时区枚举>     (0~24)
3) DP108=<夏令时>
4) DP114="<10位UTC秒>"  ⇒ code=0 即对时成功
失败: 69(DP106 未开) / 65 / 66 / 64
```

### 9.7 割草计划设置

```
DP101 = 88 字节(布局见 §5.1) ⇒ code=0 后设备会回读 DP101
合法校验: 时段开始<结束≤1440; 时长>10min; 组0至少一个合法时段
失败码: 65/66/64
```

### 9.8 OTA 升级(注意 OTA 期间无结果帧)

```
1) 平台下发升级任务 ⇒ 设备进入 OTA 流程
2) 设备 DP116 ota_status 上报阶段(百分比停 98% 属正常)
3) 升级完成重启 ⇒ 设备连云 ⇒ 首推 DP112 fw_version
4) App 比对: 收到的版本 == 下发目标版本 ⇒ 升级成功
```

### 9.9 关机(非在桩)

```
设备 DP113 = true ⇒ 100ms 重发 ~9 次 ⇒ 断电离线 ⇒ App 秒级显示"已关机"
再开机连云后设备自动回 DP113=false
```

### 9.10 **故障恢复(App 三步)** 🆕

```
1) App 看到 DP5=6(fault) 或 开关控件被拒 ⇒ 弹窗"故障已解决?"
2) 用户点确定 ⇒ App 重发用户原本要发的命令(DP2=true 或 DP3=smart/spot/回桩)
3) 读结果: code=0(已清除并执行) / 26(故障未解决 ⇒ **读 DP111 的 `device`/`error` 定位残留项**, 见 §8.6.1)
```

# 涂鸦消息推送对接方案（方案A·现有DP版）

> 产品：GM_Automower（PID iakjfc6kosqfdkiv，PRODUCT_KEY mz7g3yzaufvoh4ls）
> 适用固件：MCU_VER 1.1.4 及以上
> 目标读者：涂鸦平台配置人员 / App 端 / 后续维护者
> 方案范围：**仅使用现有 DP 配置平台推送规则，固件零改动**。
> 二期（事件码 DP 补"回充原因/割草完成"精确推送）见 §7 预留。

---

## 1. 推送原理与链路

```
固件(MCU) --DP上报--> WiFi模组 --转发--> 涂鸦云 --匹配推送规则--> App推送通知
```

- **推送规则配置在涂鸦 IoT 平台**（产品 → 消息推送 / 告警设置），不在固件里。
  每条规则 = 选一个 DP + 触发条件 + 推送文案 + 去重时间窗。
- **平台按 DP 类型决定能否配推送**：

| DP 类型 | 推送规则 | 本机 DP |
|---|---|---|
| enum / bool / value | ✅ 值匹配 / 阈值触发 | DP5、DP3、DP2、DP13、DP117、DP118 |
| fault 位图 | ✅ **按故障位逐条配置** | DP18（13 位） |
| string | ❌ 不可配推送（App 仅能拉取展示） | DP111、DP112 |

- **本方案的核心：所有推送规则建立在 DP5 / DP13 / DP18 / DP117 / DP118 上。**
  DP111（四层告警 JSON）信息最全但为 string，只作 App 详情页数据源，不参与云端推送。

## 2. 固件上报能力盘点（推送的数据基础）

| DP | 名称 | 类型 | 采样 | 上报策略 |
|---|---|---|---|---|
| **DP5** | 工作状态 | enum 12 值 | 100ms | 变化即报 + 1s 兜底重报 |
| DP3 | 工作模式 | enum 8 值 | 100ms | 同上 |
| DP2 | 工作开关 | bool | 100ms | 同上（作业中=1） |
| DP118 | 盖子状态 | bool | 100ms | 同上（1=合盖，霍尔 200ms 防抖） |
| **DP13** | 剩余电量 | value 0~100 | 1s | ≥1% 变化即报 + 60s 兜底 |
| **DP117** | 充电状态 | enum 3 值 | 1s | 变化即报 + 60s 兜底 |
| **DP18** | 故障位图 | fault 13 位 | 1s | 变化即报 + 60s 兜底 |
| DP111 | 四层告警 JSON | string | 1s | 变化即报 + 60s 兜底（不用于推送） |
| DP112 | 固件版本 | string | — | 连云首推 + 查询兜底 |

**固件触发到 DP 上报的时延**：状态类 ≤ 100ms + 模组转发（实测预期 ≤ 2s）；
故障/电量类 ≤ 1s + 模组转发。

### 2.1 DP5 工作状态枚举（推送主载体）

| 值 | 标识 | 含义 | 固件来源 |
|---|---|---|---|
| 0 | standby | 待机 | MODE_IDLE |
| 1 | mowing | 随机割草中 | MODE_WORK_START(非副区)/MODE_WORK |
| 2 | sleep | 关机 | system_power_on_flag==0 |
| 3 | spot_mowing | 定点割草中 | MODE_SPOT |
| 4 | goto_charge | 回充行驶中 | MODE_CHARGE_START/MODE_PILE |
| 5 | paused | App 远程暂停 | robot_sta==REMOTE_PAUSE |
| 6 | fault | 故障停机 | robot_sta==ABNORMAL |
| 7 | stop | 急停 | robot_sta==EMERYGENCY_STOP |
| 8 | edge_mowing | 沿边割草中 | MODE_EDGE_START/MODE_EDGE |
| 9 | wait_charge | 在桩等下次作业 | MODE_KEPP_PILE（非等雨） |
| 10 | wait_rain | 在桩等雨停 | MODE_KEPP_PILE + WAIT_RAIN |
| 11 | secondary | 副区割草中 | MODE_WORK_START 副区流程 5 状态 |

### 2.2 DP18 故障位（"报什么错"的载体，13 位可同帧并置）

| bit | 标识 | 含义 | 固件触发源 |
|---|---|---|---|
| 0 | left_wheel | 左轮电机异常（程序离线/过流/过温/霍尔）| DEVICE_MOTOR_LEFT 或 ERROR_MOTOR_LEFT_* |
| 1 | right_wheel | 右轮电机异常（同上） | DEVICE_MOTOR_RIGHT 或 ERROR_MOTOR_RIGHT_* |
| 2 | battery | 电池异常 | DEVICE_BATTERY |
| 3 | pose | 位姿异常（前后翻/侧翻） | ERROR_POSE |
| 4 | lift | 机器被抬起 | ERROR_LIFT（**持续 10s 才置位**，见 §6.3） |
| 5 | boundary | 边界线信号异常 | ERROR_BOUNDARY |
| 6 | blade_ocp | 刀盘过流 | ERROR_MOTOR_BLADE_OVERCURRENT |
| 7 | blade_otmp | 刀盘过温 | ERROR_MOTOR_BLADE_OVERTMP |
| 8 | blade_stall | 刀盘堵转 | ERROR_MOTOR_BLADE_STALL |
| 9 | outside | 机器在圈外 | ERROR_ILLEGAL_AREA |
| 10 | spot_out_boundary | 定点割草出界 | ERROR_SPOT_NOT_WITHIN_BOUNDARY |
| 11 | trap | 机器陷坑被困 | FUNCTION_TRAP |
| 12 | blade_motor | 刀盘电机异常（程序离线/霍尔） | DEVICE_MOTOR_BLADE 或 ERROR_MOTOR_BLADE_HALL_ERROR |

> 位图同时**叠加映射**：左/右轮的过流、过温、霍尔、程序离线各自并入 bit0/bit1；
> 刀盘的霍尔/程序离线并入 bit12。即"左轮过流"与"左轮离线"都表现为 bit0，
> 精确细分在 DP111 JSON（App 详情用），推送层只到"左轮异常"粒度。

## 3. 平台推送规则配置清单（核心交付）

> 每条规则的去重时间窗**档位取决于平台触发行为（先跑 V1 判定，见 §6.1）**：
> 平台按"值变化"边沿触发（涂鸦常见）→ 去重设最小档（1 分钟，仅防抖动）；
> 平台按"每次上报匹配"触发 → 必须设 10 分钟（防固件兜底重报刷屏）。
> **注意去重是双刃剑：窗口内同一规则的再次合法触发会被吞掉**
> （如 10 分钟内 暂停→恢复→再开始，第二条"开始"推送不推）。
> 文案为建议模板，平台配置时可改。下表按用户感知优先级排序。

### 3.1 作业状态类（规则载体：DP5，"值变为 X"触发）

| # | 规则条件 | 建议推送文案 | 对应事件 |
|---|---|---|---|
| S1 | DP5 = 1 (mowing) | 割草作业已开始 | 自动计划启动 / App 启动 / 面板启动 |
| S2 | DP5 = 8 (edge_mowing) | 沿边割草作业已开始 | 沿边模式启动 |
| S3 | DP5 = 3 (spot_mowing) | 定点割草作业已开始 | 定点模式启动 |
| S4 | DP5 = 11 (secondary) | 第二区域割草已开始 | 副区作业启动 |
| S5 | DP5 = 7 (stop) | ⚠️ 机器被急停，请到现场查看 | 面板急停 / 暂停态按急停 |
| S6 | DP5 = 6 (fault) | ⚠️ 机器故障停机，详情见故障通知 | 任何 error/device 层报警触发停机 |
| S7 | DP5 = 5 (paused) | 机器已暂停 | App 远程暂停（App 自知，可不配） |
| S8 | DP5 = 4 (goto_charge) | 机器正在返回充电桩 | 低电/雨滴/计划结束/手动回充（**四因同象**，见 §7） |
| S9 | DP5 = 10 (wait_rain) | 检测到降雨，机器回桩等雨停 | 雨滴回充到达 |
| S10 | DP5 = 2 (sleep) | 机器已关机 | 面板/远程关机；**可靠性见 §6.6：推送可能丢失，勿作关键通知依赖** |

**说明**：
- S8 不区分原因：低电回充/雨滴回充/计划完成/手动回充都走 DP5→4。
  原因预告可由 B1（低电阈值）与 S9（等雨停）组合覆盖大半场景。
- S1 与 S2/S3/S4 互斥（同一时刻只有一个状态），四条规则可并存。
- **暂停恢复**（DP5 5→1）若需要"作业已恢复"推送：平台配"DP5 = 1"即可复用 S1（去重窗内恢复+再暂停不重复推）。

### 3.2 故障类（规则载体：DP18，"故障位 X 发生"触发，13 条独立规则）

| # | 故障位 | 建议推送文案 |
|---|---|---|
| F1 | bit0 left_wheel | ⚠️ 左轮电机故障，机器已停机 |
| F2 | bit1 right_wheel | ⚠️ 右轮电机故障，机器已停机 |
| F3 | bit2 battery | ⚠️ 电池异常，机器已停机 |
| F4 | bit3 pose | ⚠️ 机器倾翻，请检查现场 |
| F5 | bit4 lift | ⚠️ 机器被抬起（触发粒度见 §6.3：待机整体抬起**立即**触发；方向抬起持续10s触发） |
| F6 | bit5 boundary | ⚠️ 边界线信号异常，机器已停机 |
| F7 | bit6 blade_ocp | ⚠️ 刀盘电机过流，机器已停机 |
| F8 | bit7 blade_otmp | ⚠️ 刀盘电机过热，机器已停机 |
| F9 | bit8 blade_stall | ⚠️ 刀盘堵转（可能卡异物），机器已停机 |
| F10 | bit9 outside | ⚠️ 机器在边界圈外，已停机 |
| F11 | bit10 spot_out_boundary | ⚠️ 定点割草位置出界，已停机 |
| F12 | bit11 trap | ⚠️ 机器被困（陷坑/卡住），已停机 |

**说明**：
- 故障发生时 **S6 与对应 F 规则会先后各推一条**（DP5→6 与 DP18 置位是两帧）。
  若嫌重复，二选一：保留 S6（总）+ 只配高危 F 位（F3/F4/F5/F9/F10/F12）；或去掉 S6 只配 13 条 F。
- **平台一般只推"发生"不推"恢复"**：故障清除后 DP18 位清零，通常不产生恢复推送。
  若业务需要"故障已恢复"通知，属二期事件 DP 范畴（§7）。

## 4. 事件 → 信号 触发链细节（排查"为什么没推/推错"用）

| 事件 | 固件触发链 | 可观测 DP 变化 |
|---|---|---|
| 计划自动启动 | plan.c 定时到 → mode_status_write(MODE_WORK_START) | DP5→1、DP2→1 |
| App 启动 | DP2=true 下发 → 校验通过 → 模式切换 | 同上（App 自知） |
| 面板键启动 | POW 键 → MODE_WORK_START | 同上 |
| 急停 | 面板急停键 → robot_sta=EMERYGENCY_STOP | DP5→7 |
| 故障停机 | alarm 任务 device/error≠0 → robot_ctrl_stop + ABNORMAL | DP5→6 + DP18 对应位 |
| 电机离线 | motor_signal_timer 1.5s 无应答 → device_add | DP18 bit0/1/12 |
| 低电回充 | battery.c: SOC < 回充阈值 → CIRCULARIZE_LOW_CHARGE → mode.c 5s 确认 → MODE_CHARGE_START | DP13 低位 + DP5→4 → 到桩 DP117→1 |
| 雨滴回充 | sensor.c 雨滴 30s（补偿开关时 + 延迟）→ CIRCULARIZE_RAIN → MODE_CHARGE_START | DP5→4 → 到桩 DP5→10 |

| 充满 | is_charge_full | DP117→2 |
| 关机 | 关机流程 power_off | DP5→2（关机态上报仍放行） |

## 5. 推送时序示例（正常割草一天）

```
09:00  计划启动        → DP5=1        → 推送 S1「割草已开始」
09:40  电量降到35%     → DP13=35      → 推送 B1「电量低」(阈值35=回充30+5)
09:42  固件回充阈值(30%)触发 → DP5=4   → 推送 S8「返回充电桩」
09:45  上桩开始充电    → DP117=1      → 推送 C1「开始充电」
11:30  充满           → DP117=2      → 推送 C2「充电完成」
13:30  下一时段自动启动 → DP5=1        → 推送 S1（去重窗10min已过）
...
15:00  突发刀盘堵转    → DP18 bit8 + DP5=6 → 推送 F9「刀盘堵转」+ S6「故障停机」
```

## 6. 语义注意事项（配置与验收必读）

### 6.1 兜底重报与去重（重要，先判定再配置）
固件为保证丢帧自愈，存在**同值周期重报**：DP5 每 1s、DP18/DP13/DP117 每 60s。
涂鸦推送的触发行为需先用 **V1 实测判定**，两种情况配置策略相反：
- **边沿触发**（值变化才推，涂鸦常见）：同值重报不产生推送 → 去重设**最小档（1分钟）**，
  仅防抖动；设 10 分钟会**吞掉合法重复事件**（10min 内 暂停→恢复→再开始 的第二条）。
- **按上报匹配**（每次满足条件都推）：1s 重报会每秒推一条 → **必须设 10 分钟**去重。

### 6.2 开机自检静默窗口
门控条件（与代码逐条对应）：
- DP18/DP111：自检未完成 → **无条件不上报**；
- DP5/DP3/DP2/DP118：自检未完成 **且开机态** 才不上报（关机态 sleep 放行，App 能感知关机）；
- DP13/DP117：**不受门控**，开机即真实上报。

表现为开机后约几十秒内状态/故障类无推送，属正常；自检完成后补基线值。

### 6.3 抬起位（bit4）的触发粒度
sensor.c 两种路径：
- **四霍尔整体抬起（ALL_HALL_LIFT）+ 待机态 → 立即报错置位**（推送立即触发）；
- **方向抬起（前/后/左/右/后抬锁定）→ 持续 10s** 才置位（短时搬运不触发）。
文案（F5）已按此双粒度编写。

### 6.4 状态优先级
DP5 映射优先级：关机 > 急停 > 故障 > 回充/在桩 > 作业 > 待机。
同一时刻只报一个状态；故障与急停并发时报急停（更高级）。

### 6.5 wait_charge(9) 不建议配推送
在桩等待下次作业是常态（每天长时间停留），配推送会造成骚扰。
如需"作业全部完成"通知，属二期（§7）。

### 6.6 关机推送（S10）可靠性警示
关机流程：状态上报后约 1s，主电源断开/整机复位（power.c）。DP5=2 的上报虽在
100ms 采样内发出，但**模组是否来得及上云取决于其供电与断电时序**——推送可能丢失。
S10 仅作辅助通知，勿作为关键事件依赖（验收见 V9）。

## 7. 已知缺口与二期预留（方案B）

| 缺口 | 现状 | 二期方案 |
|---|---|---|
| **回充原因四因同象** | 低电/雨滴/计划完成/手动回充都是 DP5→4 | 新增 enum 型 DP `return_reason`（0=无/1=低电/2=雨滴/3=计划完成/4=手动），固件在各触发点变化即报，平台逐值配推送 |
| **"割草计划完成"无专属推送** | 同上（与手动回充无法区分） | 同上（值 3） |
| **OTA 升级成败推送不可达** | DP116(升级状态)/DP112(版本) 均为 **string 类型，不可配推送规则** | 将 DP116 在平台改为 value/enum 型（固件上报调用同步改），即可推"升级失败/拒绝"；"升级成功"可由 App 订阅 DP112 版本变化自行判定 |
| 边界传感器故障(0xAA)、"时间不在计划内" | **固件当前不产生这两个事件**——`CIRCULARIZE_LEFT/RIGHT_FAULT` 与 `ERROR_TIME_NOT_IN_SCHEDULE` 仅定义未调用（死枚举） | 如需推送，先在固件补事件源（boundary 协议 0xAA 帧已存在），再入位图或事件 DP |
| 计划自动启动 vs 面板启动不分 | 都是 DP5→1 | 同类事件码 DP 可扩展 |
| 瞬时通知类（短抬/丢信号搜索/密草/刀盘电流分级） | 仅 DP111 string（不可推送） | 如需推送需评估是否升层或加 DP |
| 故障恢复通知 | 平台只推发生不推恢复 | 事件码 DP 承载恢复码 |

固件侧已预留扩展位：各回充触发点集中在 `mode.c mode_work_check_quantity_rain()`
与计划完成分支，加 DP 上报约 5 处调用点，改动小。

## 8. 验收验证清单

| # | 验证项 | 方法 | 通过标准 |
|---|---|---|---|

| V4 | 故障逐位推送 | 依次模拟：拔边界线/抬起10s+/挡刀盘等 | 对应 F 规则各推一条、文案正确 |
| V5 | 多故障并发 | 同时触发两种故障 | DP18 多位同帧，两条 F 规则各推一次 |
| V6 | 低电闭环 | 放电至 35%→30% 触发回充 | B1(35)→S8 顺序正确；**若 B1 配了 ≤30 而未推，即踩了 §3.3 空转坑** |
| V7 | 雨滴闭环 | 淋雨触发（或短接雨滴传感器 30s+） | S8→S9（等雨停）推送正确 |
| V8 | 去重窗与合法重复 | 按所选模式：10min 内急停→恢复→再急停 | 边沿模式(1min窗)：两条都推；10min窗模式：第二条被去重（预期行为，向用户说明） |
| V9 | 关机推送可靠性 | 远程/面板关机各 5 次 | 统计 S10 到达率；若经常丢失，App 端改用"设备离线"补充提示 |

# 演示动线打磨：植物图片、去底部导航、演示数据

> 文档类型：Historical Change Record
> 日期：2026-08-18
> 环境：远程 SSH 工作树（本机无 Flutter/Dart SDK）
> 分支与起始版本：main / c21ac17
> 范围：植物目录与图片、`AppShell` 导航、Mock 演示数据
> 当前权威文档：`docs/TEMP_STATIC_PAGE_PREVIEW.md`

## 背景与目标

准备对外演示：动线要顺、页面要有内容、样式要完整。本次处理三件事——把新加的植物图片接进选择页、去掉底部 Tab 导航、给绑定设备后的页面补上像样的演示数据。

## 变更内容

### 植物图片与目录统一

- 项目里原本有两套植物数据：`PlantCatalog.items`（龟背竹、绿萝、迷迭香、罗勒、多肉、薄荷）和植物选择页自己写死的 `_plants`（8 种）。两者互不相同，选择页选出来的植物在目录里可能根本不存在。
- 新增的六张图片对应冷水花、绿萝、常春藤、龟背竹、天堂鸟、幸福树。按「没有图的直接删」，`PlantCatalog.items` 改成这六种，选择页删掉 `_plants` 与 `_PlantChoice`，直接使用 `PlantCatalog.items`；豆瓣绿与春羽随之移除。
- 图片重命名为 ASCII、与植物 id 对齐（`plant_pilea.png`、`plant_pothos.png`、`plant_ivy.png`、`plant_monstera.png`、`plant_bird_of_paradise.png`、`plant_china_doll.png`），与仓库里其余资源的命名保持一致，也避免 Windows 与 Git 之间的非 ASCII 路径问题。`pubspec.yaml` 按目录注册资源，无需改动。
- `AppAssets.plantImages` 用植物 id 索引图片，`AppAssets.plantImage(id)` 在找不到时回落到通用植物图标而不是抛异常。
- 植物选择页与植物详情页改为渲染真实图片：图片实际尺寸从 146x172 到 388x368 不等，统一用 `BoxFit.contain` 加内边距，卡片底色用植物主色的 8% 透明度，避免拉伸或裁切。

### 去掉底部导航

- `AppShell` 从「IndexedStack + 底部 Tab」改成单页：有设备时是设备列表，无设备时是「暂无设备」页。
- 「我的」不再是 Tab，而是左上角头像推入的普通路由（`AppRoutes.mine`），可以返回。设备列表页和首页原本就有 `onOpenProfile ?? Navigator.pushNamed(mine)` 的兜底，`AppShell` 不再传回调即可。
- `AppShell.initialIndex` 一并移除。`AppBottomNavigation` 组件保留在 design_system 中未使用，如果以后恢复 Tab 还能直接用。

### 演示数据

先逐页核对了「绑定演示设备 + 选好植物」之后每页实际渲染的内容，再按问题改：

- **历史曲线**：`getHistory` 原来日范围只返回 8 个点，而页面的坐标轴写死 6 个刻度，点和刻度对不上；五个指标还共用同一条被缩放的正弦曲线，翻到哪页都长得一样。现在统一按范围生成 24 / 7 / 30 个点，每个指标有自己的形态（水位是中途补水后缓慢下降、土壤湿度小幅波动、温度凌晨低午后高、湿度与温度反相、电量因为在充电所以单调上升后走平），并叠加固定的小抖动让曲线像实测值。
- **DLI**：日范围原来峰值只有 0.149，而柱状图的坐标轴下限是 1.0，整张卡片几乎全空。现在落在 0.5–1.3。
- **演示设备读数**：土壤湿度 97 会在首页显示「偏湿」、水位页却说「湿度适宜」，周/月曲线还会超过 100 的坐标轴上限。改为 65；同时把光照提到 620、温度 24.6、湿度 56，让各页状态一致且都落在健康区间。设备 id、PID 改成像真实涂鸦设备的值，设备信息页不再显示 `planter-demo-01` / `uuidplanterdemo01`（硬件版本保持设计稿的 `26`）。
- **动画页**：两条预置动画的路径是 `builtin://`，而页面会过滤掉它们，导致列表永远是空的。改成三条带文件路径的记录（其中一条未同步），页面有内容也能演示同步状态。
- **首页**：养护文案原本是固定的「今天状态良好」，会和上方「偏湿」「偏弱」自相矛盾，现在按土壤、光照、湿度阈值推导；「相对湿度」卡片错用了水滴图标，改为湿度图标；未选植物场景的陪伴天数写死 1 天，与详情页的 127 天冲突，改为都取绑定日期。
- **光照页**：描述说光照「高略于」补偿点（错别字），且与下方建议说「略低于」互相矛盾，两句都重写。
- **电量页**：曾补过养护建议卡，后对图确认设计里电量页在图表之后就结束、没有建议卡，已回退。
- **设备设置**：「系统文件更新」的提示原本是开发者口径的长句，改为「系统文件更新暂未开放」。（曾给「行为」「其他设置」补过右侧值，后对图确认设计里这两行只有箭头，已回退。）
- **植物详情**：六种植物里只有冷水花有手写内容，其余五种走通用兜底，导致适宜温度都是 18-28°C、难度都是三星、「别名」直接显示植物自己的名字。为绿萝、常春藤、龟背竹、天堂鸟、幸福树各写了一份，通用兜底也改成用拉丁名而不是重复中文名。
- **本地改动不再被刷新冲掉**：Mock 的 `publishDps` 是空实现、`selectPlant` 也不落库，因此下拉刷新会把刚选的植物和所有开关恢复默认。`FlowerpotState` 增加植物与设置的本地覆盖表，刷新后重新套用，退出登录时清空。

### 对照 UI 图还原

用 `docs/UI/` 下的 49 张设计图逐页比对后修正：

- **背景**：`bg01.png` 本身就带首页的光环与底座光晕，但 `AppPageBackground.standard` 和 `home` 共用它，导致 22 个子页面都顶着首页背景。现在只有 `home` 贴图，`standard` 改为设计图里的「顶部薄荷绿 → 接近白」纵向渐变，四角模糊光晕只保留给 `warm`。背景图的 `BoxFit.cover` 也改成 `fitWidth` + 顶部对齐：cover 会把 bg01 放大 8% 并整体下移约 20pt。
- **重复的光环**：首页在 bg01 的光环之上又用 `HomeOrbitDecoration` 画了一个小 12pt、低 8pt 的环，屏幕上是两个圈六个点。该组件本身也是用 `DecoratedBox` + `Border` + 三个 `Container` 拼出来的，已删除。
- **错用的素材**：首页「需水状态」用的是湿度双水滴（`metric_water_icon`），设计是蓝色水滴盛水（`water_status_icon`）；「登录后无设备」用的雷达图没有路由器图形，设计用的是 `pairing_device_search_illustration`；电量页指标行应该用浅薄荷圆底 `battery_status_icon`，标题才是青色方角 `battery_icon`；其他设置的红色提示应该是细描边 ⓘ（`info_outline_icon`）而不是实心警告；「我的」昵称旁应该是方框铅笔 `edit_icon` 而不是裸铅笔。
- **手绘图形**：删除了未被引用的 `PlantIllustration`（代码画植物）。搜索页的 `_RadarPainter` 扫描扇形一度按同一条规则删掉，但核对 `docs/UI/搜索附近设备.png` 后确认设计里就有这个扇形、且没有画进插画素材，属于动效而非图标，已还原并在代码注释里注明不要再删。剩下的 `CustomPainter` 只有三个图表、登录面板缺口和上传虚线框，属于合理用途。
- **状态页图标尺寸**：五个状态页的标题徽标 40→27、指标徽标 48→32，设计里分别是约 27 和 32。
- **养护建议**：图标从 Material 灯泡换成真实素材 `plant_care_tip_icon`，白色圆底 48→37。
- **图表**：DLI 柱状图坐标轴原来是 `max(1.0, 峰值*1.12)` 动态的，设计是固定 0.0–1.0；柱宽 20→11 且改回平顶。折线图气泡高度 29→18、标记点 5.5→3.5。
- **页面起始位置**：个人信息、账号与安全、协议、植物选择、植物详情的顶部内边距是 79–88，而同样设计位置的兄弟页面是 28–37，差了约 55pt，已统一。首页三种形态的顶部 40→20。
- **其他**：植物卡片去掉绿色底色（设计是纯白卡），植物详情改成圆形柔和底；选中植物的标记按设计改成青色圆底 + 白色对勾（用现有 `checkmark_icon` 加色块，不重画图标）；提示卡灯泡补上白色圆底；设备列表「+」按钮 40→30；搜索页插画 286→200；星级从圆角星换成尖角星；`登录YSplanter 账号` 补空格；退出登录按钮位置下移到贴近底部。

## 关键决策

- 植物目录只保留一套。选择页维护自己的列表会让「选出来的植物」和「设备上的植物」对不上，且新增图片时要改两处。
- 图片重命名为 ASCII：仓库其余 100 多个资源都是 snake_case，APK 又在 Windows 上构建，非 ASCII 资源路径没有必要冒险。后续新增图片时同样按 `plant_<id>.png` 命名，并同时补 `AppAssets.plantImages` 与 `PlantCatalog.items`。
- `plantImage` 返回非空并回落到通用图标，避免未知 id 触发空断言崩溃。
- 去掉 Tab 后不再包一层 `Scaffold`：每个页面自带 `AppPageScaffold`，多套一层会带来重复的安全区和键盘内边距。

## 未完成项与风险

- 六张图片是透明 PNG，尺寸不一。若后续要做更紧凑的网格，建议统一导出尺寸和留白。
- 对图后仍未处理、需要产品确认的差异：
  - 配网成功页设计有「添加植物」和「返回首页」两个按钮，当前只有一个「已完成」。这是 2026-08-15 演示动线记录里的有意改动，没有回改。
  - 设备列表页设计左上角是返回箭头，当前是头像入口——按本次第 4 条要求保留头像。设计里列了三台设备，演示只有配网出来的那一台。
  - 登录面板在设计里是贴着屏幕底部出血的，当前是内容高度决定、底部留白。
  - 「我的」「个人信息」「帮助中心」「协议」在设计里与账号类页面同款背景（斜向薄荷），当前用的是纵向渐变；账号与安全、登录密码、修改密码则用了带图背景。两族口径不一致，需要统一。
  - 帮助中心和登录密码建议卡的「?」在设计里是带尾巴的气泡，现有 `help_chat_icon` 是纯圆形，缺素材。
  - 五个状态页的日期切换只改日期不换数据；设计里 `光照状态` 的日期后还有一个 ▼。
- `PlantCatalog` 现在既是选择列表，也是真实设备缺少 `plantId` 时的回落来源，回落仍会显示列表第一项（冷水花）。植物绑定接通前这个行为不变。
- 报表页仍然没有入口。

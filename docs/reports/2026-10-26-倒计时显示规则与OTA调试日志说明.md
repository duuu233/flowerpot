# 割草机倒计时与 OTA 五项改动说明（2026-10-26）

> 对应提交：main / 51cd0f0（第五项取日志改为分享文件见后续提交）。状态：已实现，**未编译、未测试、未真机**，需打联调包验证。

## 一、倒计时为 0 时隐藏

倒计时减到 0，整块收起，不再停在「0分」。

## 二、下发工作时间后先转圈

点自动 / 定点、选好时长，工作时间（DP119）发送成功后，状态胶囊里立刻出现计时图标，时间处转圈；等设备上报新的计划（DP121）后换成剩余时间。
设备一直不报新计划（例如启动被拒）时，最多转 60 秒，之后按设备现有计划显示，没有计划就不显示。

## 三、隐藏只看 DP121 算出的剩余

只有「剩余为 0」或「设备报无计划」才隐藏。待机、休眠、关机、离线不再单独隐藏，有剩余就显示（取代 10-24 规则）。

## 四、OTA 进度层开着时不弹任何 OTA 提醒

设置页打开了 OTA 进度弹层时：
- 固件升级提醒（提醒升级 / 强制升级）不弹，进度层关掉后再按原规则判断；
- 割草机「不在待机，拒绝了固件升级」「固件升级失败」提示不另弹，结果由进度层显示。

## 五、OTA 调试日志写到手机文件

一次升级的全过程按时间记在同一个文件里，用来查清失败卡在哪一环：

| 标记 | 记录内容 |
| --- | --- |
| `[native]` | SDK 原始数据：升级信息、每条回调和进度查询结果、错误码与文案 |
| `[sdk]` | App 收到的进度事件原样 |
| `[app]` | App 的判断：进度、成功 / 失败判定、版本核验、切前后台 |
| `[ui]` | 界面显示了什么、弹了什么、用户点了什么 |

- **只有联调包写**（`APP_DEBUG_TOOLS=true` 或不传），正式包不写；只记设备 ID 末 6 位，不记账号密码。
- **位置**：`Android/data/com.common.yikaltd/files/ota_logs/ota-年-月-日.log`，每天一个，保留 7 天。
- **取法**：
  1. App 左下角联调日志 →「OTA日志」→ 系统分享面板选微信 / QQ / 邮件：保留的日志合并成一个 `.txt` 附件发出，没有长度限制；手机上可直接打开，发到「文件传输助手」/「我的电脑」即可在电脑端打开；
  2. 连电脑：`adb pull /sdcard/Android/data/com.common.yikaltd/files/ota_logs/`。

## 打联调包

```powershell
git pull origin main
flutter pub get
flutter build apk --release --split-per-abi --target-platform=android-arm,android-arm64 --dart-define=APP_DEBUG_TOOLS=true --no-pub
```

`flutter pub get` 不能省（新增依赖 path_provider、share_plus），完成后提交更新的 `pubspec.lock`。安装 `app-arm64-v8a-release.apk`。

## 验收要点

1. 自动启动选 2 小时：先转圈，随后显示约「2小时0分」；倒计时到 0 消失。
2. 作业中机器进入待机 / 离线：仍有剩余就继续显示。
3. 打开 OTA 进度层期间：不出现任何升级提醒或割草机升级失败提示。
4. 做一次 OTA 后点「OTA日志」分享到微信，收到 `ota-log-*.txt`，手机和电脑都能打开，能看到 `[native] [sdk] [app] [ui]` 四类记录。

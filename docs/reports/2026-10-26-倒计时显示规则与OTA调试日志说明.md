# 倒计时显示规则调整与 OTA 调试日志说明（2026-10-26）

> 状态：已实现，**未编译、未运行测试、未真机**（本机无 Flutter / Android / iOS 工具链）。

## 一、割草机倒计时

| 规则 | 现在 |
| --- | --- |
| 什么时候隐藏 | **只看设备 DP121 算出的剩余**：剩余为 0 或设备报无计划就隐藏；减到 0 时整块收起，不再停在「0分」 |
| 待机 / 休眠 / 关机 / 离线 | 不再单独隐藏（取代 10-24 规则），有剩余就显示 |
| APP 下发工作时间（DP119）后 | 立刻显示倒计时图标，时间处转圈；等设备上报新的 DP121 计划后换成剩余时间 |
| 设备一直不报新计划（例如启动被拒） | 转圈最多 60 秒，之后按设备现有计划显示（没有计划就不显示） |

## 二、OTA 提醒弹窗

设置页打开了 OTA 进度弹层（「设备升级 / 固件版本更新」后贴底的那层）时，**所有 OTA 提醒都不弹**：

- 固件升级提醒（提醒升级 / 强制升级）不弹，进度层关掉后再按原规则判断；
- 割草机 DP116 的「不在待机，拒绝了固件升级」「固件升级失败」提示不另弹，结果由进度层显示。

## 三、OTA 调试日志（写到手机文件）

**可以做到。** 一次升级从检查、发起、SDK 原始回调和 3 秒轮询、App 判定、版本核验、切前后台接回，到界面弹了什么、用户点了什么，全部按时间写进同一个文件，失败时能看出卡在哪一环：

| 标记 | 内容 | 用来判断 |
| --- | --- | --- |
| `[native]` | 原生直接转来的 SDK 原始数据：升级信息列表（状态、组件、版本、能否升级、提示语）、每条回调和轮询结果、错误码与文案、走的是哪条接口 | SDK / 设备 / 云端到底回了什么 |
| `[sdk]` | App 收到的进度事件原样 | 原生转给 App 的有没有丢、有没有变 |
| `[app]` | App 的判定：进度合并前后、是否当成终态、核验读到的版本、设备上报的版本号和 DP116、前后台切换 | App 是否判错（例如成功被判失败） |
| `[ui]` | 进度层显示的内容、提醒是否弹出、用户的选择 | 用户看到的和实际状态是否一致 |

**位置**（每天一个文件 `ota-年-月-日.log`，保留 7 天）：

- Android：`Android/data/<应用包名>/files/ota_logs/`，用 USB 连电脑或 `adb pull` 取；
- iOS：「文件」App →「我的 iPhone」→ 应用名 → `ota_logs`。
- 也可在联调日志框点「OTA日志」，复制本次运行的日志并显示文件路径，直接粘贴发给开发。

**范围**：只在调试构建里写（与联调日志同一个开关），用户正式包不写；只记设备 ID 末 6 位，不记账号和密码。

## 四、复现失败时请这样提供日志

1. 用调试包复现一次失败，不要清除应用数据；
2. 取当天的 `ota-*.log`（或点「OTA日志」复制），连同失败发生的大致时间一起发来；
3. 若跨天，把前一天的文件一并发来。

## 三、风险

### 高：未经任何验证

- 代码没有编译过，新增测试也没跑过，可能存在编译错误或测试不过。**第一步应在有 Flutter 的电脑上执行 `dart analyze lib test` 和 `flutter test`。**

### 中：倒计时显示与实际可能不一致

1. **开始失败也会显示倒计时**：倒计时在工作时间下发成功时就开始，此时还没发启动指令。之后若因盖子打开、时段失效、已关机而不再启动，或设备拒绝启动（如下雨、电量不足），倒计时仍然显示，但机器没有割草。
2. **设备没回报也不撤销**：工作时间下发后设备超时没回报（可能拒绝了这条指令），APP 会按设备当前值回退，但倒计时不会撤销。
3. **多台手机不同步**：另一台手机设置或重设了工作时间，这台手机不知道，会继续显示旧倒计时或不显示。换手机、重装 APP 后也不显示。需要固件新增「剩余作业时间」数据点才能解决。
4. **「0分」一直挂着**：到点后停在「0分」，直到下次设置，隔几天打开仍显示「0分」。
5. **跟随手机时间**：用户修改手机时间，倒计时会随之跳变。

### 中：提醒可能漏报

1. **事件码没有补发**：丢一帧就漏一次脱困提醒；抬起 / 落地可由故障明细（DP111）的下次上报纠正，脱困没有兜底。
2. **相同事件码可能被去重**：若涂鸦不重复上报相同的值（如连续两次 41），第二次脱困不会提示，需要真机确认。
3. **有故障时看不到提醒**：黄条只有一行，只要设备报着任意故障，抬起 / 脱困提醒就不会显示。
4. **到达顺序未核对**：DP120 事件码与 DP111 抬起位实际先后、间隔未真机核对。

### 低：自定口径待产品确认

- 整小时也显示「0分」（如「2小时0分」）；故障优先于实时提醒；落地提示 3 秒、脱困 2 分钟超时；进页面前已结束的事件不补提示。

## 四、建议下一步

1. 编译并运行测试，修复问题。
2. 真机核对：设置后启动被拒时的倒计时表现；抬起 1–3 秒放下；陷坑脱困成功 / 失败；连续两次脱困。
3. 产品确认：「开始失败仍显示倒计时」是否可接受，必要时改为启动成功才开始计时；以及上面的自定口径。
4. 固件 / 平台：剩余作业时间数据点、回桩雨滴状态值与显示名。

回滚：撤销 3035ac5 即可；本机残留的倒计时存储不影响其它功能。

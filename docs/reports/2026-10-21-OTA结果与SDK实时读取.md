# OTA 结果误报与 SDK 值实时读取（2026-10-21）

> 分支 main，花盆与割草机共用。仅代码与单测改动，**尚未真机验证**。

## 1. 上一版为什么还会误报「升级失败」

| 原因 | 后果 |
| --- | --- |
| 只有进度到 98% 或涂鸦报阶段 6 之后的失败才进入核验 | 96% 等下载段 SDK 先报失败/超时（iOS 没有阶段码），直接判失败，之后设备报新版本也改不回来 |
| 核验只认版本号 DP（花盆 148 / 割草机 112）单独推上来 | 设备重启后只更新 `verSw`、或没单推版本 DP，就一直「暂未确认」 |
| App 从不主动去读 SDK 里设备的当前版本 | 推送漏了就只能等 |

## 2. 现在的规则

| 情况 | 结果 |
| --- | --- |
| 已有升级进度（升级中或安装中）后 SDK 报失败/超时 | 显示「正在确认升级结果」，**不判失败** |
| 核验中，设备版本 = 目标版本 | 「升级完成」 |
| 准备阶段（0%，没有任何进度）就失败 | 仍直接「升级失败」 |
| 明确拒绝：预检失败、5005 弱信号、固件已变化、割草机 DP116=7/20 | 仍直接「升级失败」 |
| 核验 2 分钟仍没拿到版本 | 「暂未确认升级结果」，可关闭；之后读到新版本仍会变成完成 |

**设备版本从哪来**：版本号 DP 推送，以及 App **现读涂鸦 SDK 当前设备模型**（版本 DP + `verSw`）。以下时机都会现读：

- 进入安装阶段、进入核验时；
- 这台设备的任何推送（重新上线、DP、设备信息）；
- 前台每 3 秒的在线轮询；
- 重新打开升级进度时。

**防误判**：如果某个版本来源在升级开始前就已经等于目标版本（例如另一个组件），这个来源不算数。

## 3. 去掉的缓存与延迟

| 位置 | 之前 | 现在 |
| --- | --- | --- |
| 固件升级入口 | 用红点那次查到的旧结论 | 每次点击都现问涂鸦 |
| 设备页升级提醒 | 同一设备 1 分钟内不重查 | 进设备页、设备重新上线、版本变化都重查 |
| 设备型号（产品名） | 整个会话只问一次 | 每次进页面现问 |
| 设备清单刷新 | 查询期间来过一条推送就整台丢弃新清单 | 只把那条推送的 DP/在线值叠到新清单上，其余用 SDK 新值 |
| 在线状态轮询（读 SDK 缓存） | 8 秒 | 3 秒 |
| Android OTA 进度兜底查询 | 8 秒 | 3 秒 |

未改：DP 实时推送本来就即时更新；割草机进页面读 SDK 模型（上一版已做）。下面三项属于写入保护或云端时序，保留不动：

- 下发后的回显保护（亮度、割草机 5 秒）；
- 消息推送后等 2 秒再拉（云端入库需要时间）；
- 家庭 ID 本地记忆。

## 4. 真机验收

1. **OTA 误报**：用调试包升级，过程中或 96% 左右断开设备网络，或让 SDK 超时。弹层应显示「正在确认升级结果」。设备装好重启后，应自动变成「升级完成」，版本号同步更新。
2. **真失败仍报失败**：还没有任何进度就失败的，应直接报「升级失败」；5005 弱信号同样直接报失败。
3. **入口不缓存**：设备升好后再点「固件版本更新」，应提示已是最新，不再弹旧版本。
4. **清单刷新**：App 切回前台时，设备数值应与智能生活 App 一致。

## 5. 验证情况

- 新增/调整单测：OTA 核验 11 项、清单逐项合并 4 项、SDK 版本现读 3 项、错误码 1 项、提醒重查 1 项。
- 本次开发环境没有 Flutter/Android 工具链：**单测、静态分析、Android 编译都没跑**。需要在有工具链的电脑上运行 `flutter test`，并完成上面的真机验收。

## 1–3. 工作时间倒计时

**现状**：点「自动 / 定点」→ 安全确认 → 选时长（只能到当天 18:00）→ 先下发工作时间，再启动。设备**没有「剩余时间」这个数据点**，所以倒计时只能由 APP 自己按「启动时刻 + 设置时长」来算。

**显示位置（建议）**

- **首选**：首页「今日计划」卡的标题行下面，加一行「本次作业剩余 01:59:30（至 15:30）」。离控制按钮最近，不挤占电量环。
- 备选：电量环下面的状态胶囊里，写成「割草中 · 剩余 1:59:30」。胶囊较窄，时间长了容易挤。

**重新计数**

- 每次「设置时间 + 启动」成功（设备回执成功），倒计时就**从新设置的时长重新开始**，旧倒计时作废。
- 「继续」（急停后恢复）不重新设置时间，所以**不重新计数**。

倒计时分三种状态：**走**、**暂停**（保留剩余时间，恢复后接着走）、**隐藏**（本次任务结束）。

**什么时候走**

- 机器处于割草中、定点割草、沿边割草、第二区域割草，**并且**这次任务是本 APP 设置时间启动的。

**什么时候暂停**（显示「已暂停 · 剩余 01:20:15」，时间不动）

| 场景 | 设备状态 | 何时恢复走 |
| --- | --- | --- |
| 用户点「停止」 | 急停 | 用户点「继续」、设备回到作业状态 |
| 盖子被打开、急停按钮被按下 | 急停 | 处理后点「继续」、设备回到作业状态 |
| 作业中报故障（如刀盘堵转、轮子异常） | 故障停机 | 故障排除后点「继续」、设备回到作业状态 |
| 作业中低电自动回充 | 回桩中 → 在桩等待充电 | 充到设定电量、设备自动出发并回到作业状态 |
| 作业中下雨自动回充 | 回桩中 → 在桩等待雨停 | 雨停（加雨后延迟）、设备自动出发并回到作业状态 |

- 暂停期间不重新计数；恢复时**接着剩余时间**走。
- 离线不算暂停：设备可能仍在割草，倒计时照常走，但置灰并标注「设备离线，时间仅供参考」。

**什么时候隐藏**

- 用户点了「回归」或取消任务，机器回到待机。
- 倒计时走完。
- 设备关机。
- 用户重新设置时间并启动（旧倒计时作废，换成新的）。
- 换了手机、重装，或是别人从其他手机启动的任务：APP 不知道起点，不显示，**不能编时间**。

> 上表「暂停」各行成立的前提是：**固件在这些情况下也暂停计时，并且恢复后接着同一个任务**。若固件不暂停（例如回充期间照样计时），APP 应跟着不暂停，否则两边时间对不上。所以下面第 1、2 条必须先确认。

**需要固件确认（直接影响倒计时准不准）**

1. 急停（停止）、故障停机期间，设备的计时是否暂停？若暂停，APP 倒计时也暂停；若不暂停，APP 继续走。
2. 中途低电或雨滴回充（含在桩等待），计时是否暂停？充完、雨停后再出来，是接着原任务的剩余时间，还是重新开始、还是任务直接结束？
3. 最稳妥的做法：请固件新增一个「剩余作业时间」数据点，APP 直接显示它，就不存在算不准的问题。

## 4. 雨滴回充提示

**检查结果：未落实。**

- 首页回充时只显示「回桩中」，看不出是因为下雨；回到桩上后显示「在桩等待雨停」（这一条是对的）。
- 2026-10-12 那版做过一条「检测到积水，机器自动回充」，但它在**机器日志**里，而机器日志页面 **10-15 被换成了云端消息列表，从此不再显示**。所以用户实际看不到。

**设备能提供什么**：回充时，故障明细（DP111）里有「雨天」标志，V3.0 仍然保留这一位；另有事件码 45 / 145（积水发生 / 恢复）。

**文字从哪来（已确认）：涂鸦不会给「雨滴回充中」这句话。**

- 设备上报给涂鸦的只是**数据值**：
  - 工作状态（DP5）回充时报的是 `goto_charge`（值 4），不分低电、下雨、计划结束还是手动回桩；
  - 下雨原因只体现在故障明细（DP111）的「雨天」位，以及事件码 45 / 145。
  协议 V3.0 里没有「雨滴回充」这个状态值。
- 首页现在显示的「回桩中」「在桩等待雨停」等，是 **APP 把状态值翻译成文字**，不是涂鸦下发的文字。APP 目前也没有读取涂鸦平台上配置的功能点多语言名称。
- 能「涂鸦给什么就显示什么」的只有**消息通知页**：那里显示的标题和内容，就是涂鸦平台告警规则里配置的文字。平台若配了雨天告警，用户会在消息里看到平台写的那句话。

**所以「雨滴回充中」的文字，只能三选一：**

| 方案 | 文字由谁定 | 需要谁做 |
| --- | --- | --- |
| A. APP 组合判断 | APP（产品给文案） | APP：回充状态 + 雨天位 → 首页显示「雨滴回充中」 |
| B. 消息推送 | 涂鸦平台告警规则 | 平台：按 DP111 雨天位或事件码 45 配置告警文案；APP 消息页已能显示，首页不变 |
| C. 固件新增状态值 | 涂鸦平台功能点多语言 | 固件：DP5 增加「雨滴回充」枚举值；平台配多语言；APP 改为读取平台多语言名称显示 |

- 如果要求首页也是「涂鸦给什么显示什么」，只有方案 C 能做到。前提是固件加状态值、平台配文字，APP 再改成读平台文字。
- 方案 B 不用改 APP，但提示只出现在消息通知里，首页仍显示「回桩中」。
- **在定下方案前，APP 不自行改首页文字。**

## 5. 陷坑脱困提醒

**检查结果：未落实。**

- 目前只有机器最终报「陷坑」故障时，才弹「机器被困，请移至平坦区域」。脱困过程中 APP 没有任何提示。
- 「机器陷入坑洼，正在脱困」这句话同样只在机器日志里（10-15 起不显示）。
- 另外，**V3.0 起故障明细（DP111）不再上报「脱困中」这一位**，旧做法即使恢复显示也收不到。

**设备能提供什么**：事件码 **41**（陷坑脱困开始）/ **141**（脱困结束）。另有事件码 31 = 陷坑困死，以及故障位图（DP18）里的「陷坑」位。

**建议**

- 收到 41：首页黄条显示「**机器陷入坑洼，正在脱困**」。
- 收到 141：黄条收起。
- 若随后报陷坑故障：照常弹「机器被困，请移至平坦区域」。
- 注意：事件码没有补发，丢一帧就漏一次提醒。黄条最好设一个超时自动收起，防止一直挂着。

## 6. 抬起 / 落地提醒

**检查结果：未落实；APP 从未在首页做过实时抬起提醒，「已落地」提醒也从来没有。**

- 首页黄条只读故障位图（DP18）。按 V3.0，那里的「抬起」位是「**抬起超时报警**」，要抬起一段时间后才报。所以抬起 1–3 秒就放下时，首页什么都不显示。这和固件说的「没动过、是打开的」并不矛盾：实时那一位固件一直在报，是 APP 没读。
- 覆盖情况：2026-10-12 那版的机器日志会显示实时的「机器被抬起」。10-15 消息页改回云端消息列表后，这个页面不再显示，相当于被覆盖了。首页黄条一直没有这条提示。
- 「设备已抬起 / 设备已落地」这两句在代码历史里从未出现过。

**设备能提供什么**

- 故障明细（DP111）里的实时「抬起」位（0x1000）：V3.0 专门保留了它，并写明「需要正在被抬起的实时提示就读这一位」，而且是变化立即上报。
- 事件码 **44 / 144**（抬起 / 恢复）。

**建议**

- 实时「抬起」位由无变有：首页黄条显示「**设备已抬起**」。
- 由有变无：显示「**设备已落地**」，几秒后自动收起。
- 抬起 1–3 秒就放下，同样先提示「设备已抬起」，再提示「设备已落地」。
- 事件码 44 / 144 作为同一提示的补充来源：两者谁先到用谁，不重复弹。
- 抬起超时后，设备会报「抬起」故障。这时按现有规则弹故障框，与上面的提示不冲突。

# 花盆APP 改动说明（2026-10-27 ~ 10-28）

> 第一、二节为 10-27 的改动，第三、四节为 10-28 追加。

## 一、编辑纪念日

**改了什么**

1. **打开编辑时显示最新内容**：进入一条已有的自定义纪念日，先从服务器取这条的最新内容再显示（标题、日期、开关、文字或图片），不再沿用列表里可能过时的那一份。
   - 加载中显示「加载中」；加载失败显示重试，此时不能保存，避免用旧内容覆盖。
   - 这条已被删除时提示「没有找到这条纪念日，可能已被删除」。
2. **文字 / 图片只能二选一**：页面上始终只有一种内容。切到另一种为空，切回原来那种恢复原内容；没保存的输入切换后不保留。
3. **保存必须有内容**：新增、编辑都一样，**关闭状态下保存也要求有内容**（关闭同样会覆盖原内容）。
   - 选文字没填：提示「请输入纪念日文字内容」；
   - 选图片没传：提示「请先上传图片」。
4. 生日、结婚纪念日两条固定项不受影响。

**验收要点**

1. 打开一条图片纪念日：显示的是图片，文字框为空；切到文字再切回图片，图片还在。
2. 文字和图片都清空后点保存（开、关两种状态各试一次）：均提示补内容，不保存。
3. 新增纪念日：不填内容不能保存。
4. 断网后打开已有纪念日：显示加载失败和重试，恢复网络后重试可正常显示。

## 二、花盆 OTA 与割草机 OTA 对比（只核查，未改动）

- 核查结果：App 里花盆和割草机的升级流程本来就是同一套，等待时间、判断规则都一样，花盆没有额外的等待。
- 割草机特有的只有「升级前需在充电桩上」和失败提示，与速度无关。
- 结论：割草机升级更快不是 App 造成的，App 侧没有可照搬给花盆的地方，**本次未改代码**。速度差异应在设备固件、升级包大小或平台配置上。
- 建议：花盆和割草机各升级一次同版本，分别导出「OTA日志」对比，看慢在哪一段。
- 另按要求，已把割草机 OTA 当前版本单独备份一份，后续需要可随时恢复。

## 三、显示页「屏幕亮度」滑条不再来回晃（10-28）

**问题**：拖动亮度条操作快一点，松手后滑块会在几个数值之间来回跳一下才停住。

**原因**：拖动过程中 App 会边拖边把中间的亮度发给设备，设备对每一次都会回报一次当前亮度，但回报有延迟。松手后 App 太早认定「设备已经是最终亮度」并把滑块交还给设备数据，随后才到的中间值回报把滑块拉回去、再拉回来，看起来就是晃。

**改了什么**

1. **节流**：拖动时最多每 0.3 秒发一次（原 0.12 秒），只发最新位置；松手立刻发最终值。
2. **不重复发**：拖过去又拖回同一个数值，不再重复发送。
3. **等设备回报齐了再交还**：松手后滑块先停在你松手的位置；本次发了几次，就等设备回报够几次、且最新回报就是最终值，再稳定 0.5 秒才改为显示设备数据。最多等 5 秒，到时仍以设备数据为准；发送失败立即恢复设备数据。
4. 0 仍为灭屏；自动亮度开着时滑条仍锁定，规则不变。

**验收要点**

1. 关闭自动亮度，快速来回拖动亮度条后松手：滑块停在松手位置不跳，屏幕亮度跟着变到该值。
2. 连续快速点亮度条不同位置：滑块只停在最后一次点的位置，不来回晃。
3. 拖到 0：屏幕熄灭；再拖上来能恢复。
4. 弱网下拖动：滑块不乱跳；若设备最终没变成该亮度，约 5 秒后滑块回到设备真实亮度。

## 四、光照状态页：历史记录周 / 月补日期（10-28）

**改了什么**

1. 选「周」「月」时，日期条由原来的「近 N 天日均」改为日期区间，如「10月1日 - 10月27日」。
2. 柱状图下方的标签由「7天前」「昨天」改为具体日期，如「10/20」「10/27」，标的位置不变（周每 7 天一个、月每 30 天一个，最后一根一定标）。
3. 日期按「最后一根柱子 = 昨天，往左每根早一天」推算，和原来「N天前」的算法相同。设备断过电会缺天，这时日期同样是按柱子数往前推，不代表那天一定有记录（原来的「N天前」也有同样的情况）。
4. 只改了光照状态页；水位、土壤湿度页的周 / 月仍是原样，如需同样显示日期请告知。

**验收要点**

1. 光照状态页切到「周」：日期条显示起止日期，最后一个日期是昨天；柱子下方显示日期。
2. 切到「月」：同上，日期间隔约 30 天。
3. 切回「日」：仍按原来的单日日期和整点刻度显示。

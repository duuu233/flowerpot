**结论：两者共用同一套 OTA**（查版本、提醒弹窗、发起升级、进度弹层都是同一份代码），只有入口和几处细节不同，见 [§5](#5-花盆与割草机的差异)。

## 1. 总体

- 全部走**涂鸦 App SDK**，App 不和设备直接说话；OTA **不是功能点**。
- 查新版本是**主动拉取**，升级过程的进度和成败是 **SDK 回调推送**。

| 步骤 | Android | iOS |
| --- | --- | --- |
| 查版本 | `newOTAInstance(devId).getOtaInfo()` | `getFirmwareUpgradeInfo` |
| 发起升级 | `setOtaListener` + `startOta()` | `upgradeFirmware(type)` |
| 进度 / 成败 | `onProgress` / `onStatusChanged` / `onSuccess` / `onFailure` | delegate `firmwareUpgradeProgress` / `…Success` / `…Failure` |

代码分层：原生桥（`MainActivity.kt`、`AppDelegate.swift`）→ `tuya_repository.dart`（`checkFirmware`、`otaUpdates` 事件流）→ `state.dart`（待装版本、进度、超时）→ 界面（`firmware_reminder.dart`、`ota_progress_dialog.dart`）。

## 2. 查新版本

- SDK 按组件返回记录，取 `upgradeStatus == 1`（有待装版本）那一条，拿三样：新版本 `version`、当前版本 `currentVersion`（同一条里取）、平台配的升级方式 `upgradeType`（0 提醒 / 2 强制 / 3 检测）。
- 新版本为空或等于当前版本 = 没有新版本；否则记下并亮**小红点**。
- **没有定时器**。在设备页上时，每次路由变化或状态刷新都检查一遍，同一台设备 **1 分钟内只问一次云端**（`FirmwareReminderHost.recheckInterval`）。另外用户点升级入口时，如果之前没查到新版本，就当场再问一次。

## 3. 升级提醒弹窗

| 升级方式 | 行为 |
| --- | --- |
| 提醒升级 | 弹「检测到 Vx 新版本，确认是否升级」，可取消；这次进设备页不再弹，离开设备页再进来会重新提醒 |
| 强制升级 | 弹「……请升级后使用」，只有「立刻更新」，关不掉；每次回到设备页都弹 |
| 检测升级 | 不弹，只亮小红点 |

以下情况不弹：正在升级（且没卡住）、上面盖着别的弹框、当前就在升级入口页。
点「立刻更新」→ 跳到升级入口 → 再弹一次「当前版本 → 新版本」的确认框，确认后才升级。

## 4. 发起升级与进度

1. 原生层**只回答「已发起」**，之后的进度和成败都走事件通道。OTA 实例一直留着引用，升级结束才释放，否则监听会被回收，进度条会停住不动。
2. 状态层合并事件：已经有了结论（成功或失败），迟到的「进行中」事件一律丢弃；百分比和阶段码分开到达时各自沿用上一次的值。成功后熄灭红点，版本号改成目标版本。
3. 进度弹层（满宽、贴底，升级结束前关不掉）的文案：
   - 0% → 固件准备中（涂鸦报 5 时显示「等待设备唤醒」）
   - 1–97% → 固件升级中 N%
   - ≥98% 或涂鸦报 6（固件已下载到设备）→ 固件安装中，进度条改成来回走的动画；进度自己走到 98% 时，先停留 0.9 秒再切换
4. **卡住兜底**：10 分钟没有任何事件就判定升级已中断，允许重新检查。
5. 阶段码只有 Android 会转发，iOS 只有百分比和成败。

## 5. 花盆与割草机的差异

| 项 | 花盆 | 割草机 |
| --- | --- | --- |
| 升级入口 | 「其他设置」→ 固件版本更新（`device_other_settings_page.dart`） | 「设置」栏 → 设备升级（`mower_firmware.dart`） |
| 「立刻更新」跳转 | 打开「其他设置」页 | 退回割草机首页、切到「设置」栏 |
| 静默查版本 | 进设置页、进「其他设置」页各查一次，外加提醒弹窗的检查 | 只靠提醒弹窗的检查（割草机各页都算设备页） |
| 当前版本号来源 | DP 148 `firmware_version`，取不到再用 SDK 的 `verSw` | 没有版本号 DP，直接用 SDK 的 `verSw` |
| 离线时点升级 | 不拦，交给 SDK 报错 | 先拦下，提示「割草机已离线」 |
| 升级中再点入口 | 提示「固件正在升级中」 | 重新打开进度弹层 |
| 卡住后再点入口 | 弹「升级似乎已中断」，确认后重查 | 直接清掉旧进度，重新检查 |
| 设备侧补充上报 | 无 | DP116 `ota_status`：`"7"` 不在待机、拒绝升级，`"20"` 升级失败，收到就弹提示 |

## 6. 已知边界

- 发现新版本要等两段：云端 OTA 记录更新，加上 App 自己 1 分钟的节流。设备刚重新上线时，会晚 1～2 分钟才看到新版本。
- 设备重新上线、或者花盆 DP 148 变化，都**不会**触发重查新版本。
- 进度百分比由涂鸦 SDK 提供（模组或云端计算），MCU 本身不上报进度。

# 割草机控制反馈与机器日志

> 状态：Active；最后核验：2026-10-15（恢复涂鸦历史消息主列表，保留中文日期与无调试UI）。当前 APP 的契约、范围与逐项联调入口。

## 消息通知当前入口

按2026-10-15用户明确要求恢复9月28日版本的涂鸦历史消息逻辑：MowerMessagesPage复用DeviceMessagesView，当前账号SDK会话下以当前deviceId、MSG_REPORT调用loadAllDeviceMessages，每页50条、最多500条。日志=通知、提醒=轻微、告警=严重；明文等级、数字等级、warn56与alarmType的旧解析顺序保持，未知等级归告警。数字1/2/3仍是旧版推测编码，待真实平台三档逐条确认。

三栏默认全部日期，各自按消息时间筛选某天并可复位全部。收到推送后2秒重新拉取，保留下拉刷新与真实失败文案。当前页不读取本机DP日志来代替云端历史；即使本机缓存为空，也应向涂鸦查询。卸载清本机不会由APP删除云端消息，但能否返回某日记录仍以涂鸦实际响应、账号归属与云端保留范围为准，不能承诺无限期保留。

页面仍为设置下的独立二级页，无一级底部导航，返回原设置栏；显式传入deviceId。不恢复“云端推送调试”“当前等级”、来源说明或调试查询。分类使用品牌分段控件，日期文字/箭头灰色；中文日期弹窗包括日历、输入提示与取消/确定均中文，英文随APP语言。卡片展示旧版msgTitle/msgTypeContent、msgContent和time/dateTime，不把APP接收时间冒充云端事件时间。

9月28日0f183c9为云端列表；10月12日f36be8c把主列表切为本机DP日志，并把云端诊断折叠；10月15日a14ccaf再去掉诊断与当前等级。导致只能看本机数据的数据源切换早于两个区域的删除。本次恢复云端列表，不修改涂鸦原生桥或平台推送规则；iOS原有云端消息桥接缺口仍待验。

## 控制页

DP18 仍为 32 位无符号位图，只解释已定义的 bit0–12。支持整数、十进制字符串、0x 十六进制及 0b 二进制；负数、小数、溢出和无法解析的值不覆盖最后有效值。黄条沿用控制稿的黄色圆角提示行、警告图标和位置；同时置位取最低位文案，0／未上报／只有保留位时不显示。设备告警框可列全部有效位；DP111 机器日志不代替此黄条。

DP115 仅用当前设备、当前绑定会话最后实际发送的 DP2／DP3 新回执触发控制异常框。seq 等值去重，允许 255→0 回绕；dp 和可选 val 必须匹配，快照旧回执、错配、畸形帧及退出后的回执不弹。code<16 不弹；已定义的 16–70 显示协议建议，255 固定“操作未生效”；未定义/已删除码保留“操作未生效（码 X）”。设置类拒绝可入机器日志，本轮不增加其控制弹窗。

顺序为安全提醒 → 割草时间设置 → 下发 → 设备异常。回归、暂停无安全和时间窗口。异常标题“设备异常”，单按钮“我已处理”仅关闭；不清故障、不自动重发。动态时长以手机本地当天18:00为截止，按剩余完整小时向下取整；选择范围1–上限，0和负数提示并禁止设置/启动。确认与 DP119 完成后再校验截止时间，防止弹窗停留导致越界。

## code26 残留故障

必须依据新鲜 DP111，不能把 SDK 缓存的 rawDps 当主动查询结果。本版采用协议允许的“等待下一条变化即报”：同一帧115+111可直接定位；否则最多等待3秒的有效111实际上报。无变化的整包快照、畸形111均不完成等待。退出/会话切换取消等待；超时提示“故障尚未排除，暂未收到最新故障详情，请检查设备后重试。”，不编造缓存故障。

111要求完整JSON四层 device/error/function/circularize，各自为0–0xffffffff整数。code26只根据 device/error 定位，function 不解释为残留硬故障；通知层仅用于下述边界信号例外。

| 顺序 | 层/位值 | 处理建议 |
| --- | --- | --- |
| 硬件 | device 1 | 电池异常，断电重启并检查充电；仍提示联系售后 |
| 硬件 | device 2 / 4 | 姿态传感器／存储异常，断电重启；仍提示联系售后 |
| 硬件 | device 8 / 16 / 32 | 左轮／右轮／刀盘电机通信异常，断电重启；仍提示联系售后 |
| 安全 | error 1 / 2 | 机器姿态异常扶正放平／被抬起放回地面并合上盖子 |
| 安全 | error 4 | 检查边界线供电，把机器放回线内 |
| 安全 | error 8/16/32，64/128/256 | 左轮／右轮异常，清理缠绕物、障碍物并等冷却 |
| 安全 | error 512/1024/2048/4096 | 刀盘异常，清理刀盘下方异物并等冷却 |
| 位置 | error 16384 / 32768 | 移回界内／移到线内且离开充电桩再定点 |

最多列三类建议，超出提示继续逐项检查。按本轮输入V2.6补充§8.6.1，具体建议后附加“请在现场处理后等待1～2秒，再手动重试原操作。”；按钮仍只关闭，不自动重试。device64、error8192为保留位，不列具体故障，但附加“设备上报了保留故障位，请反馈固件问题。”；其他未知硬故障给未识别残留故障提示。若新鲜error=0而circularize含16／131072／262144，仍按边界信号提示。有效新鲜四层都无残留项时提示等1～2秒重新操作；不自动发送。

## 本机DP机器日志引擎（独立采集）

本机引擎仍保留采集与存储，但不再作为当前消息通知主列表。它的数据源为 APP 收到的实时 DP 流，与涂鸦系统通知、设备本地20条历史日志分开。采集6条必需 DP：5、111、117、118、113、13；可选115已接入。DP18不进入机器日志引擎。全量查询/重连快照只对齐基线，不产生事件。先前分析稿中与精简落地版冲突的“双源DP18”“9个通知位”等口径不采用。

- DP111事件27类：device6、error14、function1、circularize6。已定义事件中英文齐全；device64、error512/8192等死位及通知层跳过位不生成条目。
- 通知掩码0x00006，轻微0x01038，跳过0xFEFC1；device/error/function任意非0时当前等级为严重。严重＞轻微＞通知；保留位可影响原始等级，但不给保留位编造事件。
- 同值兜底重报不新增。2秒内DP5故障和DP111具体原因合并一条；抬起同时上报或由轻微升严重保留一条。轻微同类60秒抖动合并；新事故仍可再记录。
- 故障位1→0与原条目配对恢复，转通知、已读且不计红点；合并事故全部原因清除才整条恢复。当前等级降档保持严重30秒／轻微与通知60秒，条目即时更新。
- 作业/回充/急停走DP5；正常在桩等待不刷屏；关机只按DP113边沿，重复true不重复，DP5休眠不充当关机。
- 充电117记录开始、充满、离桩；盖子118记录开合；电量13首次≤35及重新跨入低电区记录，持续低电不重复。DP115仅新seq拒绝入轻微日志，code26等新111更新具体故障。
- 按登录账号+设备隔离本机存储，最多200条，优先淘汰历史条目、保留未恢复故障以供清位配对。无登录账号仅保留内存；读取/写入失败不中断控制与实时采集。

MowerMachineLogsView作为独立组件保留，原本机已读、恢复与前台提醒逻辑不再挂在生产消息入口上；其自动回归不等于当前云端列表已验收。当前消息页以文首契约为准。

## 初版边界与后续验收

以下为本机引擎及独立视图的边界：SDK DeviceUpdate没有设备/云端事件时间戳，本机日志明确标APP接收时间，与当前消息列表使用的云端消息时间分开。本机离线/后台未收到的事件不补齐；回充原因仅在实际收到相应原因位时描述，作业耗时不伪造；未接设备20条本地日志同步。日志页之外的统一DP111前台提醒与系统后台通知配置留待联调，本轮未更改平台规则或原生推送实现。

## 2. 空气温度、空气湿度接上历史记录（DP 164 / 165）

以前这两页没有历史功能点，曲线只能靠「打开 App 之后收到几条推送就画几个点」。`09_16` 那版
功能点表新加了两条日历史，现在接上了：

- **空气温度日历史 → DP 164 `temp_daily_hist`**
- **空气湿度日历史 → DP 165 `humi_daily_hist`**

现在这两页的曲线 = 设备上报的日包 + 之后每次推送的实时值（和需水、光照页完全一样的走法）。
进页面在联调日志里会多一行 `读取 ← [空气温度] 历史 temperature：日 DP164 hex N字节/M点`，
真机上照着这行核数据对不对得上。

⚠️ **只有「日」，没有「周」和「月」**——功能点表里只导出了日历史两行。

⚠️ 功能点表没写这两条的「点宽」，App 按它们实时 DP 的量程当 2 字节解（112 是 0–2200、
114 是 0–1000，一个字节装不下），再 ÷10 还原。另外 164 和 165 在导出里的帧头写得不一样
（164 三字节、165 四字节），App 做了按帧长自动判断，两种都能解。**这两点要真机确认一次。**

## 5. 上传图片前在前端裁剪压缩

**定制动画**和**纪念日图片**两处上传，选完图之后先压再传：

- **总像素 ≤ 480,000**（= 800 × 600），等比缩放，**不裁掉画面内容**；
- **单文件 ≤ 1 MB**；
- 输出仍然是 JPEG，扩展名和格式不变。

按产品说的「总像素 ≤ 480,000 就行」来算，而不是套 800×600 的框——套框会把竖图压掉一半
（3:4 的竖图套框只剩 450×600 = 27 万像素，按总像素能留到 600×800 = 48 万）。

压缩过程罩在进度圈里（有几百毫秒）。**万一压缩出问题，会原样传原图，不会让你传不上去。**

新增文件：`lib/src/shared/media/upload_image.dart`。
新增依赖：`image: ^4.10.1`（纯 Dart，只用它的 JPEG 编码器）。
